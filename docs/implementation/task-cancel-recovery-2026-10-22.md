# 手机 Agent 停止请求恢复（2026-10-22）

> **已简化（2026-10-23）**：本文的撤回／栅栏协议已移除。停止任务、重命名、删除、关闭终端改为可安全重发：确认时只读回执或实际状态（运行是否结束、名称是否已变、会话是否还在、终端是否已退出），未确认就重发同一操作；「不再等待」只清除手机上的记录。保持唤醒改为直接设置并回读，不再跟踪。`command_retirements` 表、`session_command_receipt`/`retire_session_command`、`power_preferences_operation`、`terminal_stop_operation` 均已删除，数据库格式回到 1。下文保留作历史记录。


## 行为和边界

手机“停止”保存原 taskId、turnId、runId、Core envelope、版本及命令身份后才执行。停止请求被受理只表示后台接受了取消；Agent 是否已经停止仍以任务事件和状态为准。不会把一次丢失的停止回覆显示成任务已结束。

取消记录存于手机安全存储独立的 `dogcodes.cancel.v1.<hostId>`，按任务/运行保存，最多 64 个待核实运行。它不占 Git、发送、审批等普通操作的待确认槽，不因其它操作结果未知而阻止用户停止 Agent，不同运行也互不覆盖。手机重启后，当前会话和“待处理”页均能核实、重试或结束该停止请求的跟踪。多个恢复卡片在小屏中使用受限高度的滚动区域。

电脑移除时清理取消记录，并阻止移除前启动、之后才完成的本机准备阶段继续写入或执行。此动作不会撤销已经发到电脑的停止请求。

## 受理回执与原子取消栅栏

复用 `session_command_receipt([envelope])` 和 `retire_session_command([envelope])`；能力位为 `cancelCommandRecovery`。Core 的命令指纹允许版本化 CancelTurn，与重命名/删除共用 SQLite `command_retirements`，无新增数据库迁移。

- 核实只读：未找到不等于尚未执行；保留原请求，不生成新停止指令。
- 回执验证 commandId/idempotencyKey；受理回执额外验证原 acknowledgement 的 commandId 和 accepted。
- 用户结束跟踪时先持久保存 `retiring` 阶段，再请求原子取消。回复丢失后重试只继续取消，不重新停止。
- 取消与 Core append 的共同事务栅栏保留原受理结果或拒绝迟到请求；已受理不可撤销。栅栏不依赖任务历史，重启、会话清理和投影重建均保留。
- WSS 与 WebRTC 物理连接使用认证手机 actor，换路不改变同一请求的身份或栅栏。

## 活跃流式版本冲突

流式输出可能使 expectedStreamVersion 过期。明确 Conflict 后先持久保存 `rebasing`，对旧 envelope 建立取消栅栏，确认旧请求未受理，才读取最新任务版本。只有 task/turn/run 仍完全相同且未进入 interrupting 时，才保存新身份/版本并再次发送；不会把原停止意图套用到后来启动的新运行。每次自动处理有有限重试次数。

任何中断都保留阶段。普通核实不生成新指令；重连后需用户明确重试才继续原运行的版本处理。用户在读取最新状态期间结束跟踪，晚到结果不能重新写入新停止请求。
