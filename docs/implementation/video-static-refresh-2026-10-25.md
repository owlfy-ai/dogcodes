# 静态补编码、实际输出与关键帧恢复

日期：2026-10-25。继续 [RustDesk 对照](rustdesk-video-reference-2026-10-25.md) 的静态刷新项，保留原远控与 PC 操作恢复目标。

## 原问题

旧 `Shared::tick` 在运动停止后只补一次成功提交：低码率下不一定足够改善最后的文字画面；提交持续被跳过时，又会每个 ticker 周期无上限重试。macOS 的成功提交只表示异步编码器接收了输入，不能证明输出了画面。实际返回普通 P 帧也不能证明已经满足关键帧请求。

此外，ticker 曾先取出缓存帧、之后才等待 encoder 锁；期间新的 capture 可能先完成编码，旧缓存随后反而覆盖新画面。

## 参考与实现

对照本机 RustDesk `src/server/video_service/static_refresh.rs` 的静止检测、有界重复、失败/无输出分开核算，以及消费反馈思路。本项目独立实现 `video/refresh.rs`，没有复制其按 codec/vendor 的重复次数表，也没有改传输协议。

- 新画面停止变化 400ms 后开始普通补编码；不为提高静态质量强制 IDR。补编码间隔至少 100ms，同时遵守协商 FPS。
- 每次静止最多 24 次尝试、12 个实际输出或从首次补编码起 3 秒，任一到达即停止。连续三个不超过 64 字节的小输出可提前停止，这只是减少无效转换的启发式，并非画质达标证明。静止前的小输出不消耗本次预算。
- `Output` 只在最终授权检查通过后的真实编码回调累加。异步提交成功、同步跳帧都不能伪造输出进度。它由独立 Arc 持有，不回指 Shared/encoder。
- 从尚未获得输出的首次提交起保留 2 秒期限，连续新画面和重试不延长；真实输出清除期限。持续无输出则结束本视频并保留错误，桌面现有 `stream.error` 链路负责停止/回退。
- 关键帧有独立的真实 IDR 计数与 2 秒期限。只有实际关键帧能核销请求；普通帧不能核销或延长期限。自动补编码预算用尽后仍可按需请求关键帧。终态编码错误立即退休输出，保留首次原因。
- capture 与 ticker 对缓存帧的选择、编码和更新使用同一 encoder 锁，防止旧静态帧在新画面之后被提交。原授权、停止、OS 状态的最终拦截继续有效。

3 秒/24 次/12 输出是当前有界产品预算，不代表全部硬件最佳值；不同原生后端仍需实机校准。没有新输入且没有待处理提交时，静止本身不会触发无输出故障。

## 实际编解码测量

显式 opt-in 入口，不读取屏幕：

```sh
cargo test -p dogcodes-remote-desktop --lib --locked measure_static_text_refinement -- --ignored --nocapture
```

源为 1280×720、先运动 30 帧再静止的合成灰阶文字/纹理。源和解码结果都比较 Y 平面，计入行跨度；记录 PSNR、输出大小与编码耗时。六组分别对比 400k/1Mbit 的普通重复、额外 IDR、当前生产调度策略。时间戳与限速使用真实时钟，数值是本机样本，不是跨设备承诺。

macOS 上运行同一 source-built OpenH264 软件后端的记录：

| 码率 | 当前有界普通补编码 | 强制额外 IDR 的对照 |
| --- | --- | --- |
| 400 kbit/s | 首个静态输出约 38.25dB，经几次输出达到 39.06dB；随后三个 13B 小输出停止，与 24 次普通重复的最终质量相同 | IDR 约 35.26dB、28.8KB，之后未恢复到普通补编码质量 |
| 1 Mbit/s | 原本约 40.25dB；三次 13B 小输出后停止，没有继续做 24 次无效转换 | IDR 约 39.90dB、48.3KB，未改善该样本 |

没有据此提高目标码率、强制 IDR 或照搬 RustDesk 的重复次数。PSNR 只是合成亮度误差证据，不能代替彩色小字、文字边缘或硬件编码的主观质量验收。

## 回归与反例

- macOS remote-desktop 50 项、1 个测量 opt-in 默认忽略；严格 Clippy、Windows GNU all-targets 严格 Clippy 通过。Windows 仅静态检查。
- Ubuntu 22.04/PipeWire 0.3.48 与较新 Linux/PipeWire 0.3.65 各 70 项、7 个 opt-in 默认忽略，严格检查通过。
- 新状态回归覆盖无输出不被新运动/接受提交续期、重试尊重低 FPS、真实输出与静态预算、静止前的小输出隔离、P 帧不能核销 IDR、实际 IDR 停止强制重试；Shared 回归区分接受/输出并保留首个终态错误。
- macOS 原生 VideoToolbox 与 Linux OpenH264 均用纯合成来源验证：实际输出、多次静态刷新后停止、继续静止不误退休、后续 IDR 仍可输出。没有调用屏幕采集 API。
- 私有 login1 的 desktop 跨 Auto/CB3.1 真实解码接续和 15 项桌面视频回归通过。旧/新 Linux 私有 NV12 授权/损坏/收尾仍通过，旧 Linux 另验证裁剪旋转来源。
- 两个独立只读覆盖对照：让新运动重置无输出期限，明确复现无输出回归失败；让普通 P 输出核销关键帧，明确复现 IDR 回归失败。自有 target 随后清理该 crate 并以当前源码重编译。

最终记录：`/tmp/dogcodes-static-refresh-{mac,mac-clippy,windows,linux,ubuntu22,final-linux}.log`、`/tmp/dogcodes-static-quality-final.log`；反例为 `/tmp/dogcodes-refresh-{renew,key}-before.log`。此前试验和当前测量不能作为 Windows/MF、真实 GPU、手机或弱网的验收。
