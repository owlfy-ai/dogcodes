# Diff、Git 与文件恢复的共享服务

日期：2026-10-16。对应 DT-08/09/10。当前工作块迁移服务所有权；外部副作用的完整持久意图/回执仍是后续发布前必做项，不因迁移完成而标记 DT-09 完成。

## 实现边界

- `ServiceControl` 持有唯一 ReviewHost（快照、独立阅读者租约、SnapshotOwner、操作 gate、ReviewStore 目录）。DesktopState 不再创建或持有 ReviewHost。生产 daemon 与 embedded 验收配置使用同一服务实现，复用原有 `review` 数据目录。
- `review::service` 接受类型化 ReviewCall，经现有本机认证 RPC 分派；服务直接调用 Core。Tauri 入口保持原命令和前端参数形状，负责窗口可访问任务的检查与转发；Core 不增加 Tauri 依赖。
- 查询、冻结正文、续租/释放、历史/分支、工作树导航、暂存/取消暂存、丢弃/忽略/批量文件操作、提交/拉取/推送/同步、提交说明生成、逐轮撤销/状态读取均在后台执行。已受理 RPC 不因回复连接关闭而取消，继续持有后台门禁直到操作返回。
- 项目审查材料由后台根据快照及任务归属生成，不能由桌面传入任意材料替代。重试或同 runId 重放仍复用 Core 的持久请求和材料，保持原语义。
- 项目目录修改、永久删除与快照读取/写入使用同一后台 gate 协调，删除后的缓存/租约清理也迁至后台；Core 删除失败但已实际删除时仍按当前任务状态清理。客户端消失不再跳过 GUI 后置清理。
- 打开文件管理器/系统应用仍留在桌面；路径解析和当前工作区范围在后台检查。Git 子目录项目必须满足 scopes，不能仅因文件处于同一仓库就越过项目子目录范围。
- 冻结文件读取重新核对当前根目录和 scopes。服务新实例不恢复旧内存快照，客户端需重新查询；持久的逐轮撤销记录继续可查询和幂等重放。内存租约不当作持久操作回执。

## 验证记录

原生首轮 `cargo test -p desktop --lib review -- --nocapture`：30 通过、1 失败，exit 101（`/tmp/dogcodes-review-service-native.log`）。失败是断连后的暂存用例在用 Git 轮询磁盘状态时超过 5 秒，并非编译失败。改为通过共享门禁等待已受理操作完成，再检查实际索引；没有放宽超时、跳过磁盘结果或改成模拟 Git。首次超时的具体原因尚未证实，候选阶段仍需核对并发/延迟表现。

同时补上项目目录修改与 ReviewHost gate 的协调，以及项目审查持久材料重放和实际类型化响应解码覆盖。复验第一次在新增测试夹具处发现 JSON 宏写法和未引入 futures 宏的编译问题，exit 101（`/tmp/dogcodes-review-service-rpc-recheck.log`）；修正为嵌套 JSON 宏和标准库 Future poll，没有新增依赖。

最终 `cargo test -p desktop --lib daemon::tests::review_tests -- --nocapture`：6 项全部通过，exit 0（`/tmp/dogcodes-review-service-rpc-final.log`）。覆盖：

1. 双客户端共享冻结读取、独立租约、17 次查询造成的缓存压力、任务归属、类型化快照/正文解码，以及新服务实例拒绝旧快照并可重取。
2. 真实请求已获得后台写入许可后关闭回复连接，暂存仍完成；旧写预览被拒绝，提交没有重复产生 commit，历史/分支仍可查询。
3. 文件预览、忽略、单文件/批量丢弃，当前目录收窄后旧范围读取被拒绝，永久删除清理后台快照。
4. 服务读取并验证真实 Artifact 内容/哈希，逐轮撤销结果跨服务实例可读；同一撤销重放不会覆盖后续文件修改。
5. 后台构建项目审查材料；无旧内存快照的服务实例可重放原请求；变更原请求及客户端伪造材料入口被拒绝。
6. 项目目录修改在 ReviewHost 被操作占用时不能先更改 Core 中的范围，门禁释放后才生效。

累计 33 个不同原生用例最终通过；不是一轮全套 33 项运行。已通过部分未无理由重跑。diff 空白检查通过；前端命令及参数保持不变，没有再次执行前端全套、构建安装包或调用真实模型。所有本次测试句柄已收取终态。
