# 手机会话命令恢复与取消

> **已简化（2026-10-23）**：本文的撤回／栅栏协议已移除。停止任务、重命名、删除、关闭终端改为可安全重发：确认时只读回执或实际状态（运行是否结束、名称是否已变、会话是否还在、终端是否已退出），未确认就重发同一操作；「不再等待」只清除手机上的记录。保持唤醒改为直接设置并回读，不再跟踪。`command_retirements` 表、`session_command_receipt`/`retire_session_command`、`power_preferences_operation`、`terminal_stop_operation` 均已删除，数据库格式回到 1。下文保留作历史记录。


适用：手机发起的会话重命名、永久删除。尚未执行的请求可取消，已受理的请求只返回原回执，不回滚名称或恢复已删除会话。

## 请求与状态

手机发送前保存完整 Core envelope、任务 ID/标题和动作。身份、原版本和原输入在核实/重试时不变；不因 PC 版本前进而替换成新请求。`session_command_receipt([envelope])` 是只读查询：返回 null、原受理回执或持久取消状态。

用户选择结束跟踪后，先将本机记录保存为 `phase: retiring`，再调用 `retire_session_command([envelope])`。取消前断线与取消回复丢失都保留该阶段；重连后的核实仍为只读，重试只继续取消，绝不重新执行原删除。响应丢失不能变回普通执行阶段。

两接口只接受有效用户/配对设备、版本化的 RenameTask/DeleteTask 和合法命令身份。PC 网关替换为认证设备 actor；指纹绑定 actor、原版本、命令内容及 schema。状态响应携带原 commandId/idempotencyKey，已受理状态另带 acknowledgement。手机检查这些身份后才清理当前匹配记录；旧对话框不能取消新记录，迟到回复不能清理替换后的操作。

## PC 的原子栅栏

SQLite `command_retirements` 保存逻辑键、请求指纹及取消时间，不保存标题或命令正文，独立于会话历史和投影。

- 取消事务取得写入锁，先查原受理回执；已受理则返回原回执，否则持久插入栅栏。
- 正常 append 和删除墓碑回执生成均在自己的事务里检查栅栏。检查与受理不能分离；两个 SQLite 连接竞争也只会有一方成功。
- 原请求被取消后，即使任务后来被其它操作删除，也不能通过删除墓碑去补写一个“已受理”回执。
- 会话清理、投影重建和正常重启不删除栅栏；取消本身不推进任务版本，也不改变名称/历史。

## 数据库格式

格式 1→2 的事务迁移只新增表，不重写已有内容。新库也使用格式 2。旧程序通过已有的格式检查拒绝打开新格式，避免降级后绕过栅栏。此处是 PC 数据库格式，JSON/Core schema 仍为 1。开发验证使用临时数据库，没有为验证切换日常 PC Core 或迁移它的数据。

## 证据

- 存储测试：重启、投影重建、会话历史清理、已受理结果、错误身份/内容/版本、错误作用域、两个真实 SQLite 连接竞争、1→2 迁移后保留数据。
- 手机：未知结果、原版本重试、明确拒绝、错误回执、取消前断线/取消回复丢失、旧确认对话框、就地继续取消与不重发原请求。
- 隔离真实 Core/Noise/WSS 网关：取消前后两种丢失、手机恢复、迟到原请求拒绝、后续新请求仍可正常执行；保留其它配对/流式/审批/Git/终端启动等恢复链路。
- 当前：手机 249 项、PC 库 281 项通过/7 项跳过、存储层完整 151 项通过；严格 Clippy、静态分析及 iOS/Android 普通应用构建通过。测试未调用付费模型或真实 PC 键鼠。

仍须逐项核对终端停止、保持唤醒、剪贴板等其它写入；不能把这两个会话命令的完成等同于所有操作恢复已经完备。

## 终端关闭后续

终端页和运行页停止/重启现已接入独立的终端关闭持久回执、受理/取消栅栏、后台代次校验及退出证明，详见 [终端关闭恢复](terminal-stop-recovery-2026-10-22.md)。保持唤醒与其它写操作仍继续审计，不将该项完成等同于所有操作可靠性完成。

## 保持唤醒后续

保持唤醒设置的原请求、版本栅栏、未知结果核实和换连接页面恢复已补齐；详见 [保持唤醒恢复](power-policy-recovery-2026-10-22.md)。其它写操作仍按完整范围继续审计。

## Agent 停止后续

版本化 CancelTurn 已加入同一持久指纹/原子取消栅栏；独立手机运行级记录避免其它待核实操作阻塞停止。活跃会话的版本冲突必须先取消旧请求，才可在同一 run/turn 更新版本。详见 [手机 Agent 停止请求恢复](task-cancel-recovery-2026-10-22.md)。
