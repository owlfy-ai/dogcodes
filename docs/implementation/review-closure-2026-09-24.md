# 审查修复闭环与共享项目验收（2026-09-24）

## 实现

逐轮审查和项目 Diff 审查共用问题勾选与修复操作。选择问题后，点击“交给主 Agent 修复”会在原对话提交一轮修复，不切换主 Agent，使用其默认权限并保留原生审批；当前主轮次忙碌时不允许重复提交。原报告、所选问题索引及输入哈希保存在 `turn.queued.reviewFix`，服务端验证任务归属、终态、哈希及选择范围，并从已保存报告构造修复材料，客户端不能替换证据。

原报告下展示选中问题对应的修复轮次状态；完成后点击“复审修复后的版本”，使用原有工具栏选中的审查 Agent。新 Run 的 `recheckOf` 关联原报告和修复轮次，输入来自该修复轮次的冻结改动，并附带选中的原问题。原问题仍存在时可再次报告；原报告中的文件编号/行号不能当作新报告位置。新复审中的问题也可以继续选择修复。

“重新检查原快照”及逐轮“重新检查”仍是原材料重试，必须保持输入哈希和复审关联，不冒充当前代码。修复、新版本复审、原材料重试分别保留记录。关联从事件重建，重启/重建投影不丢失，不新增数据库表。UI 操作保留幂等标识，网络结果不明时重试不会重复创建轮次。

不会仅凭 Agent 声称修复、复审零条问题或独立 AI 复核自动标记“已解决”。复审覆盖的是修复轮次保存的文件与有界上下文；未进入该轮快照的原问题不作解决结论。多目录的修复材料保留目录信息，来源不明时要求 Agent 核实；没有恢复项目级单写者门禁。

## 实机发现并修复的问题

1. 不完整/非结构化回复曾把分组标记为完成。现在显示部分完成、保留原文与可用问题；有缺口的运行不能视作完整成功。
2. Kimi 返回唯一完整的 JSON 代码块后追加说明，旧解析器拒绝整段输出。解析统一支持纯 JSON 对象或唯一完整 JSON 代码块加外围说明；外围说明不计入结构化结论，并明确提示。多个候选、外围另含对象、截断代码块仍拒绝。初审、冻结检索请求与独立复核复用解析。
3. 保留结果的失败/取消/中断审查也可带状态进入主会话上下文和历史投影；不能丢掉部分有效证据，也不能把它们当完整成功。

## 真实共享目录并发

隔离例程：`cargo run -p agent-store --example live_shared_project -- codex|kimi [cancel]`。只创建临时项目/数据库；普通会话权限，等待原生审批，不使用自动全放行。复用既有 native Driver 工厂。

| 场景 | 结果 |
| --- | --- |
| 同一个 Codex 安装的两个对话，同时修改同目录 `a.txt` / `b.txt` | 通过：两个活动轮次重叠、独立原生 Session，两个审批分别处理，文件内容及消息归属正确 |
| 同一 Codex，取消 A 的待审批轮次，让 B 完成 | 通过：A 文件保持原样，B 写入成功，未串消息/取消 |
| Codex 与 Kimi 两个对话同时写同一目录 | 通过：两个审批与原生 Session 独立，两个文件都正确写入 |

可复核摘要在 [evidence/review-closure-2026-09-24](evidence/review-closure-2026-09-24)。初次脚本未兼容审批的 `input` 包装而停止，未批准意外操作；随后适配并重跑。Kimi 原生审批仅提供 `Write b.txt` 标题，验收限定为该临时文件，另核对最终内容。此矩阵不代表所有供应商两两组合，也不保证两个 Agent 对同一行的修改自动合并。

## 桌面真实流程

环境：macOS，独立 `dogcodes Review Closure.app`，前端端口 1432，`review-acceptance` 隔离数据库。应用数据：`dogcodes-review-acceptance-izw10p`（系统临时目录）。没有调用 Claude；其 Key 过期的既有阻塞仍保留。

- 从主对话真实发起 Codex 修改，原生审批后形成两个 Python 文件的真实逐轮快照。
- 逐轮入口选择 Codex 开始 2 组审查；项目 Diff 入口选择 Kimi 并行开始。取消逐轮运行，项目运行继续；逐轮原材料重试完成，两项缺陷均有独立复核。
- 项目报告点击问题可打开冻结历史 Diff。期间追加的工作区注释不会进入旧材料；刷新后明确显示报告属于此前快照。
- 重启后仍能读取两路报告。只勾选 Kimi 项目报告中的越界问题，交给主 Agent Codex 修复。审批准确指向 `reports/last.py`；最终恢复 `values[-1]`、保留审查后新增注释，未改动未选中的 `payments/withdraw.py`。
- 再次重启仍能看到修复轮次关联，并从原报告发起修复新版本复审。首轮 Kimi 复审返回 JSON 加外围说明，触发上述解析兼容性修复；失败记录保留。
- 最终从修复轮次点击“重新检查”，Kimi 真实重试通过：1/1 组、1/1 文件覆盖、结构化报告零问题，追加说明被正确保留为原文。新旧版本输入哈希不同；失败复审与其重试输入哈希相同，复审来源关联保持。后续追加的 `AFTER_RECHECK_STARTED` 注释未进入送审材料。详见 [桌面证据](evidence/review-closure-2026-09-24/desktop.json)。
- 当时使用一次性只读脚本复核哈希、修复选择、新旧来源、幂等提交次数和重试关联。2026-10-19 删除该脚本：其中固定夹具、冻结材料和分组工作流断言已不适用于后续简化的审查流程；本节保留历史验收结果，当前验证使用 Core/Store 回归与[平台验收](review-platform-acceptance.md)。

隔离特性直接使用本地 Core；这些桌面结果不冒充生产独立服务 IPC 或所有平台全矩阵。首次测试使用的临时安装标识被重新检测替换，选择实际检测到的 Codex 后继续；未将此夹具注册过程记为产品审查失败。多目录同名文件仍由已有 Core/组件回归覆盖，本轮没有重新跑多目录桌面矩阵。
