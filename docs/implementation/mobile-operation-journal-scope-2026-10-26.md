# 手机操作跟踪：并发、移除电脑及结束后的重试

日期：2026-10-26。属于“完善远控视频后继续 PC 功能对齐及操作恢复完整性”的后续工作。本轮修改手机端，不修改视频协议、服务端或日常 Core。视频的 RustDesk 对照及待办继续以 CURRENT_WORK 和专门实施记录为准，业务恢复不声称来自 RustDesk 协议。

## 已复现的问题

修改前用受控存储与假 HostApi 执行四项测试，三项失败、一项通过：

- 卡住普通操作的本地写入，再移除电脑：旧写入仍能结束并调用一次 RPC，移除与普通记录没有共同串行边界。
- 两个 MobileOperations 同时提交到同一电脑的主槽：两个 RPC 都发送，后一条覆盖前一条待确认记录。
- 结束旧评审跟踪并发起新评审后，旧卡片重试仍再次发起旧评审。
- 网络回复挂起时，独立工作区槽仍可操作：此行为必须保留。

另外核实到相同项目路径/名称可生成内容相同的本地记录；旧查询的迟到清理可能误删替代记录。Git 提交后自动推送及终端启动存在多步骤接续，“不再等待”的关闭回执丢失不能使恢复变回原来的执行请求。

## 实现

`dogcodes-app/lib/core/recovery_journals.dart` 按同一个 SecretStorage 实例与 hostId 共享串行队列、对象代次及清理状态。普通主/工作区槽与取消、终端关闭日志统一使用该队列；仅存储操作及 RPC 准入在队列内，网络回复在队列外等待，避免独立停止及其他电脑被慢网络阻塞。

移除电脑同步使所有旧对象失效，再排队删除四类记录。旧存储写入即使此后返回也不得发送。重新建立的对象排在清理后保存，旧对象重复清理不能删除新记录。存储删除失败时，新对象不得执行操作；原清理可重试。此代次仅存在当前 Dart isolate，不代替持久的绑定身份。

普通新记录新增本地 `localTrackingId`，不发送到 PC。替换、清理使用完整且不依赖 Map 顺序的相等比较。发起有副作用的 RPC 前再次核对当前记录、所属代次、结束状态，并复制 JSON 参数。覆盖消息、审批执行/失效、会话/偏好/Fork、项目、评审/修复、Git/暂存、终端启动/运行配置、取消和终端关闭；保持唤醒的幂等设置也检查对象仍有效。只读查询仍可核实旧回执，但不能清除替代记录或凭旧记录继续执行。

选择不再等待消息、Git/暂存或启动时，先保存 `phase: closing` 再发送原身份的结束请求。未知结果保留此阶段；应用重新建立操作对象后，重试只会继续结束，不能重新提交任务、自动推送或启动。结束请求已经到达 PC 之前开始的执行不会撤销。已启动终端的原回执仍返回“已找到终端”，不误报“原启动已取消”。卡片说明和重试文案区分正在结束与重新执行。

## 验证

所有测试只使用内存/受控失败存储与假 HostApi，不建立真实远程会话，不执行 Agent、Git 或终端命令。

- 新增 `test/operation_journal_scope_test.dart`，16 项时序/失败测试通过：上述三个反例、网络不占用准入、跨电脑独立、旧对象失效与新对象排队、重复移除、相同项目记录的迟到清理、目录核实期间移除、写盘失败、删除失败重试、迟到提交不能推送、消息/启动结束丢回复后恢复、已启动终端准确反馈、旧取消/关闭卡片不能重发或误删替代记录。

- 对 10 个操作库、待确认卡片及新测试运行 Flutter analyze，12 个文件无问题；格式与 diff 检查通过。
- 修改前失败日志 `/tmp/dogcodes-journal-before.log`；最终完整测试 `/tmp/dogcodes-journal-final-full.log`；分析 `/tmp/dogcodes-journal-final-analyze.log`。临时日志不随仓库发布。
