# Codex 原生进程、通信取消与停止确认（2026-10-23）

本阶段接续 Pi、Antigravity 和 ZCode，补齐当前 Core 内 Codex 的私有 app-server 作用域、关闭/恢复证明、通信取消及停止确认。一个 Codex Thread 使用一个私有 app-server 进程；不会关闭用户的独立 Codex GUI，也不操作其它 Thread 的私有进程。手机、服务端和视频管线没有生产代码变化。

## 原进程作用域与退出证明

- `Connection` 启动改用 `OwnedChild`，独立 supervisor 持有原 Unix 进程组 / Windows 私有 Job、stdout pump 与 stderr drain。调用方取消、actor Drop、初始化探测取消后仍保留原作用域并继续清理。
- 输出 EOF 不作为退出证明；直接进程先退出但后代持有管道，仍能由 supervisor 的进程观察触发原组收尾。无法确认时发布未知并退避重试，不按迟到数字 PID 操作。
- `Connection` 关闭先释放 stdin，给予自然退出宽限，然后必要时终止原作用域。临时读取/探测的关闭等待有 8 秒期限，未获证明就返回错误；actor 也仅在清理获证后确认关闭。等待超时/取消不取消 supervisor，registry 仍保留原作用域，不提前把未知当作退出。
- registry 同时保留原命令通道和原 NativeProcess。命令通道关闭或 actor 没有回复，不能直接解释成 native 已退出；shutdown、恢复和安装替换对象之前仍须检查该原作用域的回执。删除时保留同一 sender 身份比较，防止旧等待者删除新注册。
- Driver 独立 owner 信号可关闭原私有 CLI，即使 actor 阻塞于 prompt 写入。释放的只是该 Driver 拥有的进程；不是按进程名结束所有 Codex。
- 额度辅助连接不再反向持有拥有它的 QuotaState，解除原来的 Arc 引用环，并订阅同一 owner 信号。额度读取失败/取消后的原辅助连接保留到退出获证，再允许新辅助连接启动；不因清空缓存槽而跳过清理。
- stdout pump 的未读缓存为 64 KiB，用背压限制内存。它不是累计传输限制；单条 RPC 仍使用原 8 MiB 上限，可以持续处理多条数据。

## 通信取消

原 `read_value` 的局部字节缓冲会在 `run_turn` 的 select 切换到审批/停止命令时随 future 一起丢失。现在缓冲属于 transport，已经消费的半条记录可以继续拼接；完整行、大小预算和解析错误仍由同一 parser 校验。取消只读等待本身不损坏连接。

写入则不同：JSON、换行和 flush 未全部完成时取消，必须先使管线失效；下一请求不能附在半条 JSON 后。完整控制请求已发送但未得到响应时取消/超时，同样停用原连接，避免继续使用未知会话状态。收到明确原生错误响应不损坏健康连接，原错误类型保持不变。语法错误、超限帧和不合法 frame 也会关闭原管线。

排队中的 prompt 如果接收方已经取消，actor 不再派发；已原生派发但无法交付 stream，则清理该原会话。Core 的活动事件流已释放时也停止原生任务，避免任务失去业务接收者后继续执行。这是 Core/driver 事件流，手机或桌面关闭页面不会直接释放它，仍遵循既有后台执行架构。

## 停止确认

`turn/interrupt` 的 RPC 回复不再直接返回停止成功。同一次活动轮次只发送一次原生 interrupt，重复等待者加入原 actor 的等待队列；某个等待者取消不会取消原请求。

只有带原 Thread/Turn 身份和可识别终态的 `turn/completed` 才证明任务结束。原生失败/额度耗尽仍按实际事件显示，并非改为中断成功。控制确认超时、流结束或关闭抢先发生时，等待者收到失败，原私有进程继续清理；不伪造完成或中断。正常运行没有新增总时长限制，只有停止控制期限。

## 本地验证

新增 15 项回归：4 项通用 transport 双工测试、11 项私有 Python app-server 生命周期测试。半读/半写取消、stop ACK 提前返回及额度引用环共五项先复现旧代码失败，再验证修复。

- 通信：半条读取取消后保留原字节；半条写入取消后拒绝复用；完整控制请求的响应等待被取消；明确原生错误后仍能正常发下一请求。
- 进程：初始化探测取消、EOF、直接进程退出但后代持管道、Driver Drop 时写入阻塞、关闭等待取消、丢弃 Core 流、取消排队 prompt，以及关闭 actor 通道仍活着的原进程、恢复前等待原作用域清理和旧连接 Drop 不影响新实例。
- 停止：取消等待后的重试只发一次 native interrupt；只有 ACK 没有真实终态必须失败。
- 辅助连接：查询过额度后释放 Driver，缓存状态必须能销毁，原辅助进程必须清理，不能留下引用环。

macOS 与隔离 Linux Codex 完整各 46 项通过，各 3 项原有真实/按需用例保持跳过；两平台 all-targets 严格 Clippy 通过。Windows `x86_64-pc-windows-msvc` all-targets 交叉检查和严格 Clippy 通过。最新桌面完整库 331 项/Core 92 项通过，另 7 项桌面按需用例未启用，桌面 all-targets 严格 Clippy 通过。

测试仅创建自己的 CLI 和子进程，未调用真实 Agent、模型或用户凭据，未替换日常 Core、运行模拟器、操作用户屏幕/键鼠/剪贴板。Windows 交叉检查仍不是实际 Job 行为验收。

## 保留范围

这是当前 Core 已持有原对象时的退出/取消保护，不是跨 Core 完整恢复。整个 Core 被强制终止、native session 同名恢复后才发起的新旧请求、其它临时元数据事务与 helper 进程、配置/审批并发及长期 actor 队列仍需继续审计。持续输出背压下的大请求双向排空仍须专项核对，不能以本轮半帧测试证明全部流控场景。Unix 主动 setsid/换组逃离的后代不在原组保证内。

ACP 仍需按其 SDK、共享连接和 native session 能力独立改造，不能直接将某个 handle 的 shutdown 变成杀共享进程。原生视频硬件加速、特殊来源、更高编码能力，全部平台/手机实机、真实 TURN 续期/弱网、地区网络、推送凭据及官方部署验收继续保留。
