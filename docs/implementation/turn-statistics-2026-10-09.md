# 每轮回复的数据统计

2026-10-09：每轮结束后的“复制回复”右侧增加统计图标。悬停或键盘聚焦打开共享结构化 Tooltip，支持 Escape 关闭。

## 展示内容

- Agent、本轮耗时，以及可获得的模型、模型请求次数、输入/输出 Tokens、缓存读写、推理 Tokens、原生费用和 Credits。
- 请求记录的输入包含缓存、输出包含推理，合计不重复加缓存/推理；未知字段不按零显示，不按价格表估价。
- 完成、失败、连接中断均有入口；历史轮次没有保存用量时明确显示“暂无数据”，不拿当前会话累计量补旧轮次。

同日增加配置生效确认、请求事实持久化、首个输出等待及 Claude / Pi 生成速度；最新行为、实测数据和边界见 [配置与用量可靠性](selection-and-usage-reliability-2026-10-09.md)。下文保留初版实现与验证记录，后续差异以该记录为准。

## 采集与持久化

普通用户提交的轮次在原生 prompt 前、原生流结束后各读取一次 session usage，每次最多等待 2 秒，不查询账户额度。结束快照在工作区变更捕获之前冻结，避免后续保存工作拖延采集边界。

请求级数据用同一 native session 的请求 ID 差集汇总，旧请求的后续修订不会再计入新一轮。对于复用会话，缺少基线时不把全部历史请求误当成本轮请求；新建会话允许从空基线开始。各字段只有所有新记录都提供时才汇总，缺失和溢出保留未知。

没有请求记录时，仅接受有新证据的原生 turn 摘要，或 Kiro observed Credits 的正增量。不直接相减任意会话 Token 快照，不用轮次 token 数推算请求数。

汇总通过 `turn.usage_recorded` 事件保存，时间线的 `turnCompletion.usage` 关联到相应 turn。后续轮次和实时额度轮询不修改旧轮次；投影重建可以恢复统计，不需要数据库结构迁移。可选用量事件写入失败不会改变执行结果。

## 边界

- 请求数据是 prompt 期间观察到的记录，不能保证包含全部原生请求；达到采集上限时另行标记部分数据。
- 同日后续改进已为 Claude 自主续轮接入所属事件流的请求记录；其他无可靠归属证据的用量保持未知。历史轮次不追溯填充。
- 原生 turn 摘要若数值与上一轮完全相同且缺少可靠轮次身份，保守视为无法确认的新数据。开始前失败、遥测超时或未提供数据也会显示暂无用量。
- 后台子任务的迟到遥测、持久化之后的原生用量修订不保证归属完整；当前面板不是账单审计记录。
