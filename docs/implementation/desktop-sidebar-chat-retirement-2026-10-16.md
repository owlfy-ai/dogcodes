# 永久删除后的问答恢复记录清理

对应 DT-09/DT-10，接续[后台删除边界](desktop-sidebar-chat-deletion-2026-10-16.md)。本工作块处理各客户端保留的原问答/清空请求，不把“查不到会话”当作删除依据。

## 后台证据

Core 新增通用只读 `task_deletion` 查询，返回 `taskId`、`deletionSequence` 或 null。它复用普通发送恢复已经采用的永久删除标记校验：必须是对应 task 流、匹配任务身份、具有有效流版本且 `permanent=true` 的规范事件。只有缺少任务投影、缺少回执、旧的软删除或查询失败均不能证明永久删除。

daemon 同名 RPC 和 Tauri `core_task_deletion` 提供该查询；Tauri 保留会话窗口范围检查，主窗口可以核实自己保存的各会话记录。TypeScript `CoreClient` 增加可选 `taskDeletion`，旧适配器没有此能力时保留本地记录。没有新增 CoreCommand、数据库表或任何写入动作。注册 handler 现为 122 项，其中生产 120 项。

## 客户端行为

`sidebarChatOperations` 只清理两个问答恢复键空间。先保存原字节快照，查询并验证永久删除证明，只有 taskId 一致且删除序号为正安全整数才进入清理；删除时再对比本地原字节，避免迟到查询覆盖新请求。归属不匹配、损坏记录、网络错误及存储错误保留待处理记录，各任务的错误不阻止其他任务核实。不会清除正文草稿、主题布局或其他业务恢复记录。

主窗口的 `useSidebarChatCleanup` 在启动、bootstrap 事件序号变化、聚焦、跨窗口 storage 变化及 30 秒补漏时发现并核实记录，包括已不在会话列表中的任务。单次仅一个清理过程，期间新触发会在本轮后继续检查；窗口卸载或切换客户端后，旧证明不能再清理本地记录。失败留待下一次触发重试，不发起问答、清空或其他业务写操作。

手动核实和重发原问答/清空前也查询删除证明。已删除时结束原恢复记录并明确提示，不重发变更；若发送已被后台拒绝，随后确认永久删除，则显示删除结果，而非继续声称原请求保留。证明成立但本地删除失败时，提示本地清理未完成，仍不重发原操作。
