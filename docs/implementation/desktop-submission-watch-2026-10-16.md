# 发送恢复的后台变更订阅

日期：2026-10-16。对应 DT-08/09/10，承接[发送恢复故障隔离](desktop-submission-isolation-2026-10-16.md)。后台记录及 Core 回执仍为事实源，订阅仅提示重新查询。

## 实现与边界

发送记录原子发布后通知本机客户端，覆盖新登记、证据化结束及永久删除清理。即使发布后的目录同步失败，也发出提示，让客户端核实已可见的记录；通知本身不宣称操作成功。Get/List/Resolve 查询和已存在记录的同 ID 重复登记不写文件、不制造通知。

`state_changes.rs` 提供容量有限、可合并的通知流，发送恢复与 Diff/Git 共用这一机制；每域最多 64 个订阅，连接断开释放资源，初次连接和重连先要求重新读取。通知只有 invalidated/heartbeat/error，不携带正文、附件或回执，不写进 Core 业务事件日志。Diff 仍在建立订阅及交付提示时验证原任务范围。

本机 daemon 的 `submission_watch` 复用现有有超时的帧传输和转发循环。Tauri 增加 `core_submission_watch` / `core_submission_unwatch`，仅主窗口可建立全局发送恢复订阅；窗口只持有可取消转发任务，复用现有窗口关闭清理。关闭窗口或退订不取消、删除或重放发送请求。当前可信本机通信保持原有 endpoint token 校验，不等于已交付远程配对授权。

前端 `invalidationWatch.ts` 复用 Diff 的订阅共享、退避重连和过期回调隔离；`TauriCoreClient.subscribeSubmissionIntents` 接入同一协议接口。每个客户端的恢复面板与主界面共用发现轮询及订阅，最后一个使用者退出才释放；重复解除同一订阅不会误减其他使用者的计数。

一次查询进行中收到新提示，会在该查询结束后再读一次，防止只复用旧 Promise 而丢掉最后一次变更。发现始终只读，恢复动作仍由用户显式选择。15 秒轮询、窗口聚焦和联网刷新继续用于外部文件修改、漏通知和旧客户端兼容。订阅不是文件系统监听，不能据此覆盖后台服务之外的写入。
