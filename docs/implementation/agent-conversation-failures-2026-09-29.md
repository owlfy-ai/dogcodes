# ZCode / OpenCode 对话失败修复与错误提示

日期：2026-09-29。

## 原因与修复

- **ZCode 0.16.9**：同一进程中的会话仍然存活，但 `resume_with_selection` 先检查冷恢复版本白名单，再查找活跃会话，导致切换回来时被拦截。改为先复用活跃会话；不存在活跃会话时仍保留冷恢复能力检查，没有把未经验证的版本标为支持冷恢复。
- **OpenCode**：终端默认安装为 1.15.10，桌面版及其托管 CLI 为 2.0.18，共享本地数据库。旧 CLI 日志出现迁移失败及 `NOT NULL constraint failed: session_message.seq`，ACP 曾无正文结束。macOS 发现阶段对默认 `~/.opencode/bin/opencode` 的 1.x 安装做兼容处理，优先使用通过身份及版本检测的桌面托管 2.x 或更新 CLI。没有命令行安装时也可发现该入口；自定义路径、别名/函数及其他 Agent 的终端优先级保持原规则。未修改、清空或降级原生数据库。
- **Claude Code**：原生返回认证失败，由用户处理登录/API Key，本次未修改认证配置。

## 用户可见错误

驱动错误先在内存中归类，再将固定 `failureKind` 写入事件；主对话投影根据类别显示中文说明和处理建议。覆盖认证、数据库版本不兼容、超时、连接中断、无回复、未配置、原会话不存在/不兼容及协议响应异常。ACP 不再把所有错误改写为“连接关闭”。

不直接保存或展示供应商原始报错，避免暴露密钥、地址及私人路径。无法判断的错误明确说明没有可识别的原因，不猜测认证或网络故障。已有记录若只保存了通用失败类别，无法据此恢复当时被丢弃的原始原因；新失败会使用新的分类提示。

## 验证

- ZCode 活跃会话回归：未知冷恢复能力时，活跃会话可复用，不存在的会话仍拒绝冷恢复。
- ZCode 真实原生验证：临时工作区连续两轮，第二轮复用同一会话，两轮均流式回复 `DOGCODES_OK` 并完成。
- OpenCode 2.0.18 真实 ACP 验证：临时工作区正常流式回复并完成，首段约 5.4 秒。
- 本机自动发现验证：通过真实登录 shell 解析及安装探测，选中了桌面配套的新 CLI。
- 安装选择回归：默认旧 CLI 的兼容选择、无终端安装、保留自定义路径、拒绝不匹配的身份/版本、新版终端优先。
- 错误分类及 Store 投影回归：认证、数据库、超时、未配置、无回复提示可见，事件不含模拟秘密；重建投影后结果一致。

`cargo fmt --all --check` 与桌面二进制构建通过。Driver API、ZCode、ACP 的严格 Clippy 通过；完整桌面严格 Clippy 仍受现有 `project_commands.rs`、`project_runs.rs`、历史 Diff、终端测试等模块告警阻碍，本次未扩展修改这些模块。Core/Store/Driver 库回归和桌面安装选择测试通过。

真实模型测试使用短提示，不执行工具或修改项目文件。此验证不等于所有模型、会话冷恢复或全部供应商已重新验收。桌面应用与后台服务需运行新编译版本并重新检测 Agent，才会采用新选择及新提示。
