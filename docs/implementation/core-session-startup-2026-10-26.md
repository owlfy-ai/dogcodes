# Core 主任务的启动接续与迟到资源清理

> 后续进展：项目运行配置分析与提交总结共用临时会话监督，观察超时不丢弃原创建，目录/租约跟随同一原清理；Core 空闲退休纳入临时操作保护，见 [临时会话接续](core-auxiliary-session-2026-10-26.md)。其余辅助事务与整体强退/重启继续。

日期：2026-10-26；工作分支 `remote-control`。这是工作包 2 的进展，不缩减远控视频、PC/手机日常功能及操作恢复的整体目标。仅使用当前运行期合同，不迁移旧数据或兼容旧版应用协议。

## 解决的情况

正常准备取消已经会等待 create/resume，但原执行工作者 panic 或未来被放弃时，启动未来仍随它一起消失。Core 此时没有句柄，只能保留未知状态；即使 Driver 后来创建了会话或已退出，也缺少把结果送回原 Run 的接续渠道。

现在主任务的创建、恢复、重配置和替代会话准备属于独立的 `session_startup::Startup`。它持有接受时的原 Driver、原 Run、请求参数和历史租约。执行工作者只持有结果观察者，不拥有原生启动未来。观察者丢失只设置原运行停止标记，不能取消、重新投递或改指向后来注册的 Driver。

启动登记与停止接受在同一个控制状态锁内排序，并与原清理的创建互斥。已经停止、已经开始清理或已经登记过启动的 Run 不会再轮询一份新启动未来。准备仍属于 Deferred 取消阶段，不把一个尚未进入 prompt 的调用交给 interrupt。

## 迟到结果

成功拿到句柄后，独立工作者先同步绑定原 Run 的实际 scope，再通知观察者，之后才由正常流程写 session.ready/session.resumed。没有在发布持久化身份前丢失句柄的 await 缝隙。

原执行工作者意外结束时，`Execution` 把 RunOwnership 移交给原运行时的清理工作者。运行时句柄在构造执行对象时捕获，因此即使对象在普通线程上被丢弃，仍能调度原清理，不会因 `Handle::try_current` 不存在就释放保护。迟到句柄通过原 Startup 状态交给同一次清理，不从持久化 ID 补造句柄。

如果原所有权确实已经消失，迟到候选不能绑定到后来 Run；它由独立清理保留原 Driver/句柄，并保留原控制对象的工作区保护直到退出证明成立。原运行仍有正常清理者时，不替它提前结束。

明确返回的设置错误沿用 Adapter 的资源清理合同，发布 Rejected 后可接续无句柄的失败收尾。panic、丢失结果或没有身份的未知启动不算普通拒绝；它们保留 Unknown 和工作区保护，不猜测新句柄，也不写假终态。

## 历史授权和工作区

历史查询租约改为共享持有：正常结果交接后，启动工作者释放自己的引用，主任务继续持有；观察者丢失时，原租约继续保留到原生资源退出。孤立候选同样遵守此规则。显式用户取消仍会立即撤销历史访问，保留引用不会绕过 revoke_history。

Run、工作区读保护、Driver 和实际会话一直跟随原清理。清理状态和最终失败仍按原 Run ID、原任务版本 CAS 写入；迟到失败不能覆盖后来运行。没有实际派发的任务不发送 prompt，不伪造 native_prompt_accepted 或 interrupt_sent。私有夹具验证了无 prompt、无错误 Driver 关闭和不会重复创建/关闭。

## 关闭回执与实际退出分开

原 `shutdown_proof` 在原关闭前捕获。关闭调用由独立任务继续轮询同一个未来，退出证明与它并发观察：原资源的正面证明已经成立时，不再被一个迟迟不返回的 shutdown RPC 挡住。

证明先完成时，原关闭任务继续执行，不被取消或重发；它之后返回错误也不能把已确认退出改回 Pending。没有证明且关闭失败时仍保持未知。观察预算仍只改变提示，不丢弃原调用。此处依赖 Driver 的原 scope/原资源合同，不能把别的实例退出当作这次证明。

## 重配置替代

重配置返回不支持后，取消不会继续生成替代上下文或创建新会话。已触及的原 scope 需要先退休；不把 CapabilityUnavailable 当成原会话仍可直接复用的证明。

原关闭已经开始时，等待相同关闭及相同退出证明；证明可以早于 RPC 回复。停止接受后不启动替代会话，并将已退休源映射按原 Driver 能力写为 resumable/detached，避免声称它仍在线。状态写入仍检查原 Run 与预期原映射。

## 仍须继续

本次独立工作者解决同一 Core/运行时存续期间的启动观察者丢失；它不是跨 Core 强退、系统重启或运行时整体销毁的持久化启动监督。panic 发生在身份返回前、原生未来永久不返回、监督者失联及外部脱离进程仍不能推断退出，需要继续补 Adapter 启动回执与进程恢复合同。

原生未标识回调、自动续轮、分析/目录/账号等辅助启动与临时事务仍需继续核对。重配置的旧源已退出、随后替代创建失败时的映射修复，以及取消前完全没有触及原生资源时的闲置会话归属，也须继续核对，不能以本阶段的取消回归替代完整恢复审计。

远控视频实机/弱网、HDR/光标/GPU，PC/手机功能对齐、推送与部署仍按 `CURRENT_WORK.md` 的八个工作包推进。

重新核对当前 Startup 和 run_cleanup：正常迟到句柄沿原 Run 接续关闭；明确拒绝依 Adapter 清理合同退出；身份返回前 panic 保持 Unknown，不重造句柄、不重发 prompt、不释放原工作区或历史保护。现有私有回归 `panicking_setup_without_a_native_identity_remains_unknown` 在当前源码再次通过，验证原资源仍报告 alive 时没有 turn.failed 假终态、没有错误 shutdown，并保持原 Run 和工作区排他，日志 `/tmp/dogcodes-core-unknown-audit-macos.log`。
