# 配置确认、用量恢复与生成性能

2026-10-09：落实模型/思考强度生效确认、请求记录持久化和每轮性能展示。

## 模型与思考强度

Claude 在发送消息之前读取 `get_settings` 的 `applied.model` / `applied.effort`，应用配置后再读取验证，不以控制请求返回成功或请求参数回显作为生效证据。原生拒绝或忽略变更时，恢复先前配置并再次验证；无法确认配置或回退状态则关闭该原生进程并中止发送。新建、恢复会话指定配置时也执行验证。

确认回退成功的会话保留原映射，不错误标记为不可恢复。UI 展示错误、恢复旧选择；若用户在等待期间已经为下一轮选择了新配置，不覆盖这份新选择。错误明确说明本条消息尚未发送。

Pi 保留已有 `get_state` 模型/思考强度回读。ACP 的 configOptions 校验原生 `currentValue`；旧式 `session/set_model` 若返回原生模型或错误字段则检查，移除把请求模型直接写成已确认模型的行为。

能力边界：旧式 ACP 只返回空确认时仍按协议接受，没有独立回读证据。Codex 仍通过原生 `turn/start` 参数提交每轮配置；这次没有增加独立状态回读。Claude 原生默认/auto 没有固定解析值，验证可读取状态但不假定具体默认型号/强度；本地转发服务最终使用的上游模型也不能靠 CLI 配置确认。本轮统计展示的是请求返回的实际模型标识。

## 请求事实与历史恢复

新增 `usage.request_recorded`，按本项目 turn 归属保存原生请求 ID、模型、token、原生费用和可用的生成时长。Claude / Pi 通过实时已结算请求事件记录，其他已有请求适配器保留开始/结束快照差集，并保存新请求事实。按原生请求 ID 去重，旧记录后续修订不会再计入下一轮。

`turn.usage_recorded` 仍是本轮结束时冻结的摘要。重启或投影重建后，如果最终摘要缺失，时间线从请求事实恢复；摘要存在则优先使用冻结值。统计写入是可选的，不因遥测写入错误改变任务执行结果。

Claude 原生自主续轮每次创建独立计量器，使用所属事件流内的实时请求记录，不从正在变化的共享会话快照猜测归属。后台子任务无法可靠归属时不放入当前根轮次，因此标记为部分数据。

新增完整性状态：原生本轮摘要为 complete，观察到的请求/Credits 为 partial，没有可靠证据为 unknown。采集截断有独立说明。不会把历史缺失补成零，也不会把会话累计用量补到旧轮次；这次未扫描所有 Agent 的原生历史文件追溯补录。

## 首个输出与速度

“复制回复”右侧统计图标的共享浮层增加：

- 首个输出等待：从本轮处理开始到首个非空正文/思考输出的客户端观测时间，包含准备时间。Claude 只发送无内容的首次输出信号，不保存私有思考正文。
- 生成速度（观测值）：已结算请求输出 Tokens 总和 ÷ 对应生成时间总和。Claude / Pi 在首个非空生成片段开始计时，原生请求结束时停止，不用包含工具执行的整轮耗时计算。
- 计速范围、数据完整性和缺失原因。只要参与统计的请求缺少输出量或有效生成时长，本轮不显示速度。

当前可靠计速适配的是 Claude / Pi。其他 Agent 仍展示可确认的用量和首个输出等待；缺少请求生成边界时不推算速度。短响应、缓冲和网络会影响观测速度，它不是服务端的精确生成速率。

## 2026-10-10：Codex 与 Grok 请求统计补全

参考 codex-host v0.13.1（`08c7d65d`），按本项目 Driver → Core → Store 实现。OpenCode 继续使用 ACP；Grok 的增强也仍走 ACP，没有切换 HTTP 接入。既有“复制回复”右侧统计浮层复用新数据，缺失指标直接省略，不增加范围、完整性或数据说明行。

### Codex

- 新建线程开启 `experimentalRawEvents`，接收 `rawResponse/completed` 的原生 Response ID 和准确用量，不再把同一调用的累计检查点重复入账。旧接口未发送原生响应事件时，只在轮末提交已验证的检查点差值；不凭一次累计跳变推算多次请求。
- 每轮独立观测非空输出/原生输出块开始至该次请求完成的时长。工具执行、工具结果、其他线程、旧轮次、重复通知不进入计时；重试边界不明确时省略计时，保留准确用量。纯工具生成若没有可观测起点，不使用工具执行开始代替。沿用全轮速度规则：参与统计的请求缺少有效生成窗口时，省略本轮速度。
- 只读已绑定线程的 rollout，按 Response ID 补齐 `token_usage_record`，去重 `compacted` 内嵌副本，排除其他原生线程复制来的记录。逐 turn 的原生 `turn_context` 用于确认模型。原生日志与实时事件共用请求身份，核对历史时保留有效实时计时，并把模型修订持久化；不扫描其他账户或项目。读取上限为 32 MiB；超限/读取失败保留实时已取得数据。
- 本机 CLI `0.162.0-alpha.17.2` 的 `thread/resume` 未提供开启 raw events 的参数。恢复后的新请求可从原生日志准确取得，但实测没有实时完成事件，故该轮不展示生成速度；不声称所有恢复会话都能计速。

### Grok

- 从 `_x.ai/session_notification` 的 `response_completed` 采集每次调用。原生输入不含缓存，归一化时加缓存读写；输出已含推理，不能重复相加。正文、思考和工具参数的非空增量提供生成起点，完成事件提供终点；工具执行和结算 I/O 不进入窗口。
- 提供 `message_id` 的版本按原生 ID 即时记录。本机 `1.0.50` 省略此字段，只提供签名：签名只用于识别重发，不当作请求 ID。该版本先保存逐次观测，取得原生 prompt ID 后核对调用次数以及输入/输出总和；一致时使用原生 prompt ID 与响应顺序建立稳定请求键。不满足核对条件时不制造逐请求数据，仍可显示可靠的原生本轮摘要。
- 每次完成异步查询 `_x.ai/session/usage`，有界超时；费用为进程附着后的累计值，按固定历史基线处理，不反复累加快照。代次与响应顺序排除其他会话、重复查询、乱序以及轮次结束后的迟到结果；查询失败保留已有数据，不影响对话。重建连接时重置费用基线。
- 轮末只读原生历史核对账本；已由逐响应事件覆盖的轮次不再添加单调用摘要。失败/取消保留此前已确认的请求；没有原生身份或可核对摘要的匿名观测不强行入账。多调用只有整轮费用时，Core 使用新原生摘要中的整轮金额，不将其分摊到请求，也不使用会话累计费用填本轮金额。
- 新原生轮次缺少费用或标记费用不完整时，清除上一轮金额；该规则在共享快照合并内原子执行，也覆盖历史读取。新建 Grok 会话以已知的零历史费用作为基线，恢复会话读取原生历史确定基线。
