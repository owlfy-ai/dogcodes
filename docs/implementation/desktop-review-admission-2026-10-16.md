# 审查入口的后台 Agent 准入

对应 DT-09/DT-10，接续侧边问答的启用状态与安装准入；主会话、提交说明、项目分析等入口仍需分别收口。

## 缺口与行为

原 `start_review` 只要求内存中已注册驱动，直接调用 Core/daemon 或使用旧窗口仍可能启动已禁用、探测失败、已移除或非当前安装的 Agent。`review_executors` 也直接返回注册驱动列表。

现将侧边问答已有规则提取为 `execution_admission`，由审查和问答共用。新审查必须满足后台共享启用设置、明确且匹配的 installation ID、Ready 状态、当前选择及已注册驱动。候选列表同样过滤；底层查询出错时向客户端返回错误，不将不可核实的状态当作可用。没有增加只读能力限制，既有 Agent 独立完整权限审查方式保持原语义。

审查先持有 `active_reviews` 门禁并查询原请求，只有新工作才取得 `agent_admission` 读锁；检查、材料准备、持久受理和 worker 启动期间保持读锁，与设置/安装/驱动变更排序。锁顺序未增加反向路径：删除及项目目录编辑仍按 review→sidebar，设置/探测写入不取得这两个业务门禁。

同一 run ID 的已受理请求先按原载荷核实并返回记录，不重新执行；禁用、安装降级/切换/移除不取消已受理审查，也不阻断查询和取消。新请求被拒绝时不写入审查受理记录，不自动切换 Agent。

Core `review_executors` 改为可返回错误；本机和 RPC 适配均接通，成功 JSON 仍为原 executor 数组，没有新增协议命令。测试及隔离实机示例保存安装探测事实并使用其 installation ID，没有为缺 ID 的测试驱动添加生产例外。实机示例的安装身份属于隔离验收目录，不代表生产发现链路已验证；本次未调用真实 Agent。
