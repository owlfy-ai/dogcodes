# 重编译后的桌面与忙碌后台重连

日期：2026-10-17。

## 原因与处理

启动日志反复停在 `desktop.retire_old_core`，旧后台仍存活并持有 Agent 进程。桌面检查到可执行文件构建身份变化，调用 `retire_if_idle`，收到 `false` 后错误退出连接流程，进入“暂时无法打开对话”页面。故障并非数据库损坏或外网连接失败。

`daemon::start_or_connect` 现在优先在空闲时更换后台；当后台拒绝退休时，继续连接已完成认证、协议版本相同的服务，并记录 `desktop.reuse_busy_compatible_core`。保留已有后台的执行所有权，不停止任务、不重发操作、不删除数据、不启动第二个写入者。

后台仍运行原构建。新构建中的后台逻辑在后续启动且后台空闲、成功更换服务后生效，不在任务执行期间强制切换。协议 `VERSION` 是兼容边界：不兼容的请求、响应或语义变更必须提升版本；构建文件时间/大小变化本身不代表协议不兼容。

## 核验

4 项原生测试通过：

- 新构建可重连同协议的忙碌服务，bootstrap 成功，原后台和工作保持运行；工作结束后仍能正常退休。
- 即使构建身份相同，不兼容 endpoint 协议也会拒绝连接。
- 原认证、协议版本和帧大小限制继续生效。
- 启动维护期间查询继续响应，并拒绝提前退休。

现有开发进程自动重载后的启动日志确认：8ms 连接原后台，564ms bootstrap 就绪，1908ms timeline 就绪。后台 PID 未更换；未中断已有任务、清理数据库或制作安装包。
