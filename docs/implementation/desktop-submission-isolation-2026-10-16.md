# 发送恢复记录的故障隔离

日期：2026-10-16。对应 DT-09/DT-10，承接[共享发送记录](desktop-shared-submission-intents-2026-10-16.md)。本次不改变 Core 命令、业务版本、数据库或自动执行策略。

## 问题与处理

此前后台目录枚举、逐条记录读取、删除后清理任一处遇到坏记录即中止；桌面发现流程也会在第一条错误后停止，并用整个面板的错误替代所有有效记录。因此单条损坏记录可能阻止其他已删除会话清除重复正文，也会让其他会话的恢复入口消失。

后台现在区分无法枚举目录与单条异常。目录本身不可用仍返回错误；能枚举时继续收集规范身份，将无法识别文件名的情况标为 `unrecognizedEntries`。List 返回待处理或不可读的身份，由 Get 独立核实；不可读记录占分页位置、参与游标，不能被伪装成不存在。已结束且可读的记录仍不出现在待处理列表。原始坏文件、不明条目及符号链接不被删除或覆盖。

删除后清理继续处理其他有效记录：逐会话取得 Core 永久删除证据，再逐条写紧凑结果；任一读取、证据查询或写入失败都会令本轮报告部分未完成，不把局部成功伪装成整体成功。无法确认归属的坏记录保留，下一次启动/显式核实仍可重试。没有仅凭投影缺失清空正文。

桌面逐条发现并缓存有效记录；本地坏缓存与后台单条错误都不再隐藏其他记录。恢复面板可同时显示错误提示和可读记录的核实/继续/放弃操作，仍须原请求身份及后台证据。发现本身只读，不自动执行、作废或关闭记录，也不以后台值覆盖损坏的本地原文。分页格式错误（含同页重复身份）仍拒绝。

不完整发现会阻止新的发送准备；后台对新 Put 仍严格检查全部待处理记录，无法排除重复时拒绝登记。已有正常登记的同一原请求可继续按原身份处理。不会为绕过坏记录生成新操作 ID 或使用新版本重发。目录修复后的再次只读发现可清除同步错误。
