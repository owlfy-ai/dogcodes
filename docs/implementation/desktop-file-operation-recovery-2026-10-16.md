# 暂存与文件修改的持久回执

日期：2026-10-16。对应 DT-09，衔接 DT-08/10。范围为暂存/取消暂存、单文件丢弃/忽略、批量丢弃/忽略；逐轮撤销和其他业务域继续单独核对。

## 实现

- 从 Git 操作中提取 `review/operation_journal.rs`，统一处理先写意图、原子保存结果、精确请求重放、运行中/中断未知、记录损坏拒绝执行以及任务删除清理。Git 的持久文件格式与成功布尔值保持不变，没有迁移或清空旧记录。
- 文件操作使用 `mutation_operations.rs`，保存在 `review/file-operations/<task>/<operation>.json`。请求绑定 operationId、taskId、命令及完整参数，包括快照、根目录、文件选择、操作类型和丢弃确认。结果保留原始 JSON：单文件丢弃的备份记录 ID、空返回值、批量操作的已完成路径及错误不会丢失。
- 现有四个原生修改入口增加必需 operationId；类型化后台 RPC 同样要求该身份。新增 `core_review_file_operation` 查询对应回执。实际修改只经类型化服务分派，不执行记录中的任意命令字符串。后台同一 gate 内检查会话、处理回执并执行操作，与删除/项目范围变更协调；查询回执不等待长操作占用 gate。
- 原有快照新鲜度、工作区范围、活跃 Agent 门禁、索引锁和文件备份仍保留。重复原请求优先返回持久结果，不能因原快照失效而再次写入，也不能覆盖首次操作后用户新增的修改。同 ID 改变文件选择或确认内容拒绝。
- `reviewMutations.ts` 在发送前持久保存客户端原请求，回复丢失先查回执；无法确认时保留待核实项，不换新 ID 重试。明确未找到记录时，仅允许用户重发相同请求；运行中和未知结果不重发。
- `ReviewMutationRecovery` 挂在共享 Review 面板，重开可核实。失败和部分完成结果保留到用户核对；批量操作展示原已完成文件清单，不自动重做整批，也不自动只重试剩余项。用户核对后可结束本次跟踪，再以新快照明确发起新操作。
- 后台入口总数更新为 102 个，生产 100 个。两个 GUI 验收脚本同步 operationId；旧 live-mixed 暂存参数由 path 修正为实际需要的 paths 数组。脚本仅验证语法，未调用真实 Agent。

## 验证

- 前端专项首轮 90 通过、5 失败（`/tmp/dogcodes-file-operation-frontend.log`）。新文件恢复 helper/UI 的 7 项、reviewClient 的 5 项和 Git helper 的 9 项均通过。3 个 Git 恢复用例仍按旧英文按钮定位，而工作区已改中文；2 个面板用例遇到并行修改中尚未补齐的 onEditProject 参数。
- 保留新中文文案并修正测试定位；再次读取源码确认 onEditProject 参数已补齐，没有回退并行修改。只复验两个受影响文件，74 项全部通过（`/tmp/dogcodes-file-operation-ui-final.log`）。当前五个相关文件累计 95 个不同前端用例最终通过，不是一轮全套通过。最终类型检查 exit 0（`/tmp/dogcodes-file-operation-types-final.log`）；此前类型检查同样记录了上述回调参数错误。
- 原生首次检查发现新增测试对泛型 RPC call 缺少返回类型标注，已明确为 serde_json::Value。原生专项复验 `cargo test -p desktop --lib review -- --nocapture` 共 39 项全部通过，exit 0（`/tmp/dogcodes-file-operation-native-final.log`），包含提取通用持久记录后的 Git 回归。测试覆盖真实 RPC 断连后暂存、消费快照后的原请求重放、丢弃后用户再次编辑再重放仍保留新内容/原备份 ID，以及部分批量结果跨新服务实例返回而不重做。
- 两个验收脚本的 Node 语法检查、diff 空白检查通过；本轮测试进程句柄均已收取终态。未运行全量前端套件、真实模型或安装包构建。新服务实例测试不等于真实后台进程崩溃/跨平台实机验收。
