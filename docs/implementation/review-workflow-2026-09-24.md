# 分组、冻结上下文和独立复核（2026-09-24）

延续代码审查、安全检查、性能分析三个类型，逐轮和项目 Diff 两个入口共用实现。沿用图标、Agent 选择及额度展示，不接入新模型服务，不依赖 OCR CLI。

## 借鉴与实现

参考本地 `~/Workspace/study/open-code-review`（`0243a38`）的 `internal/agent/grouping.go`、`agent.go` 中 `review_filter` 以及版本化文件读取思路。按本项目现有 Driver/事件存储实现，没有复制 OCR 引擎或新增模型配置。

- 按项目根、目录和材料大小确定性分组，每组最多 6 个文件、目标 64 KB 原文；超过目标的单文件独立一组。最多执行 24 组，超出部分明确标记未执行。组间串行，每次初审和二次复核新建独立原生 Session，共用所选 Agent 的现有接入。每阶段 3 分钟、整次 15 分钟预算（启动和清理另有短超时）。没有额外的 AI 分组请求。
- 每组只附自己的变更正文，其他组及关联代码通过冻结目录按需检索。检索协议为模型返回 `contextRequests` JSON，由宿主从已保存 packet 读取指定 source ID/前后版本/行范围，或做字面量搜索。不开放文件系统和原生工具。每阶段最多 3 轮、每轮 6 项、读取最多 80 行、搜索最多 20 处、每轮响应预算 24 KB；截断和缺失显式返回。
- 初审有问题时，再用新 Session 对逐条问题查证和寻找反例。复核可以检索同一份上下文。确认/反驳必须有能与冻结代码匹配的引用；否则降级待核实。原问题始终保留，复核不支持也不会删除。复核格式缺失、超时或取消均保留初审结果。AI 复核支持不代表已经人工确认。

## 同版本材料边界

逐轮 Git 从临时索引对应的 before/after 不可变树补采上下文，非 Git 从采集时的 before/after 快照补采未变文件。多目录保留根身份，不能混淆同名路径。Git Diff 上下文读取提交对象或受版本校验的索引对象，不读取当前工作文件；工作区比较排除其他可变文件，仅补充可证明来自比较版本的未变文件。索引/HEAD 改变或冻结超时则放弃补充上下文，变更正文仍来自原比较快照。

上下文只采常见源码/配置扩展名，排除构建/依赖目录、二进制、符号链接、子模块。每根最多 48 个文件、每侧单文件最多 16 KB、总计约 64 KB；Git 优先同目录，项目送审 packet 另设 96 KB 上下文预算。材料总预算不足时先丢弃可选上下文，保留原变更；不能把“搜索未命中”当作项目没有该实现。旧快照只检索其已存文件，不回读当前项目补历史。

packet 在持久化前统一脱敏并计算摘要。重试复用完全相同的 packet，重新运行所有组和复核，不静默混入新文件，也不自动消费额度重试。ReviewSource 支持取回已保存关联原文，缓存过期或后续改码不改变其内容。

## 状态与界面

`ReviewRun.workflow` 可选，保存各组文件 ID、阶段状态、独立会话 ID、检索次数/请求/响应摘要和初审/复核原文摘录；旧记录无需迁移。`Finding.verification` 保存 AI 判断、理由和已校验引用。各组结果及时保存，单组失败后继续其他组；整体标明未完成，用户可原材料重试。服务重启把未完成组标记中断，不重放模型请求。

两个原有结果区域共同显示分组进度、冻结范围说明、执行记录和逐问题复核结论。逐文件覆盖仍明确是 Agent 自报，分组执行完成不等于所有文件都经过充分检查。初审输出每阶段限制 64 KB；组执行记录各保留 8 KB 摘录，总初审回流原文限制 128 KB，超限明确标记。结构化问题最多 200 条，超限提示缩小范围。结果回流附独立复核摘要，反驳结论不会丢失成单纯初审意见。
