# Antigravity 启动耗时优化

## 已确认的瓶颈

2026-09-11 的“你好”任务从 turn.queued 到第一段 message.delta 为 28.327 秒。创建会话返回前 11.84 秒、原生 init 前再等待 11.42 秒，init 到首字 5.07 秒。初始日志无法进一步拆分进程锁与 Hook 验证。

桌面审批的原实现依次启动 `/hooks` 配置检查进程和真正的流式对话进程。原生 CLI 明确不支持在 stream-json 用户输入中执行 `/hooks`，不能简单合并命令。凭证刷新存在进程竞争，保留原有串行启动保护。

## 本次变更

- 进程内只保留一份成功验证的私有 Hook 目录，最多复用 5 分钟，不持久化。
- 复用键包括 Agent 和宿主可执行文件真实路径、大小和修改时间，工作目录/附加目录、允许传入的环境、工作目录祖先 `.agents` 的 hooks/settings、已知用户 Hook/settings 路径及私有目录内容；同时核验上次 `/hooks` 报告的全部文件来源内容。无法有界读取、发现符号链接或配置改变时不复用。
- 未命中时仍执行原来的有效 Hook 验证；验证失败不会发送模型输入。缓存不存储审批决定，每个新会话继续使用独立监听端口和随机令牌。
- Arc 保持私有 Hook 目录在验证缓存和原生进程使用期间存在，避免曾经发生的 TempDir 提前删除问题。
- 增加 spawn_lock、hook_verification（hit/miss）、process_spawn、native_init、first_text_since_spawn 耗时日志。不打印凭证、提示词或工具参数。首字指标表示进程启动后第一段文本，不是每轮首字。
- 同一活动会话的进程复用原已支持，本次未修改其权限/模型匹配或凭证保护。

## 范围

2026-09-28 对照本机 codex-host：该项目现只提供 Skip permissions，不验证全工具审批 Hook，
不能把它较少的启动步骤当作相同审批语义下的优化。其 `agy models` 就绪检测单次实测约 6.1 秒，
且不验证流式协议。本项目保留现有验证与串行保护；详见
[全部 Agent 初始化实测](all-agent-initialization-2026-09-28.md#对照-codex-host-后的进一步优化)。

首次使用、应用重启、切换工作目录或配置失效仍需完整验证，不能把缓存命中的结果宣称为所有消息的响应速度。模型和网络等待也不由此优化消除。依赖当前原生 CLI 的 Hook 发现规则；Agent 升级会令缓存失效。

真实验收使用 approval_probe：同一临时工作目录先拒绝再批准，检查审批前文件不存在、拒绝后无文件、批准后内容正确。不会修改用户工作项目。

最终复测：13 项单元测试通过、桌面 cargo check 通过；真实拒绝和批准两分支通过，审批前无文件、拒绝后无文件、批准后内容匹配。第二次创建会话 1401ms，其中锁等待 1398ms，Hook 缓存核验 <1ms。原生 init 首次 10988ms、第二次 5179ms，这部分未被缓存移除。证据：`experiments/approval-acceptance/2026-09-11/antigravity-performance/`。
