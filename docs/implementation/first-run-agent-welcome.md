## 界面

八个真实 provider 各一张卡片，使用自适应网格。保留各原生模型组及额度窗口，
每个窗口用圆环显示余量，下面直接显示重置日期/时间。Cursor 保留原生日期精度。
缺少余量时显示未知圆环；到期窗口不继续显示旧百分比；过期快照明确标记。
多个安装实例合并在同一产品卡片，可展开查看路径。

## 探测

欢迎页同时发起八个 `core_scan_agent(providerId)`，daemon 分别执行安装发现与 readiness，
每个 provider 返回后立即显示安装结果并查询该 provider 的额度；不等待其他 provider。
单个失败只标记自身卡片。每轮清空旧读数，不展示前次检测结果。

启动扫描与欢迎页通过 ScanCoordinator 合并同一个 provider 的在途检测，消除“等待启动扫描后
再扫描一遍”的重复进程。只共享仍在执行的请求；完成后立即删除，不缓存检测结果。
每次新检测都执行版本/身份探测（不再根据历史指纹跳过），Ready 后重新注册 driver，
欢迎页查询本轮 driver 的账户额度。旧的额度监控页刷新机制保持不变。
每个 provider 安装与连接探测设 90 秒总上限，额度沿用 Core 的 29 秒上限。

已有运行回合时拒绝重新注册 driver，用户可在回合结束后重试。同一 provider 多个安装
实例仍依次探测，避免原生认证文件竞争。重试按钮在整轮期间禁用，页面离开后忽略迟到响应。

readiness 使用现有原生控制面/账户检查，ACP 建立零消息会话。
欢迎页不发送模型消息，因此不保证生成接口一定成功；UI 明示实际响应以首次对话为准。

- 未发现安装：未安装。
- 原生 readiness 报 not_configured：未登录。
- 明确账户授权拒绝：未登录；Claude OAuth 权限缺失单独解释，不误判 API Key 无法对话。
- 新鲜、供应商报告的账户额度 + ready 安装：已登录，包括 0% 剩余额度。
- 网络失败、过期读数、无额度信息：检测失败/授权待确认，不当成未登录。
- CodeBuddy：原生会话连接就绪，额度暂不支持。
- Claude 自定义服务：官方订阅查询不适用，凭证待原生对话验证。
- Demo 标记演示安装与演示数据，不作为本机检测结果。

ZCode quota reader 的明确 login_required 经白名单错误码传入 Core，其他失败统一为
quota_unavailable，不透传供应商原始错误。ZCode 与 Claude 明确授权拒绝时清除旧拉取缓存；
Claude 欢迎页查询不再使用旧 stream push 覆盖 OAuth 拒绝。
