# 侧边问答与会话删除、项目目录变更

对应 DT-08/DT-09/DT-10，接续[状态订阅](desktop-sidebar-chat-watch-2026-10-16.md)。本工作块修复后台执行与会话生命周期的遗漏；不改变永久删除后不可恢复的现有产品语义。

## 修复边界

此前 Core 删除会话和修改项目目录只检查主任务与审查。独立问答不占用主任务字段，因此问答仍在运行时可能被删除，或者项目目录已经改变而问答仍使用旧目录；删除成功后，Core 的问答缓存和订阅源也未被释放。

现在删除和项目编辑取得与问答受理、最终收尾相同的问答互斥锁，在锁内完成业务验证和持久化。锁顺序固定为审查、问答；问答启动不反向取得审查锁。运行中问答以及已接受取消但驱动还在收尾的问答，均阻止删除所属会话及修改所属项目目录。仅修改项目名称仍沿用原逻辑；不会因为存在问答而自动取消任务。

删除完成持久化后才移除对应问答内存记录，关闭其通知源，后台转发随之结束。删除失败、版本冲突不会清空问答缓存。数据库原有永久删除事务负责清除问答所在任务事件、正文和回执，保留删除标记；不新增数据库迁移或第二套删除记录。

所有可能读取或重建问答缓存的入口（查询、原回执、启动、清空、清空回执、取消及订阅）改为取得问答锁后再核实会话存在。等待锁期间会话被删除时，它们不能依据先前的存在判断重新构建空缓存、返回旧结果或继续执行。已删除会话不接受新订阅，已有订阅关闭后查询同样失败。

## 验证

一次集中执行 `cargo test -p agent-core -p desktop --lib --locked sidebar_chat` 及 `cargo test -p agent-store --test task_lifecycle --locked`：**17 项 Core、7 项桌面问答专项、4 项存储生命周期回归全部通过**。进程 33833 已 exit 0，日志 `/tmp/dogcodes-sidebar-deletion-native.log`、`/tmp/dogcodes-sidebar-deletion-store.log`。`git diff --check` 通过，未重复运行已通过且未改变的前端检查。

新增用例：

- Core 控制锁等待，在七类问答操作到达后使会话不再存在，释放锁后所有操作均失败，缓存保持为空、订阅名额全部可用、驱动从未启动。
- SQLite 与实际 loopback RPC：问答启动及取消收尾期间，删除和目录修改都被拒绝；收尾后旧版本删除仍失败且保留历史，合法目录变更可完成；按最新版本删除后可重放删除回执，问答订阅退出，所有问答入口拒绝访问，存储只剩删除标记，不含原问答正文。
- 既有永久删除、重建、主任务/审查保护、共享 Artifact 保护和删除后快照清理失败恢复继续回归。

没有前端功能、公开协议、依赖或签名配置变更，没有生产打包和真实 Agent 调用。
