# 发布前统一当前数据格式

用户明确：应用尚未发布，不需要旧版兼容或旧数据迁移。本轮仅改代码和文档，不删除或转换本机真实数据。

## 实现

- PC SQLite 只初始化没有用户自建 schema 对象的空库；未标记的已有库或不支持的格式明确拒绝。现有当前格式打开时不补建索引、不回填投影。索引归入新库的基线 schema。
- 手机草稿 key 固定四项、缓存 key 固定包含绑定代次，删除三项草稿 key 和明文 host key 的解析；文件选择清理由 pickerId 校验。凭据/操作日志本轮检查时已经要求完整绑定身份，没有再加入字段补写或迁移逻辑。
- 保留移除/重新绑定时的分阶段清理、未知操作核实、迟到结果隔离。这些保护当前正常运行中的身份变化，不属于旧版本迁移。
- 当前手机已使用 clipboard_transfer 传输文本/图片；移除 PC 网关的 clipboard_get/clipboard_set 和旧分发分支。保留系统剪贴板工具及自动文字输入回退，不读取、不备份、不恢复原剪贴板。
- 服务端只提供根目录 schema.sql（当前格式 3）。事务与 advisory lock 只初始化空命名空间；当前格式不重复 DDL，其它版本、空版本表或没有版本标记的已有数据拒绝启动。删除三个增量 SQL 和 --import-routing、JSON 导入函数，同步 Docker/Kubernetes/部署文档。

- PC store：72 项单元与全部集成、严格 Clippy；未标记库（含只有 view 的非空库）拒绝前后文件字节不变，当前库不会补建缺失索引。
- PC desktop：339 项通过、7 项需显式环境的测试跳过，严格 Clippy；旧剪贴板 RPC 无法启动原生 worker。未访问真实剪贴板。
- 手机：源代码修改后完整 Flutter 390 项通过、无跳过，两个库文件分析通过；新增旧草稿 key 拒绝且当前草稿不被覆盖的磁盘回归后，local_workspace 专项 10 项通过。使用已有 endpoint 动态库，未启动模拟器。
- 服务端：4 项单元、19 项 HTTP/WS 集成及严格 Clippy/格式检查通过。全部使用新建的专属临时 PostgreSQL 数据库；格式测试另建独立数据库，覆盖空库初始化、不补索引、0/1/2/4 版本、空版本表与无标记已有数据拒绝，保留哨兵数据。仅清理自己创建的数据库，开发服务与既有数据保持。
