# 项目 Diff 审查（2026-09-22）

保留逐轮历史 Diff、代码审查、安全检查和性能分析。在项目 Diff 面板的比较控件下复用逐轮入口的三个审查图标和图标式 Agent 下拉，统一由 `ReviewActions.tsx` 渲染，侧栏和分离窗口共用实现。下拉的选中状态、额度、自动展开方向、点击外部/Esc 收起行为共用同一组件，不提供“关闭”选项。列表与额度复用已接入 Agent 的查询、筛选和额度组件，偏好沿用逐轮审查的本地选择，不切换主 Agent。

## 后续修正：额度缓存复用（2026-09-25）

右侧变更面板原先维护独立的空额度列表，每次展开 Agent 菜单调用全量 `quotaSnapshots()`，等待所有供应商返回后才显示，导致主对话已有读数时首次展开仍全是问号。

现通过既有 `AgentQuotaContext` 直接读取主界面额度缓存，与输入框、逐轮审查使用同一份数据；菜单打开、关闭均不再触发额度查询。缓存更新会同步到已打开菜单，按 provider/installation 匹配，确实没有读数时仍显示未知。分离 Diff 窗口没有主界面的 React Context，由窗口生命周期复用现有按供应商独立刷新的机制（打开窗口及每 30 秒刷新），保留本窗口读数，菜单本身不查询，也不等待最慢供应商才整体显示。

回归覆盖首次展开命中缓存、同供应商不同安装不串用、打开期间更新、反复开关零额外额度请求、缺失读数显示未知。前端 368 项测试、类型检查及生产构建通过；构建保留既有大 chunk 提示。

## 范围与输入

审查覆盖当前比较快照的全部文件：全部未提交、未暂存、已暂存、历史提交、分支比较，以及非 Git 目录的会话变更。搜索文件或点击单个文件不会缩小审查范围。变更面板保留比较模式；变更统计与审查操作合并为一行，左侧显示增删行数，右侧为三类审查图标与 Agent 下拉并居右对齐，审查结果和错误信息在下方显示；按用户要求移除顶部重复的目录名称与工具栏下方整段范围说明，目录仍可在文件列表中辨认，审查按钮悬停提示保留文件数。多目录按快照中的 root ID 区分。

桌面端接收 task ID、snapshot ID、检查类型和执行者，自行从所属任务的 ReviewHost 缓存及校验过的内容 Blob 组装文件前后版本、重命名路径、base/target 和文件元数据，不接收前端提供的代码或重新读取当前工作区。比较过期、目录不完整、Blob 读取失败、无改动或没有可分析文本时明确失败。二进制/子模块只保留元数据并标记未分析正文。

为避免静默遗漏文本文件，超过 1,000 个变更文件、600,000 字节文本预算或最终材料预算时拒绝启动并提示缩小范围。Core 继续脱敏，完整输入上限为 768,000 字节。此版本分析变更文件的前后内容，不提供全仓上下文检索、实际测试/基准运行，也未引入 Open Code Review 引擎。

## 执行与持久化

复用现有独立 Session/Run、3 分钟超时、最多 8 个活动审查、工具调用停止、单独取消、结果保存与重启中断恢复。项目请求使用 `turnId: null` 和 `sourceSnapshot`，逐轮请求仍使用原 turn ID；旧事件可继续读取。

项目结果保存在当前任务的审查记录中，在 Diff 面板单独展示，不混入逐轮结果卡片。已有 `review_result` 时间线投影允许空 turn ID，无须新增数据库表。重新检查复用原材料与来源，快照缓存过期也可重试；请求 ID 支持模糊响应后幂等重发。刷新或切换比较后，旧结果会注明来自此前快照。结果携带快照来源进入主任务后续上下文。
