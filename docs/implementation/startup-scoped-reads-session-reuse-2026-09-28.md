# 启动定向读取与 ACP 活跃会话复用

## 改动

启动时的工作区范围、任务运行状态、会话映射与初始化后的身份校验改为 `task_execution_state`，SQLite 在同一只读事务内查询当前任务、项目路径与该任务的会话映射，不构建其他会话、侧栏和 companion 投影。任务删除检查和待审批运行状态仍保留。这里只缩小查询范围，不跨轮缓存任务状态。

历史桥接、重建上下文和审查历史的事件上界使用 `event_head`，不再为一个序号加载全局状态。审查列表和启动辅助上下文按事件类型查询，只读取分叉来源、审查及关联修复状态；正文、思考、工具输出无需反序列化。辅助上下文从同一批事件生成来源和审查结果，不再重复读取完整历史。需要完整轮次材料的其他审查路径仍读取完整事件。

ACP 在当前连接内记录已成功初始化会话的目录、协商后的附加目录、MCP 配置和供应商初始化元数据。同一绑定的后续轮次跳过 `session/load`，继续执行模型、思考强度和权限校验/设置。不同任务或原生会话不会相互复用；连接重建、绑定变化、配置失败或 prompt 请求失败后走正常恢复。只有完成初始化才允许复用，配置更新通知仍合并到会话状态；过期响应不能使失败的状态重新可用。后续对照 codex-host，CodeBuddy 也已允许正常完成后复用，取消或失败后重建连接；实测与边界见[全部 Agent 初始化记录](all-agent-initialization-2026-09-28.md#对照-codex-host-后的进一步优化)。

首次创建原生会话依然需要 `session/new`。本次不预热额外会话，不改变模型流式分块，也不增加字符播放延迟。非 Git 撤销捕获保留，没有重新引入 Review 基线或历史数据迁移。

## 本地查询测量

对当前数据库的独立 SQLite 备份使用 `streaming_read_benchmark`，每项 10 次，调试构建：

| 查询 | 中位耗时 |
| --- | ---: |
| 全局 bootstrap | 38.747ms |
| 当前任务 execution state | 0.112ms |
| 事件序号 event head | 0.008ms |
| 审查列表 turn reviews | 0.300ms |

这是本地存储读取时间，不能作为模型推理或端到端首字加速倍数。启动阶段原先多处独立调用全局读取，现在各自按需读取。

## 回归范围

- SQLite：其他任务投影损坏时，当前任务查询仍可用；删除后不可执行；过滤查询跳过无关正文，保持顺序、分页上界和数量限制。
- ACP 模拟连接：同一会话连续复用不发送 load；目录变化发送 load；初始化失败、配置/MCP/权限元数据变化、未知连接/会话均不能错误复用。
- Core/Store：提交、恢复、历史 MCP、分叉、审查活动、修复与重审、启动计时集成回归。


## 真实 Cursor 复测

空闲开发服务使用新构建启动后，在 DrillHUD 新建诊断对话，提示只回复“性能测试完成”，不读取、修改项目文件或调用工具。首轮与后续一轮均成功，诊断对话随后清理。

| 阶段 | 首轮 | 后续轮次 |
| --- | ---: | ---: |
| 加载任务状态 | 0.92ms | 0.50ms |
| 辅助上下文 | 0.44ms | 0.43ms |
| 历史桥接 | 1.37ms | 0.02ms |
| 原生会话准备 | 8,433.96ms | 0.82ms |
| 提交至首段正文 | 3,383.96ms | 3,154.91ms |
| 首段正文落库与发布 | 1.62ms | 0.97ms |
| Core 收到提交至首段正文发布 | 11,888.56ms | 3,202.23ms |

此前后续轮次原生恢复单次约 2,988.70ms；本次绑定一致时不再执行该恢复请求。仅有少量本机样本，服务端与模型等待存在波动，首次创建仍可能慢。数据不包含前端绘制时间，也不能用来推断所有 Agent 的响应速度。

实测另外定位了会话身份校验中的剩余全局读取（后续轮次约 37ms），也已改为定向读取，保留 run/session 身份与 stream version 的并发校验；上表采集在这处最终补充之前，不将未复测的改善计入数据。

Core/Store/ACP/Desktop 默认回归通过，严格 Clippy 与桌面调试构建通过。没有改动前端渲染路径。
