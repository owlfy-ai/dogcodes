# 模型与思考强度目录刷新（2026-10-09）

两个下拉菜单均增加「刷新」入口，统一重新查询原生模型目录及当前模型的思考选项。刷新只读取元数据，不发送模型提示；部分 Agent 的协议需要建立临时元数据会话。

## 刷新与缓存

- 成功缓存有效期为 5 分钟。打开任一菜单、窗口获得焦点、页面重新可见时检查缓存；可见页面每分钟检查一次。缓存未过期不发原生请求；Agent 有活动任务或页面隐藏时暂停新查询，恢复后再检查。
- 手动刷新绕过成功/失败缓存；同一范围已有查询时合并请求。原生查询最多并行 2 个，保留原有 1.5 秒/4 秒有限退避重试，最终失败缓存 30 秒，之后可自动恢复。
- 缓存按 Agent 安装、版本、当前任务工作区上下文和所选模型隔离。读取携带 taskId 与 selectedModel，修复之前总查询默认模型、导致 Pi/ACP 等模型的思考选项不正确的问题。
- 改为按当前选择按需读取，移除启动时所有 Agent 的无工作区预取，避免额外原生进程与元数据会话。
- 刷新保留上次成功列表；失败显示说明和重试入口。刷新不改写用户的模型、强度或草稿。目录不再包含已选项时明确提示，保留选择，允许用户重新选择；不静默降级到其他模型。
- 旧任务/模型的迟到响应不会覆盖当前列表；刷新中发生焦点变化会继续等待同一请求，避免旧缓存盖掉强制刷新结果。

## ACP 适配

探测指定模型的思考选项时合并原生部分响应，保留原生默认模型。请求一个已从目录移除的模型时返回最新剩余目录，使前端能提示选择已失效，而不是整份目录读取失败。原生认证、网络或配置查询错误仍明确报告。

本机制不逐一调用模型验证可用性，不维护硬编码屏蔽名单。本机 OpenCode 2.0.18 新读取的原生目录仍包含 Exo Free；刷新机制不能保证过滤这种上游目录与实际模型服务不一致的情况。根据明确的模型下线错误标记不可用，尚未在本次实现。
