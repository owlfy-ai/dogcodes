# 终端关闭目标与输出代次

日期：2026-10-26。继续手机操作恢复与 PC 功能对齐，不恢复已移除的 terminal_stop_operation、撤回栅栏或额外用户按钮。改动使用现有 Core/网关、桌面终端及手机关闭入口；服务端不需要新的转发方法。

## 原缺口及实现

手机本地的关闭记录已有 terminalId 和 expectedEpoch，但原 terminal_stop 只发送 ID。重试前查询及收到结果后检查代次，都不能保护“查询之后、停止之前目标发生变化”的间隙。新增受控手机回归在旧实现上失败：核实返回后替换假 PC 的代次，旧请求仍让其状态变为 exited。PC 新契约测试在旧实现上也失败：缺少代次的裸 ID 请求仍被接受。两项反例均针对当前工作树源码直接运行，不使用源码覆盖或共享 target 的反例缓存。

现在 terminal_stop 请求必须为：

```json
{"terminalId":"终端原 ID","expectedEpoch":"用户已确认的终端代次"}
```

TerminalStopRequest 拒绝缺少字段、错误类型及未知字段，裸 ID 也不再接受。远程能力新增 terminalStopEpoch: true。手机新建关闭记录前检查此能力；重试只读确认能直接结清已退出目标，仍需执行时再次检查能力。旧电脑不支持时给出升级说明，不降级为裸 ID。

TerminalHost 在现有 admission 锁内获取原会话并检查 info.epoch，锁保持到停止受理完成。代次不同返回当前 TerminalInfo，保持进程不动；手机根据返回代次显示拒绝并清除旧跟踪。相同代次的重复关闭仍安全，终端已退出就返回其状态；原进程身份未知的旧记录保持既有拒绝行为。没有新增停止回执、持久撤回协议或按旧 PID 操作。

桌面端 core_terminal_close 和 daemon 客户端也必须携带 expectedEpoch。Core 客户端同时验证返回 ID/代次，不将条件不满足的返回视为关闭成功。TerminalDock 从已展示的终端状态保存代次，点击关闭时不临时查询并改投新的目标。

运行配置的 RunProcess 保留原身份的值副本，恢复时发现换代就拒绝继续绑定。启动回复未到时请求停止，会等待那次启动确认，随后以确认得到的代次关闭；多个停止等待共享同一次关闭。未启动就取消则不创建进程；启动结果未知则报待核实，不冒充停止完成。关闭回复失败可按同一目标重试。原 Core RPC 的三分钟等待上限仍适用，不引入无限等待或重新启动。

followTerminal 在交给视图初始元数据前冻结 ID/代次；每批输出先核对身份，再显示字节、缺口及新状态。即使外部修改传入元数据，也不能改变轮询或连接的目标。身份变化结束当前订阅并提示重新连接，不把新目标输出混入旧视图。

## 边界与继续工作

epoch 是服务端提供的身份，客户端不能只核对后再丢掉它；拒绝裸 ID 是本轮必要的协议收紧，手机与桌面组件升级后才能使用新关闭契约。本轮没有切换日常 Core 或安装/启动模拟器，没有调用真实 Agent 或触及用户终端；PC 测试只运行隔离 Core、自有临时目录和 PTY。

实机 Windows/ConPTY、真实手机 P2P/WSS 切换及三平台界面联调仍待安排。这里的已确认停止指 PC 接受了指定目标的停止，退出仍由终端状态/输出确认，不推断所有子进程已经退出。进程级强制恢复、跨进程解绑/重绑定的持久身份隔离及其余 ACP/Core 生命周期仍继续；视频 Wayland EIS、Linux 硬编、真实 GPU/网络、全部 PC 对齐、推送凭据与部署范围不变。
