# 受理驱动、组合恢复与共享状态刷新

日期：2026-10-17。按用户要求推进发布前基础改造中的三项：受理时驱动绑定、组合流程失败恢复、共享业务状态刷新。对应 DT-08/09/10 的本机部分；手机、配对、远程身份、官方服务与远控媒体仍未实施。本记录不将长期资源回收、性能或三平台候选验收标为完成。

## 受理与执行归属

- Core 提供 `ExecutionAdmission` 与 `AcceptedExecution`。共享读锁覆盖可用性检查、驱动捕获、调用方持久受理及派发；执行过程不持锁，禁用设置不等待模型完成。
- 项目分析的候选同时核对后台启用、明确安装身份、Ready 和当前安装选择。显式分析无可用 Agent 时在持久受理前结构化拒绝；自动目录发现仍可保存不可分析的状态。原请求回执仍优先于新工作检查。
- 项目分析在写入 catalog/running 回执前捕获驱动，排队、目录扫描以及整个多目录批次使用同一实例。不再在各目录执行时重新查注册表或重新应用新工作准入。
- 提交说明与直接项目分析调用也复用这一准入。提交说明经既有 daemon Review 服务执行，连接消失不取消服务端请求；服务请求读门禁保持到结果返回，与空闲退役互斥。它是只读生成，不添加新的持久 Git 副作用。

## 组合流程失败恢复

- 新 Fork 在外部创建前持久冻结源任务、项目元数据、历史边界/内容及完整文件快照。重启后重试读取原计划，不根据当前源项目或历史重新拼装。旧的未完成请求若缺少完整计划，保留目录并拒绝猜测接续；已完成的旧回执继续可读。
- Fork 回执补 `status/stage/error`，区分运行、失败、中断和成功；宿主重建不会把旧 running 当作仍有活动执行。失败阶段与错误写入规范事件。最终创建事实已提交但返回出错时优先核实原结果。
- 活动 Fork 与源会话删除、项目目录修改排序；只保护对应源会话/目录变更，不增加项目级单写者限制或阻止其他普通会话工作。
- Worktree 在创建前原子保存仓库快照与阶段；恢复前验证仓库、分支、HEAD 和暂存区。可核实的半成品仅接续 HEAD/index 阶段，不重新 checkout 工作文件。已完成的仓库保持用户后续修改；多仓库失败保留此前成果，重试只补未完成部分。
- 无记录的已有目录、被移动/删除的目录、孤立分支或已变化的暂存区不自动重置、删除或认领。中间已注册项目的目录发生改变时，不继续创建会话。
- Git 进程启动后的等待超时、输出丢失或信号退出记录为结果未知，不能当成明确失败后重新执行；原请求重放只返回原状态，组合推送不自动从 Unknown 接续。启动失败和可确认的正常退出错误保留原分类。
- 文件操作“结束跟踪”改为持久后台确认，与 Git 一样跨客户端共享；关闭回复丢失先查询，未核实前保留本机记录，不将结束跟踪当成撤销文件操作。
- 新增各窗口后台维护：Git、文件、Fork、审查启动/修复、取消、审批和运行配置的本机恢复记录，仅在 `task_deletion` 给出匹配的正序号永久删除证明、且原存储字节未被替换时结束跟踪。断网、查不到会话、无效证明、损坏记录均不构成删除依据；其他草稿、附件和 Worktree 不受影响。启动、聚焦、存储变化、删除事件与低频补漏触发核实。

## 共享状态刷新

- 复用一个有界、可合并的后台失效通知源，覆盖运行配置分析/编辑、终端启动/停止/退出，以及 Git/文件回执的受理、结果保存、跟踪结束和异常收尾。终端输出继续使用字节游标，不逐字节广播业务刷新。
- 新增本机 `project_runs_watch` 与 Tauri `core_project_runs_watch/unwatch`。订阅按会话验证、共享容量限制、初始失效刷新及窗口释放均复用既有机制。通知只表示需重新查询，不表示操作已成功。
- 运行面板订阅后重新查询 catalog/实际资源，保留定时及聚焦补漏；合并读取期间的新通知，丢弃已过时响应，不因刷新自动启动命令。隐藏或卸载后释放订阅。
- Fork 菜单在恢复原请求时通过规范事件订阅和回执查询显示进度，断线重连并重新核实；不会收到成功事件就自动跳转，也不会自动重试创建。
- 移除侧边 Chat 后，只有测试/验收使用的客户端 watch 方法改为条件编译，避免生产死代码告警；没有恢复 Chat 或操作历史浏览 UI。
