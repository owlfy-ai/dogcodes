# Claude Code / Kimi 升级排查与修复（2026-09-25）

## 已确认的问题

- Claude Code 2.1.278 的原生更新器能找到 2.1.282，但本机实际下载出现连接中断。完整执行约 263 秒后退出 1，诊断为 `The connection dropped while downloading the update (attempt 3/3: aborted)`。约 222 MB 的安装文件下载期间，原 UI 只有转圈；通用退出码提示又隐藏了网络中断原因。不能将其描述为 CLI 更新命令不兼容，也不能仅凭连接经过代理就断言代理程序自身有缺陷。
- 所有 Agent 的升级共用后端互斥锁，原 UI 却允许同时点击不同 Agent 的升级按钮。后一个请求会报“另一个 Agent 正在升级”。这是 Kimi 首次出现红色图标的可能原因，未取得当次悬浮提示，不能确定其历史错误一定来自互斥锁。
- 红色图标原来统一调用“重新检查版本”，升级失败后点击它仅重新获取最新版本，自然又显示“有新版本 2.1.1”。它没有重试升级。
- Kimi 2.0.2 的 `__update_download VERSION --manual` 与新版本仍兼容。隔离安装中下载和启动应用暂存更新均成功；仅保留桌面进程实际拥有的小写代理变量也通过，未发现大小写代理环境导致此次失败的证据。

## 代码修复

- 升级失败且已有目标版本时，红色按钮改为真正“重试升级”；版本检查失败仍执行“重新检查版本”。后端和前端异常路径均保留可重试状态。
- 一次升级进行中，禁用其他原生升级/重试按钮，并说明需等待当前升级完成。同步引用阻止同一渲染帧的重复调用；保留后端互斥保护。
- 升级显示检查条件、下载安装、重新检测验证阶段和本次界面计时。没有伪造下载百分比。
- 将已知下载中断诊断映射为固定中文提示，区分启动失败、执行超时和非零退出。不会把任意 CLI 输出、账号或凭据传给前端。

## 本机升级结果

- Kimi：原生下载器完成 2.1.1 下载；重新启动入口应用暂存更新，`--version` 返回 2.1.1。
- Claude Code：原生下载在重试耗尽后失败。本次人工恢复使用官方 GCS 同一制品的 Range 断点续传补全诊断过程中留下的文件，核对官方 manifest 中的长度和 SHA-256，并通过 `codesign --verify --strict`。将验证通过的文件放到原版本目录，保留原启动链接，随后再次执行官方 `claude update`，由原生更新器重新校验发布信息并启用，退出 0；启动入口返回 2.1.282。
- 断点续传是本次恢复操作，未在应用中另造一个自动下载器或跳过官方更新器验证；后续网络仍可能中断，界面会明确报错并允许重新升级。
- 未结束用户外部 Kimi 进程，也未发起付费模型对话。隔离测试副本和本次留下的空暂存目录已清理。
