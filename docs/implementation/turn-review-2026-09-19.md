## 冻结材料与归因

- 使用确切 `turn.completed` 的序号上界，以及该轮 `workspace.turn_changes_captured` 的 Artifact；通过任务归属、长度与 SHA-256 校验读取。
- 输入含本轮要求、回复、已保存补丁和可用的文件前后内容，经脱敏后固定并计算输入 SHA-256。禁止回退到当前工作区；不向审查会话注入主任务历史 MCP、附件目录或项目目录。
- 旧轮次缺少快照时，三个检查均不可用。二进制、省略的内容和有界快照都不伪装为完整项目证据。
- 同一项目仍允许多 Agent/多对话同时写入。快照反映轮次期间工作区的变化，可能混入其他写入者，无法仅凭时间段认定独占归属。
- 历史 Diff 校验 Artifact 后呈现冻结补丁或已保存的前后版本；支持多目录同名文件区分、文件导航和原/新行号。点击文件入口会定位对应文件。缺失、校验失败或无法展示的内容明确提示。

## 独立执行和恢复

Core 为审查分配独立 Run，在临时目录创建独立原生 Session，不改 Task 的主 Agent、主 Run 或 SessionMap。Codex 使用只读沙箱、禁止审批，关闭 shell、多 Agent、Web、Apps 与已配置 MCP；无法确认配置或无法安全覆盖工具名称时失败，不降级。Claude Code 禁用内置工具、清空 MCP，关闭设置来源和 hooks，使用 plan 权限。其余 Agent 直接复用已有会话、权限和执行 API，优先选原生只读/计划/询问等普通权限，拒绝继承已知跳过审批的模式；它们不据此宣称具备额外的硬沙箱。ACP、ZCode、Antigravity 为审查创建使用同一安装配置的独立驱动连接，防止主会话的事件流、权限状态和取消互相影响。Core 保留工具/交互尝试即停止的规则。原生运行时的并发限制与具体 CLI 兼容性仍须真实 Agent 验收。

`review.started` 保存请求、来源、输入包和校验值，`review.updated` 保存执行状态及结果。状态包括 queued/running/cancelling/completed/failed/cancelled/interrupted。开始请求带 RunId，可幂等重发；重试创建新 Run 并复用校验过的原输入，不重新采集文件。

取消只中断该审查会话；结束后关闭会话。启动超时 30 秒，分析超时 3 分钟，最多 8 个同时运行的审查，输入包上限 768,000 字节、结果上限 64,000 字节；超限明确失败。审查中出现工具调用或交互请求会停止该审查。后台服务不会因为主任务空闲而退出仍在运行的审查。重启把无法恢复连接的审查标为 interrupted，不自动重放请求。

完成结果显示在来源轮次下，并携带 Run、来源 Turn、执行 Agent、输入 hash 和覆盖范围进入主任务的下一轮上下文，不中断正在执行的主任务。最多附最近 10 项审查；长文本为明确标记省略字节数的摘录，全文仍在当前任务历史中，可通过已有历史查询按需读取。摘录不等于全文交付证明。
