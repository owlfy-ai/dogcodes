# 额度监控手动刷新（2026-09-26）

## 行为

额度监控标题右侧增加“刷新额度”。点击后重新读取安装列表，并发查询各个 Agent，逐项更新读数，显示已完成数量。刷新期间禁用按钮并合并重复调用；自动轮询不会另起请求。若已有自动查询进行中，则待它结束后再发起主动查询。

完成时区分全部成功、部分未取得额度、安装列表读取失败和没有可刷新 Agent。查询超时会结束等待，迟到响应不会覆盖界面。传输失败保留原读数和更新时间；后端明确返回无额度或诊断时按原面板逻辑展示未知，不伪造新读数。

## 链路

- `CoreClient.quotaSnapshots` 增加可选 `force`，经 Tauri、后台服务 RPC、Core 传到 `QuotaProvider.read_quota_with_refresh`。
- Claude、Codex、Kimi/Grok/Cursor、ZCode、Antigravity 的手动查询跳过本地额度 TTL。自动轮询仍使用原缓存策略。
- 原生认证退避、活动会话互斥和不发送模型 Prompt 的约束不变。主动查询失败不会把旧缓存当作刷新成功。
- 此次只增加刷新能力，未新增 CC Switch 或第三方供应商额度接入；不支持的来源仍显示已有诊断。

## 验证

- 前端全量 377 项测试通过，覆盖逐项交付、全 Agent 强制查询、重复点击、与自动查询串行、部分失败、超时后重试、卸载保护，以及页面按钮状态。
- Rust 额度相关测试通过；新增 Codex 缓存绕过测试，扩展 Antigravity 活动会话与缓存测试。真实联网测试仍按原设置忽略。
- 桌面后台服务 RPC 的刷新参数往返测试通过。
- TypeScript / Vite 构建、桌面 Rust 编译检查、严格 Clippy、Rust 格式检查通过；浏览器 Demo 中确认按钮位置、点击后更新时间和部分未取得额度提示。该浏览器检查不等于各家真实账户重新验收。
- 未重启用户生产应用或后台服务；测试预览使用独立端口，结束后停止。
