# 故障会话恢复与 Codex 长日志用量

2026-10-11：参考 codex-host `e61d25c7` 的故障会话恢复和日志读取改进，按本项目的 Driver / Core / Store 边界实现。

## 故障恢复

- Codex 不再把已登记的会话当作存活连接：恢复前检查控制通道与原生进程状态。失效连接清理后，按原生 thread ID 恢复；同一 ID 的恢复串行执行，避免重复启动。`turn/start` 遇到断连后结束失效 actor，下一次恢复不会复用它。恢复后的连接也接回用量观察器。
- Claude 同一原生会话的恢复串行执行，排队后再次检查主轮次、自主续答和后台任务状态。执行中或自主终态尚未被 Core 确认时，保留原进程、审批和会话映射。已关闭的控制通道不能作为健康连接复用；恢复仍验证原生模型与思考强度。
- ACP 在连接清理完成前就能识别已关闭的控制通道。异常 prompt 响应（包括成功 RPC 内的非法 `stopReason`）使原生会话驻留失效，下一次操作重新 load；并发恢复复用已有串行连接。失效会话的待确认配置代次也清除，迟到响应不能重新标记为有效。
- ACP 清理超时或等待被取消后，保留只用于确认旧进程退出的标记。它不持有旧控制通道；后续恢复继续等待，不能在退出未确认时叠加新进程。
- 原生实测暴露并修复 Claude 的 macOS 退出确认问题：组长退出后 `killpg` 可能短暂返回 `EPERM`。现在继续在原有两秒预算内检查，直到 `ESRCH` 确认组消失；持续异常仍失败，不把权限错误当作退出成功。

失败输入不会自动重放。恢复沿用原生身份和原有配置确认规则，不绕过认证错误，也不替换运行中的任务。用户需要重启项目进程才能加载新驱动。

## Codex 长日志

移除整份 rollout 超过 32 MiB 就放弃的限制，改为每个已绑定线程一个增量读取器。仅扫描新增字节，同时读取原生请求事实和 turn 模型，不再为两项数据分别重读全文。

读取使用 64 KiB 缓冲、单行 1 MiB 上限和每次 500 ms 扫描预算。超过上限的单行逐块跳过，不把整段工具输出载入内存；未写完的 JSON 行保留到后续补齐。时间预算耗尽后保存偏移，下次继续，不能承诺任意大小历史在一次查询中读完。

按 `session_meta`、thread / session / turn 身份核验；使用 JSON 解析，不依赖字段顺序。Response ID 去重包括 compacted 副本，晚到的原生 turn 模型可修订已有请求。文件截断、替换或已读边界变化后重置读取状态并重新验证身份。

当前轮次结束时仅补入对应原生 turn 的请求，后续扫描到的旧历史不会算入当前轮次。扫描尚未完成且已有该轮的检查点账本时，暂缓用部分原生请求替换整轮检查点，避免重复计数或提前丢失其他请求。缓存保留最近 10,000 条事实，达到上限后仍接收新轮次；已持久化的历史不因此删除。

日志结果在用量存储锁内合并，保留扫描期间到达的实时用量、上下文、有效生成计时和原生来源。缺失数据仍省略；没有增加统计范围、完整性或说明文字。Codex 原生恢复接口缺少实时响应完成事件时，仍不推算生成速度。

## 验证

确定性回归覆盖：Codex 空闲进程死亡、残留登记、并发恢复、执行中恢复保护；Claude 并发恢复、自主续答失败后的确认与续答、后台审批保护；ACP 非法响应后的 load 去重、失效配置代次、清理标记；超过 40 MiB 的单行工具输出、增量追加、半行、预算续读、文件替换、旧轮次隔离和缓存上限。

原生退出确认另有 opt-in 控制面测试，连续三次创建并关闭 Claude 会话，不发送模型请求。真实短对话验收使用隔离工作区，不读取或修改项目文件；故障及后台活动边界以确定性测试为准，未故意断网或制造供应商重试，Windows 未实测。

- ACP / Claude / Codex / Driver API / Core / Store 库测试共 276 项通过，32 项原有及新增 opt-in 测试默认忽略；Claude 退出确认 opt-in 另行执行通过。
- Codex、Claude 各两轮真实短请求均完成，中间关闭并恢复原生会话。两家账本均从 1 条增至 2 条，每轮一个新请求，重复读取一致且无重复身份；两次最终关闭均确认成功。Claude 当前代理实际模型为 `kimi-for-coding`。Codex 恢复轮通过 rollout 取得准确用量，没有生成时长，保持不显示速度。
- 脱敏结果见 [原生恢复与用量验收](evidence/fault-recovery-2026-10-11/native-acceptance.json)：仅保存状态、Token、时长、模型和去重核对，不保存正文、思考内容、原生 ID 或本地路径。
- 四个修改的 Driver / Driver API crate 的 all-targets 严格 Clippy（`-D warnings`）、新增及修改独立模块的格式检查、`git diff --check` 通过；桌面 debug 二进制及 `live_request_usage` 实测示例构建通过。此次没有修改前端，也未自动重启用户的桌面或后台服务。
