# Cursor 首次初始化定位与检测连接复用

## 分段测量

新增忽略执行的 `local_startup_breakdown` 诊断测试，使用实际驱动的进程启动与代理环境配置，连接本机 Cursor，只创建临时目录中的元数据会话。不发送 prompt、不启动模型轮次、不配置 MCP、不读写项目文件。

```sh
DOGCODES_ACP_BINARY=/path/to/cursor-agent \
  cargo test -p acp-driver local_startup_breakdown -- --ignored --nocapture
```

此诊断入口使用 Cursor 的 `--disable-auto-update acp` 参数，不是通用的其他 Agent 启动命令。默认模型和思考强度均未指定；模型阶段耗时不代表显式切换模型的耗时。

| 阶段 | 单次测量 |
| --- | ---: |
| 启动进程 | 1.03ms |
| initialize 握手 | 354.19ms |
| 同一进程第一次 session/new | 7,854.60ms |
| 第二次 session/new | 3,129.71ms |
| 第三次 session/new | 2,814.71ms |
| 默认模型选择 | 0.06–0.13ms |
| 默认权限选择 | 0.07–0.13ms |

主要耗时位于原生 `session/new` 请求。该测量没有前端渲染和历史 MCP，仍可复现首次请求偏慢。仅凭请求耗时不能进一步区分 Cursor 内部初始化、远端网络和服务端处理；后续请求在同一进程内显著缩短，支持复用已完成检测的进程。

## 改动

原流程完成 `initialize` 和用于验证登录的 `session/new` 后关闭检测进程，注册一个尚未启动的新 driver。第一次正式任务需要再次启动进程并经历首次 `session/new`。

新增 `AcpDriver::connect_ready`：在正常 ACP 连接处理循环中完成协议版本检查和登录检测，成功后保留该连接。桌面只对已经测量的 Cursor 使用此路径，其他 Agent 的检测与进程生命周期不变。

检测会话不写入任务映射，也不成为可复用的任务会话。实际任务继续执行自己的 `session/new`，使用自己的目录和 MCP 配置。只有进程及其内部初始化成果被保留；不同对话没有共用原生任务会话。权限策略不兼容或连接已退出时，沿用既有重建流程。

登录失败、协议不兼容或无有效 session ID 都不能标记就绪。检测请求有 45 秒预算；调用者超时/取消时退出元数据请求，初始化握手也有 45 秒上限，避免失败检测无限占用进程。检测后会保留一个 Cursor 进程，不为各项目额外创建预热会话；服务/驱动生命周期结束时释放连接。

## 验证

ACP 模拟连接覆盖认证失败不能通过检测、成功检测后在同一连接中创建独立任务会话、已取消的检测不再执行，以及正常流式输出和后续会话恢复/复用。ACP 与桌面库默认测试、严格 ACP Clippy 和桌面构建通过。

## 正式链路复测

开发服务空闲时重载新构建，等待 Cursor 检测成功，随后在原 DrillHUD 项目创建第一个新对话。使用与此前相同的只读短回复提示，包含正常历史 MCP；没有工具调用。对话完成后已清理。

| 阶段 | 上一轮冷启动样本 | 本轮保留检测连接后的样本 |
| --- | ---: | ---: |
| 原生会话初始化 | 8,433.96ms | 3,146.83ms |
| 提交 prompt 至首段正文 | 3,383.96ms | 4,400.63ms |
| Core 收到提交至首段正文发布 | 11,888.56ms | 7,566.76ms |

该样本初始化减少约 5.29 秒（63%），首段正文出现时间减少约 4.32 秒（36%）。服务端响应存在波动，不能把单次结果当作所有任务的保证。剩余约 3.15 秒发生在原生会话创建，约 4.40 秒发生在 prompt 提交后的 Agent 响应；未把它们归因于前端渲染。

这是复用已经发生的安装检测，不是省略认证检测或另增每项目预热。若用户在检测尚未结束时立即执行、切换到不兼容的权限策略，或原生进程退出，仍需要等待检测/重新初始化。

最终验证：ACP 33 项默认测试通过（16 项本机测试按默认忽略），桌面库 82 项通过（4 项忽略）；手动运行元数据分段诊断通过；ACP 所有目标严格 Clippy 与桌面构建通过。新构建已载入开发服务。
