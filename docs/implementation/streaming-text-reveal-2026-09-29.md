# 流式正文平滑显示

之前的 16ms 合并窗口只减少 React 更新次数。上游一次推送多个字时，页面仍整批显示，因此视觉上有跳字感。

新增 `useSmoothText` 和 `StreamingMarkdownMessage`，用于普通正文以及 activity message。数据接收、落库和事件游标保持即时处理，仅正文展示维护待显示队列：

- 使用 requestAnimationFrame，按实际时间逐步显示已收到的文字；常规速度为每个字素 12ms，在 60Hz 屏幕上通常每帧显示 1–2 个字素。
- 积压时压缩队列的计划播放时间至最多 160ms；这不是额外固定等待时间，也不保证繁忙主线程下的实际绘制延迟。
- 按 Unicode 字素分段，追加时只重新分段末尾字素及新增文本。
- 首次挂载的正文直接展示，避免切回会话时重播历史；之后的追加内容平滑展示。
- 完成、停止、非追加修正、页面可见性变化时立即补齐；遵循系统减少动态效果设置。
- 没有积压时不请求动画帧，卸载时取消待执行帧。

Markdown 继续使用已有稳定块缓存；未完成语法仍可能随内容补齐发生排版变化。此改动改善批次到达的视觉节奏，不提高模型生成速度，也不能填补尚未收到文字时的长停顿。

验证覆盖逐帧释放、大批积压追赶、连续追加、emoji 和组合字符、历史首次显示、结束补齐、修正、后台切换、减少动态效果、卸载清理、最终 Markdown 以及 App 事件流中的无额外回读。

验证结果：平滑显示测试 7 项、App 流式集成测试 5 项均通过；TypeScript 检查和生产构建通过。前端全量 490 项中 486 项通过。其余 4 项涉及会话永久删除、草稿项目选择、审查执行结果及额度 HTML 断言；在临时副本中关闭本次平滑展示后，同样 4 项仍失败。未进行原生窗口的实际帧率测量或视觉验收。
