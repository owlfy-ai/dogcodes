# 会话删除与恢复（2026-09-25）

> 本页为旧版可恢复删除的历史记录。当前行为已被 [2026-09-27 永久删除方案](conversation-permanent-deletion-2026-09-27.md) 替代。

已实现可恢复的会话删除。普通、置顶及已归档会话复用侧栏操作区，新增删除按钮；确认弹窗解释保留范围。删除后进入侧栏「最近删除」，可恢复原位置，不自动清空。项目代码及 Agent 原生会话不删除，完整会话导出仍暂缓。

## 行为

- 删除当前会话优先切换到同项目的其他会话，再选择其他项目的会话；全部删除后显示可继续新建的草稿。其他窗口收到删除事件后执行同样切换，导航后退不再进入已删除会话。
- 消息、附件引用、审查报告、历史 Diff、原生会话关联保持在本地存储，恢复后继续使用。原置顶/归档设置保留，恢复已归档会话仍回到已归档列表。
- 主任务尚未终结或审查处于排队、执行、取消中时，删除按钮禁用；确认弹窗打开后状态变化也会禁用确认。后端独立检查，不能通过旧窗口绕过。
- 最近删除只提供恢复。本次没有永久删除、自动过期、磁盘空间回收、删除项目或删除原生 Agent 历史。

## 实现

Protocol 新增 `DeleteTask` / `RestoreTask` 和默认空的 `BootstrapSnapshot.deletedTasks`。两项命令要求当前会话流版本，沿用命令幂等机制。

Store 将 `task.deleted` / `task.restored` 保存为规范事件，按最新生命周期事件生成删除状态，无需删除业务记录或升级表结构；投影重建保持相同语义。Bootstrap 的普通会话、项目计数、可用 SessionMap、灵动岛卡片和完成提示排除已删除会话。Core 的时间线、历史查询、审查及常规会话操作不能访问已删除会话。

删除与审查启动共用现有审查准入锁，覆盖首次审查事件之前的材料准备。Store 在追加事件的同一事务中再次检查主任务和每个审查的最新状态；`review.started` 与 `review.updated` 均纳入判断。删除后禁止普通任务事件追加，只允许版本正确的恢复事件，防止并发提交或延迟回调重新激活会话。同项目不同会话继续可并发运行，没有增加项目级单写者约束。

前端沿用侧栏按钮、归档列表与已有确认对话框样式；删除时清除该会话的界面缓存。浏览器 Demo 提供相同行为用于交互测试；Demo 数据本身仍仅在内存中，持久化保证来自桌面 Store。

- Core/Store 全量 110 项测试通过，随后新增冻结来源恢复集成测试通过（总计 111 项）。覆盖删除/恢复版本校验及幂等、排队/运行/取消审查和主任务门禁、删除后迟到提交拒绝、数据库重新打开、投影重建、会话关联/消息/报告保留。冻结材料恢复后逐字段相同，重试仍使用原输入哈希，不读取后来的工作区替代历史。
