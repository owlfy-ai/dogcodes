# 审查流式输出

日期：2026-09-27。

## 用户行为

逐轮审查、项目 Diff 审查和修复后的复审均实时展示 Agent 回复与工具状态，复用主对话的 `ActivityRow`、`MarkdownMessage`，不新增另一套消息/工具 UI。

问题列表与修复操作显示在“审查执行过程”前。审查中回复实时展开；执行成功后，Agent 最终回复和总结一并折叠在“审查执行过程”中，非结构化回复与只有最终结果的旧记录也采用同样方式。流式记录已包含最终回复时不重复展示。失败、取消、额度耗尽或中断时保留已收到的回复与工具输出；未收到终态的工具显示“结果未确认”，不误报成功。服务重启仍可查看已落盘内容。

审查问题详情默认收起，点击严重程度与标题展开/收起；文件位置随详情收起，只显示文件名与行号，悬停可查看完整路径；修复选择框不会触发展开。点击文件位置在下方 Diff 打开并滚动到对应文件，保持当前目录/比较模式/提交/分支，按仓库与完整路径匹配同名文件；不在当前比较范围时提示未找到，不猜测其他文件。逐轮审查复用现有的工作区 Diff 打开入口。不再单独展示“Agent 原始回复”入口及“Agent 报告的位置；工作区后续修改可能使行号变化”说明。

界面不显示“此结果对应此前发起的比较范围，不代表当前 Diff 已通过审查”说明；结果来源和按原范围重试的关联仍保留。

工具调用在执行过程中再收纳到默认折叠的工作摘要。主对话与审查共同使用 `TurnProcess`（沿用原主对话样式与懒加载行为）：进行中显示“正在工作 X 分 X 秒”，结束后显示“已工作 X 分 X 秒”；回复留在工具折叠区外实时展示。展开后复用既有工具状态及输出组件，取消或失败仍可查看已收到的内容。

审查工具项同时复用主对话的 `conversation-entry` 外层布局，保证左对齐、占满可用宽度及相同间距。审查卡片标题样式只作用于自身直接子级，避免覆盖内部工作摘要的图标、标题和工具行。

现有图标、Agent 选择、额度缓存、完全权限加提示词只审查的规则保持不变。

## 实现

- Core 在可取消 future 外持有输出，所有退出路径刷新尾部内容。只有正常完成才解析报告；优先使用最后一条原生回复解析结构化结论，进度文字保留在执行记录中。
- `ReviewRun.activities/activityRevision` 采用默认值，旧记录可读。`review.activity` 约每 250ms 保存一次变动展示项，而非每个 token 保存整份审查；终态 `review.updated` 保存最终记录。展示正文落盘前脱敏。
- 活动按独立 runId/revision 投影，按 itemId 合并快照与文本增量；原生 sourceEventId 去重，优先原生展示字段，不把延迟工具状态倒退为执行中。镜像文本只展示一次。
- 前端每个 CoreClient 共享订阅，按全局 sequence 去重、补齐缺口、断线续订；保留既有持久记录轮询。审查活动不混进主对话消息/工具序列。
- 子会话正文不混入主审查结论；委派活动只显示状态，不跳往主对话的子会话入口。
- 不产生源码基线副本，不恢复已移除的分组、冻结上下文检索或独立二次复核。

## 审查与 Diff 高度调整

存在项目审查记录时，审查区与文件区之间的横线支持上下拖动，两个区域各自滚动；没有记录时文件区补满空间。本地记住调整比例，并在窗口尺寸变化时限制上下区域的最小可用高度。双击分隔条恢复默认比例，键盘上下方向键微调，Home/End 调到边界。侧栏与独立 Diff 窗口复用同一实现。

隔离 Chromium 验证拖动 130px 后，上方高度从 356px 增至 486px，下方从 435px 减至 305px；审查内容、文件列表、Diff 均可独立滚动。收起/展开、双击复位、键盘边界及缩小窗口检查通过。项目审查与 Diff 面板现有 38 项测试通过。

审查滚动条贴近面板右边缘，实际占用的宽度从右侧留白扣除，保持滚动条出现前后的正文宽度与换行一致；悬浮滚动条无需补偿。Chromium 验证正文均为 356px，10px 滚动条对应右侧留白从 14px 减至 4px，标题高度不变；恢复后留白复原，无 ResizeObserver 错误。

## 多次审查记录切换

项目 Diff 面板只展示一份选中的报告，移除“审查结果”总折叠和每次审查的外层折叠。通过复用既有浮层与菜单样式的下拉菜单切换历史，按时间从新到旧显示类型、Agent、时间、状态和结构化报告的问题数量。菜单自动避让边界并滚动，支持键盘选择、Escape 和点击外部关闭。

首次读取默认选最新记录，主动发起或重试后选中新记录；后台更新不切走正在查看的历史记录，另有审查执行时显示数量。日期及取消/重试操作固定在选择器下，只作用于当前记录。各报告保留独立的展开、修复勾选与滚动状态，正文仍先显示问题、后显示执行过程。分隔条及滚动条宽度补偿保留。

相关前端测试共 40 项通过，覆盖默认排序、独立取消/重试、后台完成不抢占、历史展开与滚动恢复；隔离 Chromium 以 12 条记录验证单份展示、菜单边界和滚动恢复。

## 审查文案清理

- 删除修复按钮下的机制说明、逐轮审查时间悬浮中的来源序号/材料哈希；问题数量统一为“X 项问题”。
- 旧报告隐藏上下文请求次数、冻结检索 JSON 和分组原始输出；代码引用以“代码证据”展示。简化覆盖与安全检查标签，去掉通用范围/校验声明。
- 已保存的几条固定长声明在展示时隐藏或简化为未完成状态，不修改历史数据；保留具体失败、缺失依据、未完成状态与代码证据。
- 新审查提示词要求简洁结论，不复述权限、快照和编排机制，不添加通用范围声明；无法读取或检查受阻时说明具体原因，不将静态分析声称为实测验证。
