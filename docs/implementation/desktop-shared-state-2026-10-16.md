## 2. Agent 设置的实际实现

- Rust/TypeScript 协议定义 `AgentPreferences` 和快照 `{revision, lastSequence, preferences}`。`revision=0` 表示后台尚未保存；它是有效的并发条件，不能转换成“不校验版本”。
- `SetAgentPreferences` 使用现有 `CommandEnvelope`、幂等 Ack 和追加事务，写入 `preferences.agents.updated`。只允许可信本机用户上下文，要求版本，限制标识格式、数量并拒绝重复。不新增数据库 schema 或旧库迁移。
- SQLite 在同一读事务内读取全局事件头与设置流最新版本，保证“快照后订阅”不丢变更。流版本用于 CAS，全局事件序号用于续传；两者不混用。投影重建不改变设置事件。
- daemon 增加 `agent_preferences` 查询；桌面通过 `core_agent_preferences` 读取，变更继续走 `core_execute`。主窗口与独立审查窗口都接入同一设置门控。
- UI 使用后台快照与事件作为事实源。保存期间不乐观显示成功；同一窗口只保留一个未确认变更。回执丢失后读取后台当前版本；仍无法核实时，重试保留相同操作 ID、版本和载荷，不静默生成新操作覆盖他端变更。
- 收到旧事件按序号去重，发现事件缺口或订阅失败后重读快照并重新订阅。停止或替换连接后忽略旧连接返回。较晚到达的 Ack 不得覆盖另一个窗口的新版本。
- 首次读取发现后台未初始化、当前端存在旧偏好时，让用户选择保留旧设置或使用默认设置；两种选择都用版本 0 保存，保留原本地副本。另一窗口先保存时采用后台值，不自动合并或覆盖。后续启动直接使用后台值。损坏的旧设置在发命令前拒绝，仍可选择默认设置，不进入结果未知的重试循环。
- 普通浏览器演示及嵌入测试保留本地模式；原生桌面使用共享门控。未确认保存期间禁止管理页再切换或拖拽设置，错误显示可操作的“重新核实”入口。

## 4. 历史列表组织的实施

- 新增 `HistoryPreferences` / `HistoryPreferencesSnapshot`，区分任务的 `pinned/archived`、项目的 `pinned/removed`、分组排序与手动顺序。协议明确拒绝 `collapsed` 等额外字段及无效状态，不将视觉布局装进共享业务数据。
- `SetHistoryPreferences` 写入独立的 `preferences.history` System 流，要求本机用户和预期版本，复用原命令幂等 Ack 与事务。它与 Agent 设置拥有不同流版本；修改 Agent 设置不会造成历史设置版本冲突，但两个快照都带真实全局事件游标。
- SQLite 共用 `shared_preferences.rs` 原子快照读取；store 显式声明已有工作区版本的 serde 依赖，不增加新版本或数据库表/迁移。daemon 和 Tauri 新增查询；变更仍走 Core 命令。
- 从 Agent 设置控制器抽取类型化 `SharedPreferences<T>`，统一快照、事件缺口、迟到响应、CAS 冲突、未确认操作与原 ID 重试。两个业务域只提供各自类型、默认值、导入条件和验证规则。
- 主窗口通过 `SharedHistoryPreferencesGate` 读取/导入；独立审查窗口没有历史列表，不增加无用的历史订阅。`ConversationHistory` 根据后台快照重绘，归档失败不提前隐藏会话，未确认期间禁用置顶/归档/排序/项目列表变更，同时保留折叠、打开会话等非变更操作。错误和核实按钮在列表内展示，避免与 Agent 设置提示互相遮挡。
- 原混合 localStorage 设置只读保留；折叠另存 `dogcodes.history.collapsed.v1`，排序与手动顺序由后台保存。仅有折叠偏好时不要求导入业务设置。选择默认业务设置也不抹掉端内布局。
- 在当前可访问的 WebView 存储中，当前 `dogcodes.*` 键缺失时，允许显式导入改名前对应的 `codesheepdog.*` Agent/历史偏好；当前值即使为空也优先，旧键不覆盖、不删除。此机制不等于迁移旧应用数据目录或旧数据库。
- 当前保存的是有界的完整业务快照：任务/项目/顺序域上限与总载荷均校验；不自动合并并发冲突。长历史下的事件增长与查询/订阅成本仍属于发布候选性能验收，不能只凭小样本功能用例判定通过。

本轮集中验证：类型检查通过；8 个相关前端文件 69 项通过，覆盖原有列表交互、导入、两客户端一致、冲突、同 ID 重试、项目移除/恢复、排序及端内折叠。之后新增改名前存储键读取保障，针对两个受影响文件复验 16 项通过，本工作块累计覆盖 71 个不同前端用例。原生首次检查暴露 store 未显式声明 serde 依赖，已修正并更新锁文件，原范围复验最终通过：7 项 SQLite 测试、2 项 daemon RPC 测试；包含两个共享状态域的回归。日志在 `/tmp/dogcodes-history-settings-*.log`；未打包。
