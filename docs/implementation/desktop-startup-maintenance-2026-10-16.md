# 后台启动维护与服务就绪时序

日期：2026-10-16。对应 DT-08/09。承接发送恢复的[故障隔离](desktop-submission-isolation-2026-10-16.md)与[状态订阅](desktop-submission-watch-2026-10-16.md)。

## 发现的问题

原流程先发布 endpoint 并记录 ready，再同步等待发送恢复记录清理，最后进入连接接收循环。目录记录较多或存储较慢时，客户端已能发现服务地址，却不能及时获得响应。初始 Agent 扫描虽然已经在后台，但没有纳入空闲退出判断，可能在尚未完成准备时被判为空闲。

## 改造

- 数据库打开、Core 中断状态恢复、后台业务宿主初始化仍在发布服务地址前完成。这些必要状态恢复没有移到可并发接收业务请求的阶段。
- Agent 初始扫描与发送记录删除清理作为服务持有的启动维护任务运行。ready 日志和启动计时结束后，立即进入实际接收循环，不再等待发送清理完成。清理具有独立阶段计时，失败继续记录 `submission_cleanup_incomplete`，不会伪装成功。
- 启动任务在被调度前就增加活动计数；完成、返回错误、panic 或取消时通过 RAII 释放计数。空闲退出除核对现有 Agent/终端/项目运行状态外，也检查启动维护任务，防止准备阶段提前退出。用户窗口不持有或取消这些任务。
- 更新应用时，旧后台暂不能退出的提示改为“后台仍在准备或执行任务”，覆盖没有活动会话但正在维护的情况。
- RPC 测试夹具改为使用生产环境同一个接收循环，覆盖连接上限与真正的退出信号处理，不再用测试专属无限接收循环替代。

没有数据库迁移、命令协议变化或签名配置修改。启动维护任务不是持久任务队列；进程重启后重新核实存储，不能自动重发旧消息。

## 验证

一次原生验证 **65 项通过**：`cargo test -p desktop --lib -- daemon::tests daemon::startup submission_intents state_changes`。日志 `/tmp/dogcodes-startup-maintenance-native.log` 已收取 exit 0。

新增测试以受控等待模拟尚未完成的维护，实际通过本机 TCP RPC 确认 ping/bootstrap 可响应、空闲退出被拒绝；放行后执行真实文件记录清理，验证永久删除的紧凑结果及变更通知，随后允许退出。坏文件造成清理失败时，原文保留、活动计数释放，服务可正常退役。任务计数另覆盖首次调度前、错误、取消及 panic 退出。

共享接收循环的既有测试一并通过，含回执丢失、命令身份、审批查询、终端连接/停止、项目运行、文件监听、Diff 写入/租约及宿主进程锁。最后只调整代码格式和退出提示文案，未重复运行同一批检查。未调用真实模型、未运行前端测试或打包。

## 尚未覆盖

发送记录清理仍按该业务域的 gate 串行处理，因此其自身的登记/发现请求可能等待清理；本轮确保其他服务查询不再被整个接收循环阻塞，不代表长目录扫描成本已解决。后台业务宿主初始化开销、长记录性能、三平台真实冷启动/关闭/重启及安装包验收继续核对。接收循环异常退出时的全部在途任务回收也需纳入进程级验收，不能用本轮受控 RPC 测试替代。
