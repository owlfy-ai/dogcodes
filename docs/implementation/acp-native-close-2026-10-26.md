## 行为

仅当本次 initialize 的类型化 SessionCapabilities 声明 close 时，才调用 SDK v1 的 session/close。未声明的第三方 Agent 继续使用本地会话退休与最后所有者的进程作用域清理；这是第三方能力差异，不是本项目旧版兼容。

- Resident 固定记录本次连接的能力、物理退出代次与原任务；关闭固定原连接，只创建一个原生请求与共享回执。调用方取消等待、失败、超时或重试都不另发请求。
- 原生关闭在独立 SDK 后台任务中运行，不堵住其它会话的 prompt/cancel。关闭闲置 A 时，已有 B 可以继续工作；关闭活动 A 时，新任务需等 A 的真实结束。任何退休尚未结束都不准 new/load 重用原生 ID。
- ACK 证明会话工作已取消。即使 Agent 不再回复旧 prompt，也会终止其等待，等待本地原任务完成，再清理该会话缓存与路由。清理 latest_turn 只按原 Turn 对象身份匹配，不清除活动 B 的所有权。
- CodeBuddy 因这个原生关闭发生的取消不会把同连接的其它正常会话标记为必须重建。原生关闭未确认时仍保留活动任务的准入限制。
- 共享连接关闭报错或回复格式不正确时，回执报告失败但所有权不丢失。超时后继续等待同一请求的迟到 ACK；不强杀其它仍拥有连接的会话。最后一个所有者离开时，物理退出证明也能结束此前未知的关闭。
- 最后一个所有者先尝试原生关闭；宽限最多三秒（测试可缩短），之后关闭原进程作用域。只有原进程、SDK/后台任务退出且原本地 prompt 已收尾，才完成关闭。没有读取或操作实际用户进程、桌面输入或剪贴板。

## 本地验证

新增八项独立时序回归，使用临时 Python ACP fixture，覆盖：共享闲置关闭/明确重新加载；Cursor 与 CodeBuddy 的关闭 ACK 而无 prompt 回复；取消等待、禁止 new/load、另一个会话取消仍响应；原生拒绝/非法回复/超时保持同一所有权；活动关闭超时后迟到 ACK；最后所有者强退；闲置会话已有历史轮次但不能结束活动 B；强退活动任务后本地状态完成收尾才能建立新物理连接。另核实未声明能力时不会发原生关闭。

- macOS/Linux：ACP **117 项通过、21 项需真实环境的单元测试跳过**；另有六项需显式环境的集成测试跳过。两端 all-targets 严格 Clippy 通过。
- macOS：Core **92 项**、desktop **339 项**通过（desktop 七项需显式环境的测试跳过）；严格检查通过。
- Windows GNU：all-targets 严格静态检查通过；未据此声称 Windows 实机运行通过。
- 三个独立私有源码副本分别移除“调用声明的原生关闭”、“ACK 结束旧 prompt 等待”或“拒绝后保留未知状态”，均在对应测试断言失败；恢复后完整 117 项与严格检查通过。没有修改工作区代码来运行反例，也未运行安装的 Agent 或模型轮次。

证据日志 /tmp/dogcodes-acp-native-close-{final,final-linux,final-dependent,proof,proof-restored}.log；反例哈希与结果 /tmp/dogcodes-acp-native-close-witnesses.json、/tmp/dogcodes-acp-native-close-witness-results.json。临时文件不随仓库发布。
