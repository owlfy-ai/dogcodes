# 手机终端输入通道（2026-10-22）

## 范围与协议

新手机输入使用 `terminal_input`，PC 能力位 `terminalInputStreams: true`。inspect 只读；open 保留/切换输入通道，write 发送一个有序输入批次。以下数字均为十进制字符串，不通过 JS number 传递 u64：

```json
{"type":"inspect","terminalId":"UUID","expectedEpoch":"UUID"}
{"type":"open","terminalId":"UUID","expectedEpoch":"UUID","expectedRevision":"0","streamId":"UUID","acknowledgeUncertain":false}
{"type":"write","terminalId":"UUID","expectedEpoch":"UUID","revision":"1","streamId":"UUID","sequence":"1","data":"Base64"}
```

手机每次打开输入通道使用新 streamId，CAS 校验原 revision。回执携带 terminalId/epoch/revision/streamId/sequence、owned、state、uncertain、SHA-256 digest 与已写字节数。单批最多 16 KiB 原始字节，手机在途及排队合计最多 64 KiB。此处是输入批次/内存界限，不是连接累计流量上限。

输入元数据、字节队列和指纹只在内存中，不为键盘内容创建持久重放日志。后台重启后旧终端 epoch 不能写入；已恢复为 Unknown 的旧终端不按旧 PID 重新连接或重放。

## PC 排序和旧通道失效

- 网关以认证 PairedDevice actor 作为 owner，不接受客户端提供 owner。WSS/WebRTC 的同一认证手机身份一致，本地服务使用独立 owner。write 必须匹配 epoch、当前 owner、streamId 和 revision。
- 每个通道一次只接受一个新序号，必须等上一批完成。相同序号与相同指纹仅返回已有状态，绝不再次写 PTY；相同序号换内容、跳号、旧版本、旧通道均拒绝。
- 写入前保存 writing/序号/指纹到运行时状态。原生写入在 PTY 的输入锁内进行；每次部分写入之间检查通道有效性与终端状态。失败不补发原内容，部分写入记为 uncertain。
- open 先使旧通道的原子有效标志失效。旧的在途部分写入结束、PTY 输入锁排空后，新通道才可能 ready；排队旧写入即使稍后获得锁，也先检查无效标志，不再写字节。
- 原写入状态未知时保留 uncertain，普通 open 得到 blocked；只有明确检查后 acknowledgeUncertain 的新 open 才能继续。它不补发任何字节。
- 每个终端最多一个切换任务，连续 CAS 更新合并成最新目标，避免阻塞 Windows 写入时堆积等待线程。open 最多等两秒后返回 opening，迟到任务只激活最新保留的通道；不会把超时当作切换成功。获得输入锁后，Unix 非阻塞写循环的重试上限为五秒；Windows 正在 OS 内阻塞的调用在实际返回前仍不能宣称排空。

远程旧 `terminal_write` 已从允许列表移除；本地桌面既有终端接口保留。手机缺少新能力时明确要求更新 PC，保持只读输出，不退回不带输入通道的远程写入。

## 手机行为

单通道串行发送。丢失回覆后最多只读核实原标识/序号/指纹，匹配 applied 才可认定已写入。结果仍未知则暂停并丢弃未发送队列，不自动重发；输出读取成功不能掩盖输入未知状态。

“核实输入结果”只读；“继续输入”要求用户先检查终端，明确确认清空当前输入框后，创建新通道。二者都不重发原命令。这是输入结果恢复，不是重启/恢复终端进程。

整行输入在确认后才清空；同一行等待期间不能重复点击发送。用户等待时编辑出的新文字不因旧行的回覆或核实而被清掉。离开页面后停止后续准备和未发送队列，不在已释放的页面更新状态。只查看输出不会为了终端状态查询应答主动抢占输入通道；已有输入通道内的控制应答仍按序发送。

## 本地证据与边界

- PC 五项输入用例：顺序和指纹去重、owner/epoch/revision（包括重复使用 streamId）、部分旧写入被切断和显式确认、长度/未知字段、输入锁阻塞时连续二十次切换合并且最后保留版本生效。
- 实际加密 Noise/WSS 与 WebRTC 网关，在临时 PTY 中验证同一 owner、跨连接 inspect/open/write、新通道启用后拒绝旧 WSS 输入；输入仅为无换行的测试文字，未运行用户命令。另有隔离网关自建 PTY 的 echo 测试。
- 手机九项协议测试与五项页面测试：串行、丢失回覆只读证明、未知队列丢弃、显式继续/核实、错误身份、释放期间准备或回覆、旧 PC、长度、重复整行、保留新草稿、输出刷新不清除错误、只读展示不抢输入。
- 本轮完整 PC 库 328 项通过/7 项按需跳过，手机完整 368 项（含原生身份/加密 FFI）通过。静态检查及 macOS 严格 Clippy 通过；普通 iOS 模拟器与 Android ARM64 构建通过；Linux 终端模块 31 项、远程工作区 13 项通过，切换任务合并改动后又通过输入 5 项和加密网关 1 项及严格 Clippy。

本地桌面已有单写入队列/失败丢弃，但仍使用原始本地 terminal_write；跨桌面窗口的输入代次隔离尚未接入新协议，不能把本轮远程输入完成泛化为所有本地输入竞争已解决。Windows 真机、真实公网/弱网、系统强制退出后的原生资源清理、此前远控视频跨模式迁移/通知与部署等仍按完整计划保留。


## 桌面接入后续更新

桌面现已接入相同输入协议，生产原始写入入口已移除；主窗口、审查窗口和手机共享输入版本。未知输入与输出自动重连分开，保留只读核实与明确继续，详情及最新证据见 [桌面终端输入代次与恢复](desktop-terminal-input-2026-10-22.md)。此前记录的桌面输入缺口由该更新补齐，其它未完成范围仍保留。
