# 项目文件查询与监听共享服务

日期：2026-10-16。对应 DT-08/09/10 的文件浏览域。此记录不代表 Diff 快照/Git 操作已迁移或三平台已验收。

## 服务边界

- `workspace_service.rs` 承接根目录、目录列表、文件预览和搜索；四个查询经过 CoreClient/daemon，embedded 验收入口使用同一实现。任务归属、当前项目目录和路径约束在服务内校验，读取与搜索放入阻塞线程池。
- Tauri `workspace_browser.rs` 保留当前窗口可访问会话的检查与转发。原先的隐藏文件、噪声过滤、通配符、搜索上限、文本/图片预览大小与路径边界继续复用；没有把读取操作变成持久业务命令。
- `workspace_snapshots` 等既有 Core API 保持原路由。新查询按方法精确分派，避免前缀匹配拦截既有功能。

## 订阅与恢复

- `WatchService` 在后台建立 OS watcher；每条经过认证的连接拥有一个订阅，连接关闭自动释放。系统监听器不再存储在窗口标签映射内，也没有需要持久化/恢复的文件事件队列。
- 服务最多持有 64 个目录订阅，为其他 RPC 留出连接额度；超限有明确反馈。原生监听器启动超过 2 秒或启动失败时，切换为每秒检查当前目录的 PollWatcher，不递归扫描项目、不跟随符号链接。定时检查失败仍报告错误，不把未同步状态标为正常。
- 原生监听器创建和销毁在独立线程完成，避免 FSEvents 注册/退出阻塞 Tokio。迟到的初始化结果不接管已启用的降级订阅；取消句柄已关闭后立即释放原生监听器。系统调用本身不能强行中断，因此原生任务限 8 个，全部监听工作线程限 72 个（均包含尚未完成初始化/释放的任务）；反复重连不能无界累积线程。
- 事件合并使用有界状态，200 ms 静默窗口、最多 1 秒合并期，持续编辑也不会无限推迟刷新；OS 错误保留至订阅报错结束。
- 15 秒心跳用于发现失效转发端，并重新核对当前项目目录和解析后的目标；目标变化发送 `scope_changed`。客户端等待帧超过 45 秒视为断线，写入阻塞也有界。心跳不触发目录重读。
- 桌面只登记转发任务的取消句柄。开始建立服务订阅前先登记，关闭目录/窗口可取消尚未完成的连接；每次注册有独立 epoch，旧任务退出不会删除同键新任务。通道发送失败、服务断连或主动取消都会释放转发和连接。
- 前端每次连接使用新订阅 ID，断开按 1/2/4/8/15 秒退避重连；隐藏/折叠/卸载取消重连。迟到的旧事件与响应不更新当前界面。建立监听成功后再读取目录快照，每次重连都重读；不假定断线期间没有变化。
- 项目目录变化时刷新根目录并清除旧文件选择。订阅失败仍尝试读取目录，保留可见的自动刷新错误，不伪装为持续同步。

## 剩余边界

- Diff `ReviewHost` 的快照缓存、租约、SnapshotOwner 及关联文件/Git 操作已在后续同日迁入后台，证据见[Diff 服务记录](desktop-review-service-2026-10-16.md)；不以本记录的只读文件浏览验证代替该工作块或完整副作用可靠性验收。
- Windows/Linux/macOS 的真实窗口关闭、GUI 进程退出、服务重启、OS 文件监听及大目录表现仍需候选实机验证；64 个监听及心跳核对的开销需要测量。
- 文件系统在检查与打开之间仍可能被其他进程改变，本次保留现有路径防越界规则；没有承诺对恶意并发替换的原子文件系统沙箱。
