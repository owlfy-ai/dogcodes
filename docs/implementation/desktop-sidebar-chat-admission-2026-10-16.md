# 侧边问答遵守后台 Agent 启用设置

对应 DT-09/DT-10，接续[问答生命周期](desktop-sidebar-chat-lifecycle-2026-10-16.md)。本工作块处理共享设置在独立问答 API 上的遗漏，其他执行入口仍需逐项核对。

## 问题与行为

此前 `chat_executors` 仅按驱动是否支持只读问答筛选，`start_sidebar_chat` 也没有读取后台 Agent 偏好。即使界面隐藏已禁用的 Agent，旧窗口或直接调用 daemon 的客户端仍能发起新问答。

现在候选列表和新问答受理都读取同一后台设置，按 provider 排除已禁用的 Agent。读取设置失败时返回错误，不把它当作空禁用列表。Core 的候选列表改为可失败的结果，Local 适配和 daemon RPC 均传播错误；成功返回的 JSON 结构保持原有数组。

Core 内的读写门禁将设置写入与问答受理串行化：设置更新持有写侧直到持久化及发布完成；新问答持有读侧直到原请求保存和独立工作任务启动完成。已完成的禁用设置不会被问答先前读取的旧设置绕过。门禁不覆盖整个回答生命周期，禁用操作不会因此等待回答结束。

原请求回执查询优先于新任务准入。相同请求 ID、相同载荷的重放仍返回原记录；相同 ID 改正文或 Agent 仍被拒绝。禁用后可以查看状态、查询回执、停止已受理问答及清空结束后的历史，不自动中断已受理任务，也不自动补发禁用期间遭拒的新请求。重新启用后才可再次受理新问答。

## 验证

一次集中执行 `cargo test -p agent-core -p desktop --lib --locked sidebar_chat`：**13 项 Core + 4 项桌面原生测试全部通过**。进程 77743 已 exit 0，日志 `/tmp/dogcodes-sidebar-admission-native.log`。`git diff --check` 通过；测试后仅调整新增代码排版和文档，未重复编译。

新增用例覆盖：

- Core 的确定性并发顺序：设置禁用已排队、随后新问答到达，释放前序读锁后必须先完成禁用，新问答不能留下受理回执或启动驱动。
- 真实 loopback RPC 与 SQLite：两客户端依次禁用、尝试启动、启用并启动、再次禁用；验证候选列表同步、新请求拒绝、原回执和重放保留、载荷冲突拒绝、已受理任务不被自动取消、显式取消及清空正常，清空后仍能恢复原回执且只启动一次驱动。

使用受控测试驱动，不访问真实 Agent 服务。没有新增协议命令、数据库迁移或第三方依赖，没有前端变更、打包或签名配置变更。
