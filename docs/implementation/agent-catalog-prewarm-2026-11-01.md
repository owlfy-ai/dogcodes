# Agent 列表启动预热与缓存（2026-11-01）

## 行为

- 每个真实 Agent 就绪并注册到 Core 后，后台预热模型、思考强度和权限列表。前端不需要先选中该 Agent。
- ACP 的 session/new 和 Claude Code 的 initialize 已返回的列表直接写入缓存，不再为同一份数据创建探测会话。Codex、Pi 等缺少的列表通过已有驱动后台补齐。
- 缓存按 Agent 安装身份保存，和任务、项目、工作目录无关。列表查询不解析项目路径，原生元数据进程使用临时目录。各任务保存的模型、思考强度、权限选择保持独立。
- 成功结果没有时间过期机制；切换任务、菜单、窗口焦点及定时检查均不会重新获取原生成功列表。Core 持有共享缓存，窗口有自己的显示缓存。
- 用户手动刷新或替换驱动时更新缓存。刷新期间继续显示原有列表，失败保留上一次成功结果。Core revision 让其他窗口同步更新；revision 检查本身不会调用 Agent。

## 思考强度

一次返回全部模型思考选项的 Agent，后续切换模型也直接使用缓存。部分原生协议（例如 Pi）只报告当前模型的思考选项：启动时先缓存默认模型和完整模型名单，再在后台逐个补齐其余模型的思考选项，合并到同一份 Agent 缓存。如果用户在后台补齐完成前就选中该模型，会共用并优先处理这次查询。已经补齐的模型，包括确实没有思考选项的模型，不会重复探测；不会按工作目录复制缓存。

因此预热完成后的常用选择无需原生请求；启动尚未完成、后台尚未补齐原生未提供的思考选项、手动刷新时仍可能等待。

## 失败与并发

- 同一查询合并等待者；原生元数据查询并发最多 2 个，当前选中的查询可优先于尚未开始的后台任务。
- 单次原生读取最多等待 30 秒，失败后间隔 1.5 秒、4 秒重试。持续失败冷却 30 秒，启动预热继续在后台恢复，成功结果不参与周期刷新。
- 驱动替换和窗口缓存失效后，迟到的旧结果不会覆盖新缓存。
- 运行中 Cursor 的当前权限仍从当前 run 叠加到返回值，缓存只共享可用模式列表，不把另一个任务的实际策略当作当前策略。

## 验证

前端覆盖跨任务共享、启动预热、失败恢复、并发优先级、显式刷新、迟到结果、版本变更、权限选择和模型切换。Core 覆盖成功不失效、失败保留旧值、启动响应复用、模型思考选项合并、请求合并、后台恢复和驱动替换。驱动测试使用独立 Rust stdio 模拟端检查连接及启动目录返回值复用，不依赖账号或付费轮次。

源码完成后需要运行新的桌面构建及 Core 服务才能生效。
