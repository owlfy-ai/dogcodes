## 不依赖原窗口缓存的查询

- 新增后台 `ReviewCall::Operations` 与桌面 `core_review_operations`，按 taskId 和 Git/文件类型分页返回操作摘要。服务先核实会话存在，桌面另检查窗口范围；摘要只读，不执行或重发请求。
- 通用 journal 使用规范 UUID 游标，每页 1–50 项；界面每页 20 项。目录枚举只保留所需的 limit+1 个身份，单条列表读取限制 256 KiB，摘要说明与错误截断。目录扫描在 blocking worker 上运行，不全程占用 journal gate。
- 损坏、过大或已改变的记录明确展示，不当作空记录或成功；详情通过原 exact-ID 查询核实。运行中/结果未知沿用原 active/uncertain 判断。批量文件操作的部分结果保留，确认暂存范围前没有执行的 Git 操作不会标已完成。
- Diff 面板增加“操作记录”：展开后加载，支持分类、上一页/下一页、刷新及详情。后台失效订阅触发重新查询；切换会话、关闭或隐藏后，旧查询不能更新当前详情。空 localStorage 仍可发现后台记录；查看记录不写客户端待恢复缓存，也不自动执行历史请求。
- 当前分页按 UUID 排序，不是时间倒序；新写入可能落在已读页之前，刷新后重新枚举。内存及单条读取有界，但目录扫描仍为 O(n)，大记录详情及长期增长的性能需继续验收。
- 当前注册入口为 105 个，其中生产 103 个；CoreCommand 仍为 18 项。

## 修复正常快照写入的短暂锁冲突

多目录并发读取可能分别保存当前文件版本。原配额预留使用立即失败的独占文件锁，另一目录正在发布内容时，会返回“Review 存储正在使用或维护，请稍后重试”。新增受控并发用例在修改前复现此行为。

仅配额发布预留改为最多 10 秒等待，每次最多间隔 5 毫秒，仅对 `WouldBlock` 等待；真正的锁 I/O 错误立即返回。取得锁后仍核实 epoch、容量及对象数量，锁保持到发布完成/失败。维护、删除与 snapshot-owner 的探测继续立即获取或拒绝；永久 lock 文件及显式 unlock 语义保持。错误类别参照 [Rust TryLockError 定义](https://doc.rust-lang.org/std/fs/enum.TryLockError.html)。
