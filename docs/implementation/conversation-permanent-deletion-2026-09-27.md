# 已归档会话永久删除（2026-09-27）

本次替代 2026-09-25 的可恢复删除方案。仅已归档会话展示删除按钮；确认框明确说明“彻底删除、无法恢复”，移除“最近删除”列表和前端恢复接口。归档本身仍可取消，不等于删除。

## 清理范围

- SQLite 在删除事务内移除该会话的消息事件、审查报告、SessionMap、时间线、工作区记录与 Artifact 关联。逐轮历史 Diff、冻结来源、上下文包等独占 Artifact 及其无引用内容一并删除。
- 其他会话仍引用的 Artifact、版本链祖先和相同内容哈希的共享 blob 保留。仅删除当前会话的候选材料，不执行全库无差别垃圾回收。
- `review/` 清理对应会话的非 Git 基线、带会话归属的比较快照、恢复/撤销记录及其独占内容。先取得独占存储锁、落盘清理计划，再删引用、重新检查其他引用、回收内容。快照引用新增可选 `taskId`，旧版缺少归属的引用不能凭猜测删除，仍由已有保守存储维护处理。
- 保留最小删除标记、事件序号及命令幂等 Ack，阻止迟到事件、恢复命令或投影重建使会话重新出现。没有新增数据库表或旧库迁移。
- 项目源码、Git 数据与 Agent 原生会话历史不删除。本次也不批量清空旧版已软删除记录，不操作用户当前实际数据。旧记录仍留在数据库，UI 不再提供“最近删除”。

SQLite 删除后的空闲页可供后续写入复用，数据库文件不保证立即按同等字节缩小；本次没有对整个数据库执行 VACUUM，也不提供磁盘安全擦除承诺。

## 并发与中断

主任务或审查处于活动状态时仍拒绝删除；Core 审查准入锁及 Store 事务内校验都保留。项目内其他会话继续可并发工作。

数据库永久删除事件带 `cleanupPending`。磁盘清理成功后清除该标记；失败则明确返回“已永久删除、快照清理未完成”，再次提交删除或下次 Core 启动继续清理。清理计划先于引用删除落盘，避免中断后丢失内容候选清单。启动清理失败记录错误并保留待办，不阻塞其他会话启动。

桌面清理比较缓存；快照读取重新验证会话存在，不能继续打开已删除会话的缓存 Diff。前端刷新按当前会话清单移除消息缓存，删除当前会话优先切换到同项目会话，无可选会话时显示新对话草稿。
