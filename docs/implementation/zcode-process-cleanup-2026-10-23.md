# ZCode 停止、关闭与私有进程清理（2026-10-23）

本阶段补齐当前 Core 内的 ZCode 会话停止、关闭及共享 CLI 生命周期。单个会话的关闭通过原生会话协议完成；只有驱动整体释放、通信损坏或私有 CLI 异常时，才清理整个私有进程作用域。不会操作用户独立运行的 ZCode GUI。手机与服务端本轮无生产代码改动。

## 原生协议依据

只读核对本机 ZCode 0.16.9 的 `zcode.cjs`，没有运行已安装的 CLI 或真实模型：

- `session/stop` 只触发活动 AbortController，成功 RPC 回复不能证明任务已经结束。
- `session/close` 的 `closed:false` 表示未执行关闭，不能忽略；`closed:true` 在原生 close/dispose 完成后返回。
- `session/list` 混合持久历史，并可能省略 deferred 活会话，空列表不能证明会话已经关闭。
- `session/read` 对不存在的活运行时返回 `-32004` / `Session is not active:`。在原物理连接上，此特定错误可用作关闭确认；其它读失败仍是未知。
- 关闭核实只读 `contentProfile:index`、`messageLimit:1`，不下载整段历史。其它版本协议行为仍需单独验证。

## 生命周期与恢复

- 私有 CLI 使用 `OwnedChild`，独立 supervisor 持有原进程作用域、stdout reader 和 stderr drain。EOF 不等于退出，直接进程结束但后代持有管道也不会阻止退出观察；收尾确认后才发布成功。
- Driver Drop 通过独立 owner 信号关闭私有 CLI，即使活动轮次持有共享 connection 锁。关闭等待取消、探测取消不取消后台清理；原作用域无法确认退出时，继续保留并退避重试。
- 单会话关闭有独立任务和冻结回执。活动轮次先请求停止；等待方取消后，任务仍关闭原会话，实际确认后才从 map 删除。其它会话继续复用同一个 CLI，不因关闭一个会话而被杀。
- 模糊或丢失的关闭回复只查询原运行时，不重复 `session/close`。明确 `closed:false` 保留会话并允许用户重新发起关闭；关闭中的会话不接受新任务或审批响应。
- 会话持有原物理 CLI 的 Arc；迟到关闭只能处理该原对象，不能向新 CLI 发旧请求。map 删除再比较会话 Arc，保护已经开始等待的旧关闭任务。
- 原 CLI 已损坏时，替换连接须先取得原作用域退出证明。已经排队但尚未发送的轮次，在关闭开始后不再修改 mode 或发送 prompt。

## 停止与正常长任务

同一次停止只发送一个原生请求，重复等待加入原轮次的冻结结果。必须收到真实 `turn.completed` / `turn.failed`，不能把 stop ACK 当作 `TurnInterrupted`。

停止未获真实终态时报告失败，并启动原会话关闭核实；此时本地轮次循环结束仍不代表原生任务已停止。重试 stop 保留原失败回执，不因 `turn_active=false` 误报成功。

删除正常编码任务的三分钟总超时。启动握手和停止确认仍分别有 30 秒控制超时；已经开始的正常任务持续等待真实终态。控制超时会进入原会话清理，不能当作成功结束。

## 输入和帧边界

stdin 写入有 10 秒上限。写入 JSON、换行或 flush 期间失败或 future 被取消时，在释放输入锁前停用原 CLI；下一条请求不能附加到半条 JSON 后。只是等待输入锁时取消，不会触发这个半帧保护。后台清理不依赖等待写入的调用方。

stdout 在读取时限制单条记录为 4 MiB，包含没有换行的异常输出；超限或非法 UTF-8 结束该连接并清理原作用域，不再先无限累积完整行才检查长度。此限制是单条协议帧限制，不是累计流量断开阈值。
