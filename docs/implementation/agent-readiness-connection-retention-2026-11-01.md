# 启动检测连接保留（2026-11-01）

应用启动仍在后台发现安装并执行原生就绪检测。此前 Codex、Claude Code、Pi、CodeBuddy 检测成功后关闭检测进程，用户首次切换 Agent 时再启动目录查询进程。本次将可复用的检测连接交给已注册驱动持有，避免再次支付初始化和进程退出的耗时。

## 生效范围

| Agent | 检测成功后 | 后续使用与限制 |
| --- | --- | --- |
| Codex | 保留完成 initialize、account/read 的 app-server | 模型/思考目录在同一无 Thread 连接上查询，成功后继续保留；正式任务使用自己的工作区、MCP、权限和 Thread 进程 |
| Claude Code | 保留完成 initialize 的 stream-json 控制通道 | 无任务工作区的模型和权限读取复用该通道，直接调用驱动时仍发送原生 initialize 请求；后续的 [列表预热与缓存](agent-catalog-prewarm-2026-11-01.md) 已复用启动响应并让菜单读取缓存。指定工作区时先确认检测进程退出，再建立该工作区的查询进程 |
| Pi | 保留临时目录下 `--no-session` RPC 连接 | 默认模型目录持续复用；读取其他工作区时先退出旧连接。指定模型的查询会改变临时连接的模型状态，完成后仍退出，避免后续把探测模型误认为原生默认模型 |
| CodeBuddy | 与其他 ACP Agent 一样，通过 connect_ready 保留已认证连接 | CLI 绑定进程启动目录；正式任务提供工作区后，现有 cwd 检查会先确认检测连接退出，再为该目录建立连接。目录元数据仍采用独立隔离探测 |
| Antigravity | 保留原有临时检测 | 原生进程整个存活期间占用凭证串行锁；模型目录读取与任务启动也需要这把锁。保留无业务用途的检测进程会阻塞这些操作，因此本次没有改为常驻 |

因此这不是所有任务共享一个原生会话，也不能把所有 Agent 的首次模型菜单都变成无等待。Codex/Claude/Pi 的兼容目录路径可以直接受益；真实任务的工作目录、MCP 和权限配置仍按原流程隔离。其他原生进程或配置文件的修改是否被运行中 CLI 重新加载，由原生协议决定；需要完整重新初始化时可重新检测 Agent 或重新启动应用。

## 生命周期

- 保留连接属于具体 Driver/安装，不登记为任务会话，不发 prompt，也不创建模型轮次。
- 目录查询继续使用原有准入锁。保留连接只有在请求完整成功、调用者仍在等待且连接未停止时才能放回同一 Driver。
- 失败、查询取消或不兼容作用域会关闭原连接，并等到原 OS 进程树获证退出后释放查询准入；不把取消后的部分协议流交给另一查询。
- Driver 退出/被替换时，原来的 owner watch 继续负责关闭未使用的保留连接。Codex 已退出的检测连接不会被复用，会在确认旧进程退出后建立新的目录查询连接。
- 保留原有退出宽限与物理退出确认，未通过缩短凭证写入时间或删除清理等待来提速。
- 原有 `probe_ready` 临时检测 API 保留，Desktop 的四个启动注册路径改用 `connect_ready`。

## 验证

- Windows 上四个驱动库共 169 项通过、31 项原生/付费环境用例按默认忽略。
- 新增 13 项私有进程回归，覆盖同一进程的目录复用、Claude 模型/权限共享、默认模型状态、作用域不匹配、读取取消、Driver 退出、已退出连接替换、认证/配置失败，以及 CodeBuddy 更换工作目录。测试编译独立 Rust stdio 模拟端，不依赖本机安装 Agent 或账号，也不要求 Python。
- 四个驱动 all-targets Clippy `-D warnings` 通过，Desktop `cargo check --locked` 通过。
- 本机 Claude 原生协议验证：同一进程第二次 initialize 返回相同 13 个模型，约 16ms；未发送模型提示词。
- 本次没有执行付费模型轮次，没有主动重启日常 Core；源码接入与进程验证不等同于已打包发布。
