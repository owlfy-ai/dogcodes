# Pi 运行归属、恢复准入与退出证明

日期：2026-10-26。工作区为 `remote-control`。软件尚未发布，本次只使用当前运行期归属，不提供旧句柄兼容、历史数据迁移或用会话路径补造授权。

## 结果

Pi 之前只按持久化会话文件路径定位连接。恢复后的旧句柄可以操作下一轮，恢复/配置还会持有全局会话表锁等待原生 I/O。现在创建、冷恢复与成功热复用均返回新的 scope；prompt/问答在等待单连接准入后重新核对，开始 turn 和取消在连接状态锁内核对原 scope。旧句柄不能借已捕获的连接取消或回答新轮次。

恢复按原会话设置互斥门；配置、进程退出等待和新进程初始化均在全局会话表锁之外。一个会话的配置/退休等待不阻塞其它会话的任务和关闭。原生返回已被其它连接占用的文件 ID 时拒绝覆盖，保留原所有者；热复用也核对原生文件身份及空闲状态。

关闭在同一状态锁内禁止复用，不等待被阻塞的 prompt 写入。取消等待已有的原生 abort/settlement 回执，不因观察者取消而重发；旧归属检查失败不会顺带退休当前连接。真正的退休只移除相同连接实例，已确认退出的内存回执也必须匹配原 scope，记录缺失不算退出。

## 异步结果和配置

每个本地 turn 有独立的运行期 ID。迟到的 prompt 拒绝只影响对应 turn，不能拿走同一连接中的下一轮。当前 turn 的未知/失败派发会先禁止连接复用再退休，而不是只释放本地 busy 标记。

模型和思考强度作为同一次配置尝试：成功后才交接新 scope；明确失败时恢复并读取确认原模型/思考强度和会话文件。已验证回滚返回 `selection_rejected` 并保留原句柄，未确认的配置与调用者放弃的原生变更会退休原连接。

启动/恢复阶段如果已经触发退休，API 保留该原尝试直到原退出获证再报告失败，避免 Core 尚未得到句柄就因失败返回而过早释放工作区保护。关闭 API 本身仍可报告等待超时；Core 会继续持有其已捕获的退出证明。

`get_session_stats` 改用只读观察合同：取消或超时只移除这一次回复槽，不停止运行中的 turn。原始帧只写了一部分的情况仍须退休连接，不能把损坏的传输交给下一项请求。

## 原进程证明

`shutdown_proof` 捕获原 `Connection` 的独立 supervisor 退出回执，只观察原进程组/Job 及原输入/输出读取收尾。临时退出错误、监督通道丢失、表项消失或同名替换均不伪造成成功；观察不发送请求、不恢复进程、不按文件 ID 查找后来实例。

Driver 退出通过单独 owner 信号通知已启动连接，不依赖能否立即取得会话表锁。owner 观察者不持有 `Connection`，因此未安装的候选连接被放弃时仍可正常触发 Drop 清理。原 OS 作用域继续由既有独立 supervisor 保留和退休。

## 2026-10-27：模型与思考目录查询准入
