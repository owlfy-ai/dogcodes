# 侧边问答的后台状态订阅

对应 DT-08/DT-10，接续[安装准入](desktop-sidebar-chat-readiness-2026-10-16.md)。本工作块将问答状态变化从仅靠界面轮询推进到后台通知；不改变新问答、取消或清空的原请求与回执语义。

## 状态与连接归属

Core 为每个已经加载的问答持有可合并的变更通知，新的订阅首先提示重新查询。启动受理、可见文本变化、取消受理、结束（包括终态保存失败）及清空成功后均通知订阅者；重复文本和重复取消不制造额外变化。清空保留同一通知源，因此已有视图不必等断线或轮询才能看到清空结果。

通知只表示状态可能变化，不携带正文，不作为持久回执或执行结果。UI 仍从 Core 查询事实。Core 全局最多 64 个问答订阅，丢弃订阅释放名额；每条订阅只监听指定会话，首次订阅和发出消息时检查会话存在。15 秒无变化发送心跳，服务关闭或会话已不存在时返回错误。

daemon 新增 `sidebar_chat_watch` 流入口，复用已有认证、限时读写和失效通知转发机制。长订阅释放普通 RPC 请求门禁，不阻止服务空闲替换。客户端断线或停止读取会结束转发并释放订阅，但不会调用问答取消或清空。

Tauri 新增 `core_sidebar_chat_watch` / `core_sidebar_chat_unwatch`，使用已有窗口订阅注册表和清理机制；窗口仍先通过会话范围检查。关闭窗口只中止自己的转发。注册入口由 119 增至 121，其中 2 个为验收特性，生产入口为 119；CoreCommand 仍为 18 个。

## 前端

`SidebarChatApi` 增加可选订阅接口，正式 Tauri 客户端使用已有 `createInvalidationSubscriber`。同一 JS 上下文的同一会话共享连接，不同会话独立；连接失败展示重连状态，按已有有界退避机制重连，旧连接回调不更新新连接。

可见问答面板先订阅再查询，单次只允许一个状态查询。查询期间收到新通知会标记待重新读取，在本次完成后继续查询，避免漏掉更新或旧响应乱序覆盖。支持订阅时使用 15 秒补漏查询及窗口重新聚焦时核实；没有订阅能力的适配器保留运行中 500ms、空闲 3 秒的旧查询方式。隐藏或卸载面板释放订阅和计时器，不停止回答；本端操作继续用原有 epoch/guard 排除旧读取。

草稿、未确认原请求跟踪和待发送选择保持本端，不通过通知共享。流式文本仍是 Core 的运行时状态，本次未增加逐字持久化；后台崩溃后的中断恢复语义沿用既有实现。
