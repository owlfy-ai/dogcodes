## 问题与行为

选择/移除安装会清除 provider 的当前注册驱动，重新检测也可能用同一个 executor 身份替换实例。原主会话在 worker 启动、审批投递和取消时重新查询注册表：已经接受的任务可能找不到原驱动，或把交互发送给没有持有原生会话的新实例。

`owned_runs` 从运行 ID 集合改为运行 ID 到原驱动引用的映射，仍由 `RunOwnership` 统一释放。新主会话在准入读锁内按将要持久化的 turn.queued executor 查找驱动；找不到时拒绝受理，不创建任务回执。持久接受后、发布事件前建立归属，再交给 worker。重复请求继续返回原回执，不创建第二份运行。

执行、取消、手动审批和自动权限审批均使用 run ID 和 executor 联合匹配的原驱动。运行中权限目录也优先读取该实例，避免选择变化后权限 UI 查询失效。原生自主续跑使用其观察流已经持有的驱动创建运行归属；它不是新发用户任务，不重新应用新任务准入。

窗口/安装选择变化不释放在跑任务的引用。运行结束、worker 退出或自主续跑收尾后由 RAII 释放。后台重启没有这份内存归属，继续使用既有中断恢复，不把替换驱动当作已恢复进程。
