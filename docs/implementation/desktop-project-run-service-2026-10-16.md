# 项目运行配置与分析任务迁入后台

日期：2026-10-16。对应 DT-08/10 和项目运行的 DT-09。代码已接入、针对性验证通过；不是三平台发布验收完成。

## 已实现

- `ProjectRunHost` 改由 daemon `ServiceControl` 持有，窗口启动不再创建独立实例。运行配置的查询、分析、编辑以及启动前 generation/命令/目录校验均在同一后台入口执行。Tauri 只保留窗口访问范围检查与转发。
- 沿用私有数据目录的 `project-runs/<项目>-<平台>.json`，保留原格式和用户修改，不新增数据库表或旧库迁移。不同客户端通过同一服务读取同一缓存和文件。
- 项目注册/更新成功后，由服务触发必要的配置分析，不依赖 GUI 收到回执后继续调用。相同目录的已有配置复用，纯名称修改不重新调用 Agent；目录变化且存在用户编辑时保留旧配置，等待用户明确重新分析，不静默覆盖。
- 分析任务使用后台 Tokio 运行时、独立活动计数及原有并发限额，排队中也计为活动；窗口断开不取消分析。服务空闲退役检查同时考虑终端和分析任务。并发读取缺失配置只接收一个分析 generation，旧任务结果不能覆盖新 generation。
- 启动、编辑与分析准入使用后台配置锁；编辑仍校验 generation，分析期间不编辑。启动只接受当前平台、当前项目根目录及当前 generation 中存在的命令。进程执行继续复用独立 TerminalHost。
- 分析候选从后台注册列表与持久 Agent 偏好共同生成，遵循启用/排序；显式选择已禁用或不可用 Agent 时拒绝开始分析。此处不代表所有其他 Agent 执行入口的准入审计已完成。
- 缓存读取区分不存在、I/O 错误和损坏。后两者保留文件并报错，不再当作首次使用重新分析。写入使用同目录临时文件、同步和原子替换，移除 Windows 先删除旧文件的空窗。编辑写入失败不推进内存版本；分析结果无法保存时明确标 error。
- 服务重启读取遗留 analyzing 状态时标为中断，保留命令、固定和重命名，不自动重放旧分析。测试/隔离验收的 embedded CoreClient 也提供相同终端与运行配置服务，避免仅正常 RPC 路径可用。

## 持久操作身份与客户端恢复补充

- 手动分析和编辑使用 UUID 操作 ID 与不可变请求。后台把请求、接受后的 generation、状态与配置写进同一个原子 JSON 文件；旧文件缺少 receipts 时视为空集合，不清空用户配置，不新增数据库迁移。
- 重复 ID 先核对完整载荷，再处理当前 generation。相同请求返回当前配置，不重复改名/删除/固定或再启动分析；同 ID 不同请求拒绝。返回最新配置，避免旧回执覆盖已知的新配置；原操作的接受版本单独保存在回执中。
- 手动强制分析必须提供预期 generation，即使没有用户编辑也不能绕过版本条件。覆盖用户编辑仍需原有的显式确认。分析回执区分 running、succeeded、failed、interrupted 和 superseded；重启后未完成分析标中断，不自动重放。
- 新增 `core_project_run_operation` / daemon 查询，按会话和 ID 核实结果。私有请求记录只存在后台文件，普通配置响应仅包含 RunCatalog；新注册 handler 总数为 100（98 个生产入口、2 个验收入口）。
- 客户端调用前持久化待核实请求，各操作独立键，避免旧响应清除另一个窗口的新请求。窗口重开可继续核实；响应丢失先查回执和最新配置，不自动重发。只有用户点击重试且查询未发现原回执时，才重发原 ID/原参数。
- 未核实期间禁止新的分析/编辑。用户可明确放弃本机重试，这不会取消可能已被后台接受的操作；目录生成状态及后台进程继续从服务查询。已明确返回覆盖确认要求时，释放旧请求并进入原确认流程。
- 写入的 rename 已完成但目录同步失败时，暂停本进程的配置访问，要求检查存储并重启核实，避免基于旧内存再次执行。分析结果保存失败不会报告成功回执。

## 明确拒绝与结果未知的错误分类

- 分析/编辑返回结构化 `MutationError`：`rejected` 包含稳定错误码和用户文案，`unknown` 保留无法核实的结果。版本冲突、无效名称/参数、分析中编辑、覆盖确认、Agent 不可用及会话/项目不存在在写入前明确拒绝；读写故障、锁不可用和传输错误仍保守视为未知。没有通过字符串匹配推断是否执行。
- daemon 对这两个 mutation 的业务结果使用内层 `Result<RunCatalog, MutationError>`，外层 RPC 错误仍属于未知；CoreClient 解包后，Tauri 保留结构化错误。窗口访问范围拒绝发生在转发之前，作为 `access_denied` 返回。其他业务域的错误协议尚未收敛。
- 客户端仅在收到结构化拒绝时清理该操作 ID，不查询成功回执、不重发，也不清除其他窗口的待核实记录。未知结果继续查询持久回执，查不到则保留原请求。响应丢失后，用户明确重试仍先查原 ID，只在无回执时重发原参数。
- 覆盖确认改为识别结构化错误码，移除按字符串判断及删除首个 pending 的逻辑。编辑版本冲突刷新当前配置，只有用户再次操作才发送新请求。面板将读取错误与操作错误分开保存，定时查询成功不再抹掉刚发生的操作失败原因。

## 项目启动的原请求绑定

- `ProjectLaunchRequest` 与解析后的 `LaunchIntent` 一起写入同一终端操作记录，包含原会话、generation、目录序号、命令 ID、初始尺寸和操作 ID；在创建 PTY/进程前持久化，不另建可能与进程记录不同步的回执文件。
- 项目启动入口先按 ID 核对完整原请求。相同请求只返回既有资源及其状态，即使运行配置已改名、当前项目/会话已不可查询或后台已重启，也不重新解析最新命令、不重新执行。只有未接受的新 ID 才校验当前项目、generation、目录及命令。
- 同 ID 改变 generation、会话、目录、命令或初始尺寸均拒绝。运行期间的 resize 仍是独立操作，不改变启动请求。后台重启后原 active 记录保持 Unknown，不伪造运行或完成。
- 普通终端 RPC 不接收项目启动绑定，绑定只能由项目启动校验路径生成；持久记录恢复时检查绑定与解析后资源身份的一致性。查询记录的内部错误不再被当成“没有旧操作”。
- 缺少绑定的旧终端记录继续保留和查询；项目启动重放无法证明载荷相同时明确拒绝，并引导查看原终端。不补写猜测的 generation，不清理用户数据，不自动重新启动。

本工作块集中原生验证：`project_runs` 首次 **14 通过、1 超时失败**（`/tmp/dogcodes-launch-binding-project.log`），失败点是 RPC 实进程等待退出的 8 秒上限。补充终态/命令执行标记诊断，未延长超时；只复验该用例 **1 通过**，exit 0（`/tmp/dogcodes-launch-binding-diagnostic.log`）。首次超时原因尚未证实，不能仅凭复验通过认定稳定性问题已解决；候选验收须用隔离 Shell 环境与实际用户 Shell 分别核对。
