### 3.1 三项基础改造的验收边界

**DT-08：服务拥有执行，窗口拥有视图。** 保留并扩展现有 Core/daemon，避免重写已可靠的会话执行。重点处理仍由窗口 owner 或 Channel 发送失败触发清理的 PTY/项目进程；关闭视图释放订阅，显式停止和退出后台分别有清晰语义。运行资源可列出、重新附着和停止；有界输出缓存或终端屏幕恢复必须报告缺口。后台崩溃/系统重启后不假装原 PTY 仍存活，不自动重新执行命令；按进程身份核实或标中断/未知。文件监听与快照租约按资源/订阅管理，不继续用窗口标签作为业务归属或授权依据。

**DT-09：覆盖全部功能，不对所有消息套同一种可靠性机制。** DT-01 列出会话、审批、审查、Diff/Git、文件/附件、终端、项目运行、Agent 管理和共享设置的现有入口；每项归类为只读查询、可幂等变更、外部副作用或持续流，并记录负责服务、requestId/operationId（适用时）、版本条件、回执、终态、取消及恢复方式。纯查询不为持久操作记录增加无意义写入；PTY 按键/输入字节不重放。外部副作用持久化必要意图和结果，回执丢失先核实，不能用新操作 ID 自动重发。提交成功/推送失败及无法确定是否已启动的进程分别处理。对已有 Core 幂等和事件存储复用并补缺口，禁止另建一套互相矛盾的业务状态。

**DT-10：共享业务事实，保留端内体验。** 先建立状态归属表，再收敛后台事实源。置顶/归档、业务分组、Agent 启用/排序和运行资源状态按宿主共享；主题、布局、滚动位置、未发送正文/附件选择/待发送参数保留端内。UI 缓存和乐观更新不能成为唯一事实源。已有 localStorage 设置要有显式保留/导入及冲突处理方案，服从当前数据库策略，不静默丢失或覆盖。发布前以两个本机客户端及窗口/服务重启验证，无需先开发手机。

三项需有独立验收证据后才能通过 DT-07/R3。核心用例包括：关窗后任务和项目仍在、重开可附着；发送后断连不会重复 Git/启动进程/审批；两个客户端修改共享设置可见且有冲突语义，端内草稿互不覆盖。

## 4. 发布工程细分

### R1：安装包与平台边界

1. 利用现有图标与构建配置，先验证当前源码在三平台的工具链和原生依赖，再启用实际目标包。
2. 为每个平台记录支持的系统版本、CPU 架构、安装格式、用户/管理员权限要求、运行时依赖、签名状态和卸载行为；最低版本与架构由 DT-01/打包探针明确，不默认宣称覆盖所有架构。
3. 验证首次启动、无 Agent 时引导、发现已安装 Agent、浏览/注册目录、运行真实任务、Git、终端和项目命令、主题/缩放、退出重开。Linux 桌面会话兼容按实际 GUI 环境记录，不能把桌面客户端适配误记为已实现 X11/Wayland 远控。
4. 明确安装新版本时历史、配置、Agent 原生凭据与项目文件如何保留。现有未发布数据库策略不支持迁移，发布前必须确定冻结 schema 或兼容策略；在方案未定时不自动清空开发者或试用者数据。
5. 首发至少提供手动下载安装/更新说明。内置自动更新、Homebrew/其他包管理器、正式商店等可后续做，不作为三平台 GitHub 安装包的默认前置项。

### R2：公开源码的可用性

1. 先生成待公开文件清单，再整理 Git 跟踪内容；不能 `git add -A` 将整个工作区或已跟踪运行缓存无差别发布。任何本地数据清理/历史处理独立留证据。
2. 核对工具链版本、锁文件和 native 依赖，从全新 checkout 验证安装/编译/测试，CI 不依赖开发者本机 node_modules 或 dist。现有打包/图标脚本复用。
3. 维护项目许可证与说明；不因为 workspace 字段写有许可证就省略发布文件。2026-10-17 用户明确素材由其后续补充，Agent 不再执行素材来源核验或整理。
4. README 及多语言页面改为真实已验证三平台范围，提供 Release 下载、源码运行、Agent 自行安装/登录、已知限制和故障反馈入口。只有包实际发布后才替换正式下载链接。
5. 核实七张功能图，替换仍存在的占位截图；截图用隔离演示数据，画面与真实功能一致。维护规则见 [README 维护](../README-MAINTENANCE.md)。
6. 准备基础 CI、Issue/问题报告模板和版本说明模板；不将付费发布服务、完整遥测或新账号体系引入本期。

### R3：发布候选与发布动作

候选需包含：明确 commit/tag、源码发布边界、三平台包与校验和、签名状态、安装说明、支持矩阵、已知问题及数据兼容说明。目标仓库、首次公开/既有仓库更新、具体可见性和署名/许可证意图若尚不明确，在候选准备过程中再核实。

实际创建/公开 GitHub 仓库、推送、打 tag 或发布 Release 是后续执行动作；当前请求只调整工作拆分。本期不用手机端或官方服务通过验收作为桌面首发门槛。
