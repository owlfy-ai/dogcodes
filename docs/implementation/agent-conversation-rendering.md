# Agent 对话渲染交互设计

状态：首版交互已实现并接入产品代码。2026-09-11。实现范围、验收结果与边界见 [实现与验收记录](agent-conversation-rendering-acceptance.md)。下文保留设计规范，不能将其中所有后续目标等同于本轮已验收。

子智能体能力已完成[真实委派协议探测](../compatibility/subagent-observability-live-2026-09-11.md)。Claude、ZCode、Grok 已验证实时内部工具事件；Codex 已验证子 thread 历史读取；Cursor、Kimi 本次只有委派详情或部分过程；Antigravity 已取得子日志中的调用请求，但读取执行被拒绝。子任务展示分别判断关系、状态、实时过程和历史读取能力，不以供应商品牌硬编码可用性。

## 1. 体验目标

借鉴已观察到的 ZCode 对话：正文拥有最高阅读权重，思考和工具以低强调的紧凑行穿插；不为每次工具调用重复显示头像、气泡和时间戳。保留执行顺序，让用户随时理解当前进展并检查结果。

用户明确要求：思考内容运行时只占一行，从右向左快速滚动；思考结束后只显示耗时，不再提供思考正文。此处的内容是 Agent 协议明确提供给客户端展示的文本，不能根据等待时间编造。

## 2. 当前代码事实

本节依据当前工作区源码；文档中的历史验收不是本次重新验证。

- `apps/desktop/src/App.tsx` 的 `TimelineEntry` 用 `<p>` 输出 assistant 文本；`ToolActivity` 只有通用扳手图标、text 和状态。
- `crates/protocol/src/lib.rs` 的 `TimelineItem` 只有 item/task/turn、kind、text、provider、sequence 和时间；不足以承载分段正文、工具参数、输出、位置与计时来源。
- `driver-api` 的 ToolStarted/ToolCompleted 只有名称、摘要、ID、成功标记；没有中间更新、结构化分类与输出引用。
- ACP driver 丢弃 AgentThoughtChunk；ToolCall 只取 title/ID，ToolCallUpdate 只映射部分状态。Claude driver 忽略 thinking delta。ZCode driver 只接 text_delta，工具事件压缩成通用摘要。
- Claude 主接入是 Rust 直连官方 headless stream-json，不是直接使用 Claude Agent SDK。Codex 是 app-server；ZCode 是其 app-server JSON-RPC 变体；Cursor/Kimi/Grok 共用 ACP driver；Antigravity 是 headless stream-json。无需为视觉一致性替换这些通道。
- ACP/Claude/ZCode 多处文本使用固定 `message` ID，新增渲染必须检查工具前后文字是否被拼为一个气泡；按消息边界或连续文本段建立稳定 segment ID。

## 3. 一轮对话的结构

```text
用户问题

Agent 名称 · 工作中 24 秒
思考 · 持续了 3 秒
我先查看事件处理与对话组件。
⌕ 查阅 · 文件搜索 2 次 · 读取 3 次                 展开
⌕ 网页搜索 · ACP 工具调用                         展开
▧ 修改文件 · App.tsx · +24 −8                    查看变更
▹ 终端 · pnpm test                               运行中
◌ 思考中 4 秒   [协议提供的文本从右向左经过……]

完成后：
Agent 名称 · 已工作 42 秒
上述操作留在原位置，思考行替换为“思考 · 持续了 4 秒”
最终回答（Markdown）
变更 2 个文件 · 查看变更
```

Agent 名称和总耗时每轮显示一次。正文中的进度说明正常保留，只有被协议标记为思考的段落采用临时展示规则。不要根据文本措辞把“我先看看……”猜成思考。支持多段正文、多轮思考和并行工具。

完成时不强制折叠整轮过程、不移动最终答案，也不关闭用户已展开的详情。可手动收起整轮过程，最终答案和未解决错误始终可见。

## 3.1 Markdown、Mermaid 与 LaTeX 消息渲染

用户确认：Agent 正文需美观的 Markdown 渲染，并支持 Mermaid、LaTeX 等常见内容。主对话、子智能体侧栏中的正文与最终回复复用同一渲染组件。工具原始日志继续作为日志或代码展示，不自动解析成 Markdown。思考内容仍遵循单行临时展示规则。

### 内容范围与视觉规范

| 内容 | 展示与交互 |
|---|---|
| Markdown / GFM | 标题、段落、粗体、斜体、删除线、引用、分隔线、有序/无序列表、任务列表、表格、链接与图片；任务列表默认只读 |
| 行内代码 | 与正文协调的等宽字体、轻底色，不打断行高；长路径可换行 |
| 围栏代码块 | 语法高亮、语言标签、一键复制原始代码；未知语言降级为纯文本；长行在块内横向滚动 |
| Mermaid | 识别 mermaid 围栏，展示图表；提供“图表 / 源码”、复制源码、放大查看和缩放，适配浅色/深色主题 |
| LaTeX | 支持 $…$ 行内公式、$$…$$ 独立公式，以及 \(…\)、\[…\]；公式可选择、可复制源码，块公式溢出时局部滚动 |
| 表格 | 清晰表头、轻分隔线、适当留白；窄侧栏内横向滚动，不撑宽整条消息 |
| 链接与文件引用 | 网页链接正常打开；已确认的工作区文件引用接已有文件/Diff 入口；不能把任意文本路径猜成可靠文件定位 |
| 图片 | 限制为正文宽度，加载失败保留替代文字；支持放大查看，加载完成不强制滚动到末尾 |

正文沿用应用字体、字号和主题；建议行高 1.65–1.75，段落间距约 0.7em，标题按层级逐级缩放，避免一级标题在对话中像网页横幅。引用用低强调的左侧线与文字色。代码区使用独立等宽字体和轻边框，避免每个段落都包卡片。主对话与窄侧栏保持相同排版规则，随容器宽度自适应。

数学语法只在正文数学节点解析，不处理代码块、行内代码中的美元符号；金额、转义美元符号和未配对分隔符保留为文本。Mermaid 和公式解析错误局限在各自内容块，提供可读源码，不让整条消息消失。

### 流式渲染

- 按消息分段增量更新；已经完成的代码、图表和公式块缓存渲染结果，不因后续 token 重算整条消息。
- 尚未闭合的代码围栏先显示代码；未闭合的 Mermaid 围栏显示“图表生成中”和可查看的源码，闭合后再生成图表，避免逐 token 出现语法错误闪烁。
- 未闭合的公式暂作文本展示；边界完整后渲染。turn 结束时仍不合法的内容保留源码和简短提示。
- Mermaid 异步渲染按消息 ID、块 ID 和内容版本核对结果，快速切换会话或修改块内容时不回填旧图。
- 用户正在阅读历史时，图表、图片、高亮完成均不抢夺滚动位置；仍在底部跟随时继续正常跟随输出。
- 流式显示、历史恢复和最终全文校正使用同一解析规则；最终快照不能重复追加已收到的正文。

### 实现边界与验收

渲染不执行原始 HTML 或代码块。链接按允许的协议处理；Mermaid 不执行图表内任意脚本或点击回调；LaTeX 使用受限数学渲染，不执行系统命令或不可信 HTML 扩展。较大图表按需渲染并设大小限制，失败或超限时仍可查看、复制源码。

实现时按实际依赖版本验证 Markdown/GFM、数学解析、高亮与 Mermaid 的兼容性；图表等较重资源延迟加载。当前 desktop package.json 尚未引入这些渲染依赖，本节为需求规范，不表示功能已完成。

验收覆盖：中文混排、嵌套列表、任务列表、宽表格、未知代码语言、金额与数学公式区分、非法公式、流式未闭合围栏、Mermaid 语法失败、浅深主题切换、窄侧栏、键盘复制/放大、读屏替代描述，以及消息切换后异步结果不串线。

## 4. 思考行

### 外观与动效

- 固定 28–32px 高；左侧图标、“思考中”和秒数固定，右侧 flex 文本区 min-width:0，单行裁剪，左右渐隐。
- 建议初始速度 160px/s，可在实现评审中调整到 120–220px/s。按像素速度计算位移，不按字符串长度指定固定周期。
- 内容从右向左单次经过；新增量接到尾部，不因每次 token 到达而重启动画，不无限重播旧句子。队列最多保留约 800 字；超过时按句边界丢掉尚未显示的旧内容，优先展示新进展。
- 悬停或键盘聚焦可暂停；减弱动态效果时静态展示最新片段，仍保持单行。读屏只播报状态开始/结束，不逐 token 播报。
- 结束即清空展示文本、停止动画，原位变为“思考 · 持续了 8 秒”。无展开箭头，无 tooltip 思考全文，也不把思考正文加入普通复制或导出。

### 状态和时间

| 场景 | 展示与处理 |
|---|---|
| 明确的思考开始/增量 | 建立独立 segment，开始临时展示 |
| 明确结束 | 使用供应商耗时，或本地观测到的起止时间 |
| 没有结束事件 | 同一生成流转入正文/工具请求时关闭段落；标记时间为观测值，不把并行子流事件当结束 |
| 仅观测到 chunk 起点 | 显示“约 8 秒”；工具执行和审批等待不计入思考 |
| 时间未知 | “思考已结束”；不得显示伪造的 0 秒 |
| 用户停止或连接丢失 | “思考已中断 · 约 8 秒”，而非正常完成 |
| 完全没有思考事件 | 只显示整轮“工作中”；不得把无输出等同于思考 |
| 历史恢复 | 显示已保存的时间与终态，可展开查看已保存的思考正文；缺失终态则显示“状态未确认” |

活跃计时用单调时钟，落库保存 durationMs 与时间来源 native/observed/unknown；墙上时钟只用于时间戳。若协议无可验证的边界，不宣称准确模型推理耗时。

思考进行中，正文走有界临时通道（只显示末尾片段）。段落结束时，经脱敏的正文随结束事件保存，每段上限 64 KiB，超出部分不保存并标记 `textTruncated`；桌面端历史中折叠展示，可展开查看。手机端不展示思考正文：电脑发给手机的历史只保留状态和耗时（2026-10-21）。断线重连可重新取得当前临时片段。不改动供应商自身保存会话的行为。仅接明确可展示的 thought/summary，不读取加密、redacted 或未公开内容。

## 5. 工具分类与详情

| 类别 | 单行示例 | 展开后 |
|---|---|---|
| 文件搜索 | 文件搜索 · `ToolActivity` · 4 个匹配 | 查询、范围、文件与行号；次数和匹配数分开 |
| 网页搜索 | 网页搜索 · ACP tool calls | 查询、来源标题、链接、协议返回的摘要 |
| 读取文件 | 读取 · `src/App.tsx:134` | 路径、行范围、已返回片段 |
| 修改文件 | 修改 · `src/App.tsx` · +24 −8 | 按文件 diff，接现有 Review 面板 |
| 终端 | 终端 · `pnpm test` | cwd、完整命令、流式输出、退出码 |
| 获取网页/资源 | 获取网页 · agentclientprotocol.com | 目标链接、返回内容 |
| 删除/移动 | 移动 · `old.ts → new.ts` | 明确旧/新路径，删除单独标注 |
| 计划 | 计划 · 完成 2/4 项 | 协议返回的计划与逐项状态 |
| 委派任务 | 子任务 · 检查协议映射 | 点击在右侧栏查看执行过程；不可用时明确提示，见下节 |
| 其他/MCP | 工具 · 服务名 / 工具名 | 可识别参数、结果；未知内容保留“其他” |

分类优先级：原生结构化种类 → 已验证的 provider+toolName 映射 → 结构化参数辅助 → other。ACP search 不保证是网页搜索，只有明确 URL/工具身份/范围证据才细分；否则显示“搜索”。Bash 执行 rg 仍是终端，可加“搜索文件”副标题；不要把复合 shell 命令拆成未经证实的操作。

统一生命周期：pending、running、awaiting_approval、succeeded、failed、cancelled、unknown。批准只表示可执行，不表示成功。Turn 结束也不能把所有未终结工具改成成功。工具失败不等于整轮失败，重试用独立调用并可关联前次失败。

### 聚合和排序

- 只合并同一轮、同一父任务内连续的只读查阅操作：文件搜索、读取、网页搜索/获取。合并行仍分项计数，例如“查阅 · 文件搜索 2 次 · 网页搜索 1 次 · 读取 3 次”。展开保留原始时间顺序和分类标签。
- 正文、思考、修改、终端、待审批和失败构成聚合边界；不能跨边界把全轮工具按类别重新排序。
- 一次工具调用只占一项，更新原项；开始和完成不各占一行。并行工具按首次出现排序，不按结束时间跳动。
- 初始折叠成功工具，运行时展示紧凑状态；失败自动显示一条错误摘要，完整输出按需展开；审批始终显露。
- 数字必须来自真实数据；没有命中数就只显示调用次数，没有 diff 就不填 +0 −0。

### 详情承载

短内容在原位展开；长终端输出和多文件 diff 进入已有侧面板，主对话保留摘要。终端保留输出上限与截断提示，支持打开完整已保存输出，不把控制字符当页面 HTML。Markdown 禁用原始 HTML、处理链接协议与资源加载；代码、图片、链接、附件按结构化类型渲染。

Agent 报告的 diff 标记为“Agent 报告”，已有工作区快照仍是 Review 的变更事实源。跳转、复制可以直接操作；“重新运行命令”不能作为查看详情的附带行为。

### 子智能体：主对话入口与右侧详情栏

用户确认的交互：主对话渲染可点击的子智能体行；能够取得执行记录时，在右侧栏查看；获取不到时，点击后提示“当前 Agent 无法查看子智能体详细信息”。

- 主对话保持紧凑，显示子智能体图标、名称或类型、任务描述、真实执行状态和可得耗时。子过程不默认展开挤占主对话。
- 点击打开右侧详情栏，标题显示子任务名称与状态，提供关闭按钮；主对话和输入框保持可用。多次点击同一个子任务复用详情，不创建重复页面；切换子任务时隔离内容、请求与滚动位置。
- 侧栏复用主对话的执行过程组件：思考单行滚动且完成后仅保留耗时；文件搜索、网页搜索、读取、终端等分类显示；逐次文件修改可看 Diff；任务结束后展示可得的最终回复与文件汇总。
- 支持实时过程时持续追加；只支持历史时按需读取，并标识“执行记录”，不伪装成实时流。仅有部分记录时显示“仅提供部分执行记录”，仍允许查看已有内容。
- 文件 Diff 从子详情进入已有查看器，保留返回子任务的入口及阅读位置；不能把详情栏切换当成启动、恢复或重新执行子任务。
- 主任务结束不关闭正在查看的子详情，也不把尚未收到终态的子任务改为成功。

详情获取与子任务执行是两套状态：子任务可能执行成功，但详情不受支持、正在加载或加载失败。

| 详情状态 | 点击行为 / 侧栏呈现 |
|---|---|
| 已有实时记录 | 打开侧栏，展示已有记录并接收新事件 |
| 历史可读取 | 打开侧栏显示加载状态，按子会话 ID 读取；同一子任务请求去重 |
| 能力未知 | 先尝试已声明的只读详情接口，再按实际结果展示；不因品牌直接拒绝 |
| 明确不提供详情 | 在侧栏显示“当前 Agent 无法查看子智能体详细信息”，保留子任务摘要和已知状态 |
| 部分记录 | 展示实际可得内容与“仅提供部分执行记录”提示 |
| 临时读取失败 | 显示“子智能体执行记录加载失败”并提供“重试”，保留已加载内容；不误报接口不支持 |
| 暂无事件 | “尚无执行记录”；运行中继续等待，不能误报不支持 |
| 历史已清理或过期 | 明确提示记录不可用，不把历史丢失归为 Agent 能力缺失 |

内部身份至少保留 provider/installation、父 run/turn、父工具 ID、子会话或 task ID、详情获取方式、可用性及原因。请求返回时核对当前 task 和子 ID，防止切换任务后旧结果覆盖新侧栏。详情可用性随版本、协议通道及本次记录变化；重连或重新打开时按稳定事件 ID 去重。

### 文件修改：逐次记录与 turn 汇总

用户确认按两层呈现，复用现有 Diff：

- 执行中，每次成功修改展示操作、文件名、目录和可得的增删行数；点击看该次修改前后 Diff。同文件多次修改保留独立记录。
- turn 结束后按文件去重，汇总本轮开始到结束的净变化，提供“查看 Diff”“打开”；不能直接相加每次修改的统计，也不能使用整个工作区未提交变化冒充本轮变化。
- 保存对应的版本引用，后续修改不改变历史 Diff；执行前已有修改不计入本轮。子智能体的修改在其详情内展示，并在父 turn 汇总中去重纳入。
- 快照补充发现但缺少归属证据的变化标为“检测到文件变更”；不推断一定由 Agent 或某个子智能体产生。失败修改不计入成功汇总，无 Diff 数据不显示伪造的 +0/−0。

## 6. 事件到界面的架构

```text
原生 RPC / stream-json / ACP
    ↓ provider 适配：身份、块边界、增量/快照语义、类别
统一事件 + 临时思考通道
    ↓ 现有顺序控制、去重、脱敏、持久化
ConversationProjection（按 turn / run / segment / tool ID）
    ↓
TurnView → MarkdownMessage / ThinkingRow / ActivityGroup / ToolRow
                                      ↓
                       ApprovalDetails / TerminalOutput / ReviewPanel / SubagentDetailPanel
```

建议新增逻辑模型，字段名供实现阶段确定：

```ts
type ConversationBlock = MessageSegment | ThoughtSegment | ToolCall | PlanBlock;
// 共同字段：taskId, turnId, runId, blockId, parentBlockId?, firstSequence
// MessageSegment：phase?、contentBlocks、streaming/completed/interrupted
// ThoughtSegment：status、startedAt、endedAt?、durationMs?、durationSource
// ToolCall：nativeToolId、category、title、status、locations、contentRefs、
//           startedAt?、endedAt?、exitCode?、approvalId?、classificationSource
// 临时 ThoughtDelta：runId + segmentId + localSequence + boundedText
```

扩展 DriverEvent：MessageStarted/Delta/Completed、ThoughtStarted/Finished、ToolUpsert/OutputDelta、PlanUpdated。保留旧事件入口并在适配层转换；公开 wire schema 同步 Rust 与 TypeScript，新增字段有默认值并明确版本。

关键规则：

1. 消息身份使用 native ID；没有 native ID 时由适配器按连续消息块生成 segment，不能每 token 新建 ID。
2. 工具身份以 run/session/nativeToolId 组合隔离；相同 ID 的开始、参数和输出更新必须落到同一项。
3. patch 缺失字段保留旧值；数组是替换还是追加按具体协议解码，禁止统一 append。Claude 部分 JSON 参数完成前不能当完整对象展示。
4. 工具 update 先到则建占位，晚到的 start 只补资料，不让终态回到 running。重复通知和补发快照按来源 ID/游标去重。
5. 复用 OrderedEventCursor 的持久全局序列；临时思考使用独立序列，不能制造持久日志 gap。投影快照附持久游标，重连从游标之后补事件。
6. 父子、多 Agent 与上下文切换有独立 run 标识；无原生关联信息就平铺，不能凭标题推断父子。
7. 正文增量与最终全文可能重复：按供应商约定 reconcile，不把 final snapshot 再 append。
8. 原始 JSON 只进入现有受限诊断路径，不铺在正常对话；工具大输出使用 Artifact 引用，延迟加载。

## 7. 各通道落地策略

| 通道 | 当前可复用 | 本设计要补 |
|---|---|---|
| Codex app-server | item ID、文本/工具生命周期、审批 | 按本机生成 schema 校验公开 reasoning summary、消息 phase、command/output 与文件变更；不能假设所有版本字段相同 |
| Claude stream-json | 文本 delta、tool_use/tool_result、控制请求 | 内容块 index/ID、思考可展示性校验、tool 输入流与输出、消息快照去重；不为 UI 改走 SDK |
| ZCode app-server | stream.delta、tool.updated、turn 事件 | 核验 reasoning_delta 生命周期、工具种类/参数/结果；内部协议按版本 fixture 约束 |
| ACP（Cursor/Kimi/Grok） | SessionUpdate、toolCallId、审批 | 接 kind/status/content/locations、公开 thought 与计划；按照实际通知启用，不把标准支持等同于每家都发 |
| Antigravity stream-json | step_update、tool 信息、result | 检查 step ID、工具输入输出；无可展示 thought 时仅显示工作中；无审批通道不生成可点击审批按钮 |

统一的是显示语义，供应商能力保留 Supported/Unsupported/Unknown。适配器能力不足只影响对应细节，正文仍可完整使用。SDK 是协议消费方式，不是另一套对话组件。

ACP v1 官方文档定义了工具种类、状态更新、位置以及内容/diff/terminal 结果，可作为共同模型的参考，但不能替代安装版本与实际事件的验收。[工具调用](https://agentclientprotocol.com/protocol/v1/tool-calls)。一轮可能包含多次消息和工具交换，渲染应保留这种分段。[Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)。

## 8. 性能与阅读稳定性

以 block 为更新单位，不让一个 token 重渲染整个会话。文本 UI 批次 30–60ms，计时每秒一次，动画用 transform 与独立有界队列。后台窗口暂停动效，终态与审批立即应用。

处于底部且没有主动选择文字时跟随新输出；用户向上滚动后停止跟随，出现“回到底部”，即使仍在底部 80px 内也不恢复跟随。手动滚回底部（允许 1px 的测量误差）、点击“回到底部”或发送新消息后恢复跟随。滚动条拖动同样按实际滚动方向暂停跟随，流式布局更新不能覆盖尚未派发滚动事件的向上移动。工具展开、思考替换和完成折叠保持当前阅读锚点。长历史按轮虚拟化，当前运行轮和焦点所在内容保持挂载。

## 9. 实施顺序与验收

1. 事件层先行：补齐块身份、生命周期、分类、时间来源；为每种驱动做最小 fixture 和降级用例，同步投影与 wire schema。
2. 展示层：拆出 TurnView/ThinkingRow/ToolRow/ActivityGroup/MarkdownMessage，接真实投影；完成思考临时通道与结束清理。
3. 细节：终端输出、已有 Review 跳转、附件、计划、子任务；优先实际协议已提供的能力。

首批必须通过的行为验收：

- 同轮“思考→正文→工具→思考→最终回答”顺序正确，消息不串段。
- 完成/停止/断连后无遗留思考文本，刷新不重播；未提供思考的 Agent 不出现伪造动效。
- 交错并行调用、重复终态、先 update 后 start 只有一项且状态正确。
- 部分更新不丢字段，快照不会重复追加输出；跨 run 相同 native ID 不串线。
- 搜索与终端分类有证据，未知类别可读；工具失败和审批不被聚合隐藏。
- 批准后仅进入等待/运行状态，中断不会产生假成功；调用计数不把事件数量当调用数量。
- 320px 宽、长路径、减弱动态效果、键盘、读屏可用；输出增长不抢夺历史阅读位置。
- 老会话可读，缺失类别/时间显示合理降级，不回填虚构数据。
- 点击子智能体在侧栏展示对应过程；支持、部分支持、不支持、暂时失败和空记录分别验收；重试不触发模型执行。
- 快速切换父任务和子任务时无内容串线，重复事件不增行；主 turn 结束后侧栏保持打开。
- 逐次 Diff 与 turn 净变化分别正确，同文件反复编辑不重复统计；后续 turn 修改不改变历史 Diff。

首版实现已完成，参见开头的实现与验收记录。此前真实模型委派探测与本轮代码验证分别记录；本轮未重新运行全部 Agent 的收费模型测试。
