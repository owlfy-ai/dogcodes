# 侧边问答参与后台空闲退出判断

对应 DT-08，接续[侧边问答恢复](desktop-sidebar-chat-recovery-2026-10-16.md)。本工作块修复后台版本切换的具体遗漏，不代表问答全部生命周期、可靠性或共享状态已验收。

## 问题与修复

`retire_if_idle` 原先检查启动维护、工作区修改、终端、项目运行、审查和主任务，但没有检查独立的侧边问答。问答不占用 `active_primary_run`，因此即使仍在启动/回答，新桌面请求替换旧后台时也可能收到“可以退出”，进而中断问答。

Core 新增 `has_active_sidebar_chats()`，读取内存中问答状态的 running 标志，daemon 将它纳入同一空闲退出判断。检查持有与问答终态保存相同的互斥锁；驱动退出先于终态更新/保存，因此正常回答、取消后的原生会话收尾及保存期间均不会被提前视为空闲。后台 RPC 原有请求读写门禁仍负责排除“检查空闲时接收新启动请求”的竞争。

历史持久化记录不是活跃进程的证明。新的 Core 实例没有执行所有权；加载旧 running 记录时沿用既有“已中断”处理，不自动重发，也不因旧标志永久阻止服务退出。没有新增数据库表、协议命令、Tauri handler 或窗口所有权。

## 验证

一次集中运行 `cargo test -p agent-core -p desktop --lib --locked sidebar_chat`：**12 项 Core + 3 项桌面原生测试通过**。进程 55315 已 exit 0，日志 `/tmp/dogcodes-sidebar-lifecycle-native.log`。其中新增：

- Core 测试在驱动 shutdown 的可控等待点核实：取消已受理但收尾未完成时仍活跃，收尾完成后才变空闲；新 Core 读取同一已保存请求不会误认旧执行仍受自己持有。
- 实际 loopback RPC 测试分别覆盖正常回答和取消：发送后丢弃原连接；另一客户端看到没有主任务在运行，仍不能让服务退出；重发原请求不启动第二次会话；启动及 shutdown 等待阶段都拒绝空闲退出；终态完成后允许退出并观察真实服务接收循环结束。使用纯测试驱动，没有启动外部 Agent。

桌面测试仅新增已有工作区依赖 `async-trait` 的 dev-dependency，离线 Cargo 元数据确认外部包集合/版本未改变。仅格式化新增测试块及对应测试文件，`git diff --check` 通过；没有前端变更、全量应用测试、生产打包或签名配置修改。

## 剩余边界

这次覆盖的是受控空闲退出/后台版本替换，不证明系统强制杀进程、原生适配器崩溃或三平台真实 GUI 关闭行为已经通过。问答仍有轮询状态、跨入口 Agent 启用准入、长期记录开销、删除/资源回收和更完整错误分类等后续项；DT-08/09/10 保持实施中。
